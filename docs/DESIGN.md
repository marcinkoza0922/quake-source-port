# DESIGN

Living design doc. `PROPOSAL.md` says *what*; this says *how*. Update when decisions change.

## Decisions (interview, 2026-11-10)

| Topic | Decision |
|---|---|
| License | GPL-2.0-or-later. Porting algorithms/tables from `ironwail/` and `vkQuake/` is allowed. |
| Networking | Keep the client/server split. Loopback for SP; NetQuake protocols 15 / 666 (FitzQuake) / 999 (RMQ) for LAN/internet, after SP is solid. |
| System deps | `ash` (Vulkan, dynamic loader), SDL3 via raw `sdl3-sys` (window, input, gamepad DB + rumble, audio device). |
| Platforms | Linux first; keep code portable, Windows later. |
| Aim assist | On in SP/co-op; in DM controlled by a server-side cvar (`sv_aimassist`, default 0 in DM). |
| Mod menu | Browse installed mods + metadata, per-mod map browser (with completion/secret stats), per-mod config profiles. No online downloads. |
| Test bot | Legal movement with god mode; noclip fallback when stuck, flagged in report. |
| Game data | `QUAKE_BASEDIR` env var (default: the `vkQuake directory with maps` symlink). Data-dependent tests skip when absent. |

## Compatibility targets

Everything ironwail/vkQuake load: id1, hipnotic/rogue (`-hipnotic`/`-rogue` builtins quirks), MG1/MG3 (Machine Games re-release `progs`, `mg1`/`mg3` dirs, KEX extensions where the references handle them), Arcane Dimensions (fog, skyfog, `alpha`, BSP2, `colormod`-free, large entity counts, particle-heavy, func_illusionary etc.). Formats:

- Archives: PAK, PK3/zip (store + deflate).
- BSP29, BSP2, 2PSB, lit/colored (`.lit`), external `.ent` overrides, `.vis` not required.
- MDL (incl. `QuakeForge` flags, MD5 replacement models from re-release optional later), SPR/SPR32, WAD2, LMP, TGA/PCX external textures, `.skybox` (`sky` worldspawn key).
- QuakeC progs.dat v6, FTE/QSS extensions used by AD/MG (checkextension, string builtins, `sv_protocol 999` limits).
- Audio: WAV, OGG/FLAC/MP3 music in `music/` (decoders: `lewton` ok as a "solved" crate; mp3 via `minimp3`-class crate).

## Architecture

Cargo workspace. Binary crate at root (`src/main.rs`) wires crates together.

```
crates/
  qcore      math (Vec3, plane, bbox), byte reader, hashing, cvar + cmd + console text, filesystem (pak/pk3 search paths, gamedir stack)
  qformats   BSP29/BSP2/2PSB, MDL, SPR, WAD2, LMP, palette, PCX/TGA, WAV parsing → plain Rust structs, no GPU
  qecs       custom ECS (see below)
  qvm        QuakeC VM: progs loader, interpreter, builtin dispatch trait, edict field layout mapping onto ECS
  qworld     collision (hull traces, BSP2 large hulls), SV_Move, physics (SV_Physics_*), area grid
  qnet       message buffers, protocols 15/666/999, loopback + UDP datagram transport
  qserver    server frame, builtins impl, entity delta encoding
  qclient    client state, parse, prediction-free NetQuake model, interpolation, effects/particles (CPU sim)
  qrender    Vulkan renderer (ash)
  qsound     mixer + spatialization, music streaming
  qplatform  SDL3 wrapper: window, events, gamepad, audio callback, timers
  qinput     binds, mouse, gamepad curves, aim assist
  qui        immediate-mode UI toolkit custom-built for console/menus/HUD; mod menu
tools/
  qbot       automated level traversal test harness (headless server + bot client)
  qinspect   CLI: dump bsp/mdl/progs/pak contents, entity lists, secret/monster counts
  qbench     timedemo runner comparing against ironwail/vkQuake numbers
```

Dependency direction: qcore ← qformats ← {qworld, qvm} ← qserver; qnet ← {qserver, qclient}; qrender/qsound/qinput/qui depend on qcore/qformats and client state, never on qserver. The server must run headless (no SDL/Vulkan) — required by `qbot` and dedicated servers.

### ECS (`qecs`)

Fit-to-purpose, not general. Quake's entity model is a fixed field layout defined by progs, so:

- **Server**: edicts are stored as a dense SoA-ish block of `f32/i32` slots exactly as progs expects (QC accesses fields by offset; this must stay O(1) and branch-free). The ECS adds *engine-side* components (link state in area grid, cached hull, interpolation, bot nav data) in sparse-set storages keyed by edict index. Generational `Entity` handles for engine code; raw indices for QC.
- **Client**: entities, temp entities, beams, dlights, particles live in archetype-free typed pools (`Pool<T>` with free list + dense iteration). Systems are plain functions run in a fixed schedule; no dynamic scheduler, no reflection.
- Particles are a separate SoA pool (pos/vel/color/die/type) for SIMD-friendly update.

### Renderer (`qrender`)

- Vulkan 1.2 baseline + dynamic rendering when available; ash, hand-written allocator (big-block suballocation; few resource types).
- World: BSP surfaces batched into one big vertex buffer at load; per-frame visible face set from PVS + frustum culled on CPU (multithreaded mark-leaves), drawn via indirect indexed draws grouped by texture+lightmap atlas. GPU lightmap update for lightstyles (compute shader, like ironwail's approach) to avoid CPU uploads.
- Alias models: GPU vertex lerp from packed frame buffers; instanced by model.
- Water warp, sky (scrolling + skybox), fog (AD `fog` / worldspawn), alpha surfaces sorted, r_wateralpha / per-entity alpha, fullbrights, colored lighting, palette-accurate shading option (`r_softemu`-style).
- Shaders: GLSL compiled with `glslc` in `build.rs` to SPIR-V, embedded.
- Target: ≥ ironwail fps on AD large maps (ad_sepulcher, ad_tears) measured by `qbench`.

### Server / QuakeC

Interpreter ported faithfully from the references (opcode semantics, runaway loop limit, string table handling incl. dynamic strings for QSS extensions). Builtins table indexed by number, with extension builtins looked up by name like QSS. Physics ported from sv_phys/sv_move/world.c behaviors including known quirks maps depend on.

### Input and aim assist

Gamepad via SDL3 gamepad API + SDL DB. Look: radial deadzone, response curve (exponent), acceleration ramp on sustained full deflection. Aim assist (gamepad only, never mouse):
- **Slowdown (friction)**: reduce look sensitivity when crosshair within an angular cone of a valid target's bbox.
- **Rotational/magnetism**: when player is moving and target is in cone, add a portion of the target's relative angular velocity to view.
- **Snap**: none (not industry standard for this genre); optional `aim_snap` cvar off by default.
Target selection: live monsters (`FL_MONSTER`, health > 0) and DM opponents if allowed, visible via trace, within range; weighted by angle and distance. Client-side, using interpolated entity positions; server cvar gating via serverinfo/stufftext.

### Controller support

- **Default binds** (`src/pad_defaults.cfg`): RT attack, LT/A jump, B swim down, X/Y weapon wheel, LB/RB previous/next weapon (`impulse 12`/`impulse 10`), Back scoreboard, LS run, RS centre view. Start/Guide act as Escape. They are queued after every `default.cfg` (id1's has no pad binds). After `config.cfg`, `_paddefaults_merge` runs once per config (`cl_paddefaults` 0 → 1) and fills in any default whose pad key is still unbound, so configs that predate the defaults pick them up. Back is its own key (`BACK`), not Tab.
- **Active device**: `Input::last_device` switches to the gamepad on a button or on a stick/trigger past 0.5. It switches to keyboard/mouse on a key, click, wheel, or mouse motion over 4 px (resting-mouse jitter doesn't count). Prompts show pad glyphs only while a pad is connected and was used last (`Host::pad_ui`). Rumble is gated the same way.
- **Glyphs** (`src/glyphs.rs`): the label/colour table comes from padwight's `button_glyph`. Xbox: coloured A/B/X/Y. PlayStation: coloured ✕○□△. Nintendo: neutral discs labelled by position (south shows B). LB/L1/L, LT/L2/ZL, View/Share/−, and so on. Family comes from SDL's gamepad type, then vendor id, then name (`qplatform::pad_family`, sent as `HostEvent::PadFamily`). `joy_glyphs` overrides it (0 auto, 1 Xbox, 2 PS, 3 Nintendo). Discs and PS symbols come from a 5-cell RGBA atlas rasterised at startup with bilinear sampling (`Renderer::register_pic_rgba_linear`). Keyboard keys are drawn as square tags.
- **Menus**: D-pad or left stick moves, A selects, B goes back. The host auto-repeats held directions for the pad only, since keyboards repeat themselves. Every screen ends with a hint row for the active device. **Options › Controls** lists rebindable actions with keyboard and controller columns. Select starts capture, and the next key or button binds; a third key of the same kind replaces both. Backspace/Del clears the keyboard keys and X clears the pad keys. Esc/Start cancels. While capturing, `Input::capture` stops the sticks from emulating arrows. "Reset to Defaults" runs `_resetbinds`, which replays default.cfg's `bind`/`alias` lines plus the pad defaults and leaves cvars alone. `menu_options controls` opens the page. Pressing A on a text field (player name, join address) opens an on-screen keyboard: a 10×4 character grid plus Shift/Space/Del/Done. A types, X deletes, Y toggles shift, and B/Start closes it. Physical typing still works while it is open.
- **Weapon wheel** (`src/wheel.rs`, `+weaponwheel`): while it is held, either stick (whichever is pushed further) or a mouse-driven virtual cursor picks one of 8 slots, axe to thunderbolt clockwise from the top, instead of moving or turning. Releasing on an owned weapon with ammo sends its impulse. In single player (local server, maxclients 1) the server tic and client time run at `cl_wheel_timescale` (default 0.25; Input page "Wheel Slow Motion").
- **Rumble** (`joy_rumble` 0..1): on firing, detected from STAT_AMMO dropping on the same weapon or an axe swing starting, with strength by weapon; on damage, scaled by armor + blood; and on view punches (`punchangle`). Requests are merged per frame and the main loop sends them to every pad (`Platform::rumble_all`).
- **Intermission**: any key, click or pad button except Escape/Start sets the attack button, which QC treats as "continue". After QC's exit delay (2 s, or 5 s in deathmatch), "Press any key/button to continue..." follows the active device.

### UI / mod menu

Custom immediate-mode UI (`qui`) drawing through the renderer's 2D batch, conchars + scalable bitmap font. Mod menu: scans basedir for gamedirs (has pak/pk3/progs/maps), reads metadata (`modinfo.txt`, readme, `maps/*.bsp` names, worldspawn `message`), thumbnail from screenshot cache, launches with correct base game flags. Per-mod profile = `config.cfg` in `<basedir>/<mod>/`, with per-mod stats file (`qsp_stats.json`) storing kills/secrets/completion per map.

### Test bot (`tools/qbot`)

An integrity test, not a balance test: it checks that every level can be traversed by game means and runs without errors. In-process headless `qserver::Server` (no engine binary) ticking at 20 Hz like a dedicated server (`sys_ticrate 0.05`), `skill 3`, `god`, one local client driven by `set_move`; the client's entity updates are skipped (`ServerCore::skip_entity_updates`) since nobody reads them. Per map:
1. Scan edicts. Goals: `trigger_secret`, `func_button`, `item_*key*`, FL_MONSTER edicts, shootable brush entities (SOLID_BSP with health, e.g. secret doors), `trigger_once`/`trigger_multiple` (running a level's scripting, e.g. monsters teleporting in from closets), and finally the exit. `trigger_changelevel` gets its `touch` cleared until the exit becomes the goal, after everything else is done or failed. Monsters that are not solid and not damageable yet (hipnotic/AD spawn-on-trigger) are dormant: never targeted or noclipped to. A key goal is done once the key was placed (keys spawn SOLID_NOT until PlaceItem) and is not solid again. The ammo refill (`impulse 9`) also hands out both keys in id1, so the keys it adds are stripped right after that frame: key doors stay locked until the bot has picked up the key.
2. Nav graph (`nav.rs`): flood fill over a 32-unit XY grid from the spawn point with hull 1 traces through `Geo`: the world plus static brush entities (SOLID_BSP without a `blocked` function: func_wall floors and bridges; every mover has `blocked`), plus resting non-train movers as floors only (never walls; a ground trace that starts inside one ignores it, so doorways stay open). Edges: walk (step 18), jump (rise ≤ 40, pressed as +jump), drop (≤ 2048: the bot is in god mode, so falls never hurt), and in water a swim up (tried at 64, 128, 256… units up to the surface plus a jump out). Nodes are never in lava, slime, sky or solid. Extra nodes: lifts (`plat`/`door` with vertical pos1/pos2, `func_new_plat`, trains cycling between path_corners that share XY) get a stop node at each end, linked to the ledges beside it and to each other by `Ride` edges, seeding the flood fill at a stop it hasn't reached; trigger_teleport (without targetname) gets an entry node with a `Teleport` edge to its destination; trigger_push gets one too, to the ledges around the top of an updraft or the ground past the far end of a wind tunnel (the bot jumps when it reaches such an entry, since updrafts can start above head height); exits get entry nodes (just outside the box when it is too narrow to stand in). This repeats until the graph stops growing. Off the graph (fall, teleport), it is flood-filled again from where the bot stands.
3. Goal loop: Dijkstra from the nearest node with a clear line, cheapest reachable goal. Shootable-goal approach lookup checks all nearby candidates before falling back to the nearest node: a wall can hide the closest twelve while a farther candidate is clear. Route-start recovery retains its local twelve-candidate policy (expanding that search regressed mission-pack traversal). Locked doors gate the graph: edges (walk, jump, lift rides; not teleports) through a closed (at pos1, not moving) `door`/`func_door` are left out while its master (`owner`) needs a key the bot lacks, or has a targetname and no health and a pending button, trigger, shootable or secret fires that name (directly or through a chain of relays). The key or opener is an ordinary goal, so the bot fetches it first instead of discovering the lock by getting stuck. Gates are a preference: when nothing is reachable with them, the plan is made without them (the opener may have fired already, or the door opens some other way) before blocks are lifted. When that ungated plan crosses a gated door, the bot goes for one of the door's openers instead (pending buttons, triggers, shootables or secrets firing its name; keys with its bits): walking if the opener is reachable, else by noclip (triggers included); replan every 1 s for monsters, 3 s otherwise. Shootable goals (monsters, secret doors, buttons with health) may be reached at any of up to 8 nodes with a view of them (cached until the target moves 64 units). Shooting: the nearest target within 2000 units with a clear shot through the world, static solids and every brush entity where it is now (re-picked every 2 ticks); lightning gun within 560 units (hitscan, no projectiles to simulate), super nailgun beyond, rockets for zombies; impulse 9 every 5 s. Lifts: board at the bottom to go up; to go down drop onto it when it is at the bottom (a plat stays up while stood on), ride other movers down; wait beside it otherwise, up to 15 s. Water: swim towards the next node's height (dive or rise).
4. Stuck (no 16-unit progress for 2 s): jump and strafe; after 4 s the edge being walked and its parallel lanes are blocked and the bot replans; stuck before the first node of a path, that node is not used as a start again until blocks are lifted. A goal that times out (30 s) or a monster still out of sight at the end of its path is deferred. When nothing is reachable, blocks and deferrals are lifted if a goal was finished since, and the nav graph is rebuilt if movers moved (a bridge came out). Only then does it noclip, keys first (a key door can cut off much of the level): an instant `setpos` to the goal (a button off the graph, e.g. high on a wall: a spot just off one of its faces with the body overlapping it, on a floor when a face has one) (or a free spot near it: `fits` checks the world, brush entities where they are now and other bodies), at most 3 per goal; triggers are never noclipped to (counted as `triggers_missed`). Every noclip is a soft failure in the report; `monster_noclips` counts the ones to monsters (coverage: they take the bot into areas it can't reach, where it carries on walking), the rest went to goals a player has to reach and are the navigation gaps. Noclip targets are taken in entity order, which tends to follow the level's layout (ranking unlocking goals first lost coverage). Off the graph it returns to the nearest node that has a floor under it right now or is in water (nodes built on a plat float once the plat has moved; returning to one dropped the bot into the same pit until every goal's noclips were used up). The edge it was walking when it fell off is blocked, so it doesn't fall the same way again. Such returns don't count as reaching the goal by noclip (a goal not done 4 s after a noclip to it fails). If the bot can't get back onto the graph after 8 tries, the run stops (`stranded`).
5. The level is finished when its changelevel fires or its intermission runs for 8 s (finales). Report `<out>/report.json`, one entry per map: kills/total, secrets/total, noclip uses, failed goals, missed triggers, `exit_noclips` (direct noclips to exit goals, excluding returns to the graph), nav nodes, has_exit/exited, stranded, route, sim/wall time, errors (QC errors, spawn failures). Sim time is capped at 900 s or 15 s per goal, whichever is larger (`-time` overrides). Runs are deterministic, so `tools/qbot/baseline-<game>.json` (kills, secrets, exited, noclips per map) is compared exactly: fewer kills or secrets, losing the exit, or any error exits 1; more noclips prints a `SOFT` line. Changes to the bot itself shift the numbers, so re-save the baseline (`-save-baseline`, merged per map) after changing it. Note the release profile has `panic = "abort"`, so a panic in one map ends the whole run.
6. Route cache (`route.rs`): a run that finishes its level by game means only (exit or intermission, no noclip, no error) saves its usercmd stream (run-length coded), the bot's origin once a second and the frames where exits were armed to `<routes>/<map>.qbr` (default `target/qbot/routes/<game>`), keyed by a hash of the BSP, progs.dat, skill and format version. Next time the stream is replayed with no nav graph or planning. If the bot is more than 16 units off a checkpoint, the engine now behaves differently: the report says `diverged t=…`, and the bot builds its graph and carries on from there (a successful finish re-records). `-fresh` ignores cached routes, `-no-routes` disables the cache.
7. Variants (`-variants N`): after the plain bot (seed 0) has run every map, each map it didn't finish cleanly is rerun with seeds 1..N-1, all on the job threads. A seed fixes, per variant, a preference factor per goal (1..1.6 on its path cost: another goal order), a cost factor per edge (1..1.5: other corridors; `nav::unit_hash`) and the lift patience (9..22.5 s); runs stay deterministic per seed, and only seed 0 replays cached routes. The report keeps the best run per map (clean, exit, fewest noclips, most kills+secrets, shortest) with `seed`, `variants` and `clean_variants`; errors from any variant count against the map, and the best clean run's recording becomes the cached route. The baseline always holds and compares the seed-0 numbers. First result (id1, 32 variants, 1,344 runs in 65 s on all cores): noclips 619 → 417 for the best variants, e1m2 finished cleanly (seed 27, 42/42, 3/3; its route replays in 0.1 s); most other maps level off at noclips that no variant avoids, which marks gaps in the nav model rather than unlucky choices.
8. Hints (`hints.rs`): hand-written per-map fixes for gaps in the automatic graph, in `tools/qbot/hints/<game>/<map>.txt` (`-hints DIR` overrides, `-no-hints` disables). They are applied on every graph build, after movers. The directives are `seed x y z` (an extra flood-fill start, linked back into the old graph where the two meet on a walkable step), `walk a -> b` / `walk a <-> b` (an edge, one-way or both ways) `jump a -> b` (jump is held while moving from a to b: gaps, crates, ledges) and `block a -> b` (removes every edge crossing the segment a..b in XY, within 40 units of its height, both ways; one that cuts nothing is an error). Each end snaps to the floor within 128 units and joins the nearest node within 48 units, or becomes a new node linked to its neighbours. Coordinates are player origins, so the from/to of a `-v` NOCLIP line can be pasted in. A hint line that finds no floor, or a file that doesn't parse, is reported as an error (the baseline check fails), so stale hints don't rot silently. Cached routes replay without the graph, so use `-fresh` while writing hints. `QBOT_PATH='x,y,z;x,y,z'` prints the graph's path between two spots (non-walk and steep edges; `QBOT_PATH_ALL=1` every step) and the verbose log names the doors gating edges and their openers. Closed `func_door_secret`s are gated like locked doors: opened by the goals that fire their targetname, or by shooting them (their own Shoot goal). A sweep of id1's 232 navigation noclips (2026-11-11) by goal: exits 43 (dm maps' floating exits, button-called lifts such as e1m1's, exits on graph islands like e1m3/e1m4), buttons 63, secrets 57, keys 20; most need mechanics (calling a lift with its button, opening doors) rather than hints, which fit real geometry gaps (gaps, ledges, crates). Mechanics added from that sweep: a lift that keeps still away from the stop it is needed at is called by pressing an unpressed `func_button` that fires it (through relays; shot if shootable, else walked into when within 48 units of height and in the open); a bot stuck against a shootable brush (a secret door that closed again) shoots it; movers thinner than a player (door panels) are never floors, so a closed door in a corridor no longer puts a ledge in it; and the flood walks level where a low ceiling leaves no room to probe a stair step (e1m1's exit corridor was cut off by both). More hint-writing tools: `QBOT_INTO=x,y,z` prints the basin of nodes that can reach a spot and, when the start can't, the closest start-reachable/basin node pairs (the gaps to bridge); `QBOT_SEG=ax,ay,az,bx,by,bz` traces one segment (graph geometry and world) and the floor under its end. Totals after (skill 3): id1 1688 kills, 103 secrets, 540 noclips (211 navigation), 36/42 exits, e1m1's exit reached by game means; hipnotic 1205, 60, 207 (123), 17/17; rogue 1259, 49, 220 (134), 13/16.


9. Lift actions (`actions.rs`): keep explicit approach-button, activate-button, return-to-lift, wait, board, ride and leave stages. The existing nearby caller remains the first choice. If it cannot be used directly, plan a detour of at most 1536 units to a ready caller, following target/relay links. Search all callers and their usable touch/firing nodes, exclude gated edges, lifts, teleports and recorded jump links, and require every approach edge to have a usable reverse edge. This prevents calling a lift via itself or dropping into a pit with no return. Button state acknowledges activation; return along the reversed path before resuming the lift edge. Approach and return stages each allow 30 s, activation 5 s, other stages the normal lift patience, with a 120 s overall bound. An ordinary lift without a detour retains its original total wait limit. Main-goal replanning and timeouts yield to the bounded action; graph rebuilds and assists cancel it. Tests cover a caller around a corner, an inaccessible caller above the same lift, one-way drops, gates and independent stage deadlines.
10. Physics-tested gap recovery (`movement.rs`): just before assisting an unreachable goal, find its reverse-reachable basin and nearby source-reachable nodes, respecting gates and directed edges. Try at most 24 candidate links per search (40–192 units horizontally, rise at most 40, drop at most 48). When a goal needs a new flood seed, graph changes are tentative until a jump succeeds; failed searches restore the old graph. A probe owns a separate `qworld::World` and lightweight edicts, shares immutable collision models, and freezes brush entities and solid bodies at their current positions. It runs the engine's `client_think` and `physics_client_move` at the bot's 20 Hz tick, trying takeoff immediately or after 2/4 run-up ticks. The jump impulse is measured from an ordinary live jump, with server cvars and player gravity retained; no probe is attempted before this calibration or for a nonstandard player hull or deep-water start. QC callbacks are omitted, so probes cannot collect items, activate doors, alter globals, consume RNG or advance the live game. Accept only an actual supported landing within 16 units XY and 4 units Z; reject hazards, deep water and exit/teleport/push trigger volumes. Forbidden volumes have an extra 20-unit margin to account for playback drift and trigger touching bounds.
   Accepted links store the tested commands and per-tick positions. At execution the bot aligns and stops at the launch, releases jump, and verifies again against the current scene from its actual launch position before replaying. It can keep shooting while aligning; flight preserves the verified view/movement commands. A successful landing advances past the edge; finishing the goal interrupts the action. A deviation over 20 units, missing landing or 4 s deadline removes the link and disables further jump searches for that goal. Ordinary recovery then resumes. Reports expose `jump_links`, `jumps_completed`, `jump_failures` and `lift_detours`; cached-route replays do not reconstruct these planning counters. These are local, frozen-scene probes, not a simulation of QC, future mover motion, moving monsters, swimming or arbitrary scripted movement. Synthetic tests cover gap crossing, unsupported landings, headroom, forbidden-trigger drift and solid-body obstruction; game-data tests verify live-state isolation and executed jump recovery on e3m7.


11. Adaptive sampling and local movement search: retain the 32-unit flood as the main graph. On an unreachable approach, sample 8-unit patches around the player and goal; the best two nearby pairs linking the reachable graph to the goal basin request patches at their midpoint. Failed tentative graph changes are rolled back while retaining the attempted-region and work-budget records. Each patch spans 192 units, samples only nearby supported heights, and is attempted once per 64-unit XYZ region. At most 8192 fine nodes are added per graph, also respecting the overall graph cap. Fine nodes use separate exact-position matching without changing the coarse flood's cell merging. Connections are directed walk edges, with clearance and static floor support checked every four units; resting mover floors cannot supply fine-patch support. Hazards and exit volumes are excluded, and explicit hint barriers are reapplied. The follower uses a four-unit arrival radius and reduced speed for fine nodes.
   The isolated physics probe also searches a fixed set of short movement sequences: direct walking, 4/8-tick sidesteps, diagonal approaches and backing up, followed by destination steering, with optional jumps. Each rollout is bounded to 32 ticks; supported arrivals are ranked by duration, preferring fewer jump presses on ties. Partial progress alone cannot validate a link. Existing gap jumps retain their original first-choice probes; broader search is a fallback. Live stuck recovery requires low horizontal velocity and a static obstruction, then checks that ordinary walking actually fails in the probe, avoiding false recovery when a route merely bends away from the goal. It permits one local search per goal and uses the same standard-hull, water, hazard, forbidden-trigger, scene revalidation, alignment, four-second execution deadline and divergence checks as recorded jumps. Walk and detour recordings currently use the existing `jump_links`/`jumps_completed`/`jump_failures` report counters. Synthetic coverage includes an off-grid narrow passage, a floor gap that must remain disconnected, walking under a low ceiling, sidestepping an obstacle, and forbidden-trigger rejection. The game-data isolation test exercises the broader search as well. Validation with local game data: the workspace tests pass, including e1m1, hip2m2 and live e3m7 replay. The initial seed-0, no-route-cache id1 sweep changed kills 1689 → 1712, secrets 104 → 104, exits 36 → 36 and total noclips 536 → 492. Of those, monster assists fall 325 → 279 while other navigation assists change 211 → 213. That initial implementation lost per-map coverage in e1m3, e3m3, e4m2, hip3m4 and r1m5; the follow-up below resolves those regressions. Mission-pack sweeps retain their exit counts and improve aggregate kills, with slightly more assists. These techniques improve aggregate coverage but do not eliminate the remaining interaction and mover gaps.

12. Recovery coverage follow-up: monster assists now require a fitting position with a clear shot through current brush entities, searching every nearby graph candidate rather than the first 64. If none exists, try 16 directions at radii 72/128/192/256 around the live monster, checking floor support, fit and shot clearance. This handles monsters moving into graph islands and avoids repeatedly choosing points behind closed doors. Deferred monsters remain pending while their three direct-assist attempts remain; failing a walking approach alone no longer exhausts them. Returning to the graph has its own existing eight-return bound and no longer consumes the current goal's direct-assist budget. Trigger/key/rune/exit assists preserve a usable original approach when available, otherwise search graph and sampled positions whose player hull actually overlaps the goal and fits around current solids. Ordinary trigger traversal remains subject to the existing no-direct-assist policy. Runes (`item_sigil`) are explicit pickup goals, armed after placement and completed after removal, and participate in door prerequisite chains: e3m6's exit doors require collecting its rune.

## Implemented APIs

### qecs
- `Entity` (index = QC edict number + generation); `EntityAllocator` with `alloc`, `alloc_with(|idx, freed_at| bool)` for ED_Alloc-style reuse policies, `alloc_at(idx)`, `free(e, now)`, `free_time`.
- `SparseSet<T>` with generation-checked access plus `*_raw` index access for QC; `join2`/`join3` and `join_mut`/`join2_mut` all iterate the smallest storage.
- `Pool<T>`/`PoolHandle`: preallocated with `with_max`, swap-remove `retain`.
- `ParticlePool`: SoA, `spawn`, `kill_expired`, `integrate(dt)`, `update_with(time, dt, closure)` for per-kind ramps/gravity.

### qformats
All parsers take `&[u8]` and return `qformats::Result<T>`; bad input gives an `Error { format, msg }` with the byte offset, never a panic. Vectors are `[f32;3]`.
- `Bsp::parse`: BSP29/BSP2/2PSB/Quake64 normalised into one set of structs (i32 children: a node child < 0 is leaf `-(i+1)`, a clipnode child < 0 is a contents value). Also `decompress_vis`, `leaf_pvs`, `parse_lit`.
- Miptex texel data that runs past the end of the lump (seen in qbj, retrojam2) is tolerated: mip 0 is clamped and zero-filled, as in ironwail, and smaller mips that are out of bounds are point-sampled from the previous level.
- Quake64 (`q64`): `miptex64_t` adds `MipTex::shift` (the renderer divides st by `2*shift`), only mip 0 is stored, and the 16-bit RGB lightmap is expanded into `Bsp::rgb_lighting` (used like a `.lit` when no `.lit` file is present) plus mono `lighting`. `lightofs` is halved to index the expanded data. Skies are 32×64 with the front layer on top at alpha 128 (`convert::sky_layers(.., q64)`).
- `parse_entities` keeps key order and duplicate keys.
- `Mdl`, `Spr` (v1 and SPR32), `Wad` (WAD2/WAD3), `parse_pic`/`parse_palette`/`parse_colormap`/`parse_pcx`/`parse_tga`, `Wav` (with loop points as in GetWavinfo).
- Known gaps: maps inside .pk3 are not covered by tests yet (qcore's zip reader will fix that). For stereo WAV, the frame count is length / (width × channels), whereas Quake divides by width only; the mixer must take this into account.

### qcore
- `math`: `Vec3`, `angle_vectors`, `vec_to_angles`, `Plane` (with `box_on_side`), `Bounds`.
- `reader`: `Reader<'a>`, a little-endian cursor that returns `ReadError{pos,need,len}`.
- `fs`: `Fs::new(basedir)` / `Fs::default_basedir()`, `add_game_dir`, `truncate_game_dirs`, `open -> Option<Vec<u8>>`, `exists`, `origin`, `list(prefix, ext)`. Search order within a gamedir: loose files < pak0..N < *.pk3 (sorted, QSS order); later gamedirs override earlier ones. Names in archives are case-insensitive. Loose files and `pakN.pak` fall back to a case-insensitive match when the exact name is missing (beyond the references, by user decision 2026-11-11). `..` is rejected. Each `open` reopens the archive; mmap is a future optimisation.
- `cvar`: `Cvars` registry (`register` keeps a value already set by `set`; the usual flags).
- `cmd`: `com_parse`, `Args::tokenize`, `Cbuf` (`wait`), `Commands<C: CmdContext>` with built-in alias/set/seta/toggle/echo. `exec` and `cvarlist` must be registered by the engine.
- Dependency: `miniz_oxide` (pk3 deflate).

### qworld
- `ents::Edicts`: the trait the server implements. Fields are read and written by enum (`V`/`F`/`E`). The `touch`/`blocked`/`think` callbacks receive `&mut World` so QC can run re-entrantly.
- `hull::CollisionModel::from_bsp`: hulls 0–2 and per-submodel heads. `Hull::trace` matches `SV_RecursiveHullCheck` exactly, including the epsilon, the 0.1 backup loop and doubles on non-axial planes.
- `world::World`: depth-4 area tree with C-identical link order. `trace` is SV_Move; also `link_edict`/`unlink`/`touch_links`/`point_contents`. Traces don't allocate.
- `phys`: per-movetype physics and push movers (`PhysParams` holds the cvars and f64 time). `physics_client_move` sits between PlayerPreThink and PlayerPostThink, which the server calls.
- `monster`: movestep / check_bottom / move_to_goal. `user`: SV_User movement.
- `pmove`: QuakeWorld player movement (pmove.c/pmovetst.c) for the QW client's prediction: `predict(physents, movevars, from, cmd, dead, spectator)` splits commands over 50 ms like CL_PredictUsercmd. Physents are brush submodels (traced with hull 1 through `Hull::recursive_check`) or boxes expanded by the player size; physents[0] is the world, whose hull 0 gives point contents.
- Where C would Host_Error, this crate carries on instead (bad movetype, SOLID_BSP without a model, and similar). Rotating pushers (`SV_PushRotate`) are deliberately absent, matching ironwail and vkQuake: hipnotic rotation is done entirely in QC.

### qvm
- `Progs::parse`: v6 progs. Every operand, jump and range is validated at load, so running code can't panic.
- `Vm::new/load(progs, max_edicts, maxclients)`: `execute(&mut dyn Host, fnum)` is re-entrant, with the reference limits (runaway, stack depth). Errors come back as `VmError { msg, trace }` and the VM stays usable afterwards.
- Edicts: one dense u32 slot array. `ed_alloc` follows the ED_Alloc reuse rules via `qecs::EntityAllocator::alloc_with`. The host must unlink an edict before `ed_free`.
- Strings: a handle ≥ 0 is an offset into the progs string table; a negative handle is an engine slot (1024 rotating temp strings, zone strings, interned constants).
- `trait Host { builtin, ext_builtin, has_extension, dprint, print }`. `Builtin` is an enum of the id1 numbers 1–80. Re-release ex_* names and numbers 90–92 are remapped. #0 builtins are resolved by name at load. Math and string builtins run inside the VM.
- `spawn::load_from_file(host, ents, SpawnFilter)`: ED_LoadFromFile, including the key hacks.
- Approximations: sprintf %g, strconv modes 0–2 only, `random()` uses its own generator rather than C rand(), and tokenize uses com_parse.

### qserver
- `Server::new(fs, cvars, maxclients)` holds `core` (fs, cvars, cbuf, clients, level state) and `level` (VM + World). `spawn_server(map)` follows SV_SpawnServer (including `.ent` overrides). `frame(dt)` runs cbuf, then client input, then SV_Physics, then sends.
- Clients are in-memory slots. `connect_local()` runs the full signon and redoes it after changelevel. `set_move(i, ClientMove)`, `client_command`. Output via `take_reliable(i)` / `take_datagrams(i)`, which are protocol 15/666/999 byte streams. `sv_protocol` defaults to 999 (INT32COORD, like ironwail/vkQuake): 666 coords wrap past ±4096, which breaks large maps (e.g. Mjolnir start2).
- `stats() -> LevelStats { total/found secrets, total/killed monsters }`, used by qbot.
- qworld `CollisionModel::submodels` mins/maxs are spread by ±1 as in Mod_LoadSubmodels; precache dispatches on file magic (alias models named `.bsp` load as alias).
- Localization (`loc.rs`, `Core::loc`): `localization/loc_english*.txt` loaded in `Server::new`. bprint/sprint/centerprint use PF_VarString with LOC_GetString + LOC_Format (`{}`/`{N}` filled from the following args, each translated), WriteString translates `$key` as ironwail. `Localization::translate` is the client-side LOC_GetString for whole print strings.
- Differences from ironwail: alias and sprite models get ±16 bounds, no QSS custom stats, no `sv_netsort`, and the `alpha` key is kept only when progs define an `alpha` field.
- Smoke tests: `smoke_fast` runs by default. `cargo nextest run --release -p qserver --run-ignored only smoke_all` loads every installed map; the summary goes to `target/qserver-smoke-all.txt`.

### qnet
- `msg`: `SizeBuf` (a copy of `qserver::msg::SizeBuf`, so qserver can switch to it later) and `MsgReader` (MSG_Read*: reading past the end sets `badread` and never panics). Both have coord/angle/angle16 for the PRFL_* flags of protocols 15/666/999. `protocol`: svc/clc/TE/U_/SU_/B_/SND_/STAT_ constants.
- `dgram::Connection` is the net_dgrm.c state machine and has no I/O: reliable messages are split into fragments (`fragment`, 1024 by default), each ends with EOM and must be acked before the next goes out. A fragment is resent after 1 s. Unreliable messages carry a sequence number and stale ones are dropped. Queued reliable messages are merged up to 64000 bytes. Use it through `send_reliable`/`send_unreliable`/`handle_packet`/`poll`/`take_outgoing`. `NetSocket<T: Transport>` ties a connection to a peer.
- `control`: `Ccreq`/`Ccrep` encode/decode for CCREQ_CONNECT/SERVER_INFO/PLAYER_INFO/RULE_INFO and CCREP_ACCEPT/REJECT/SERVER_INFO/PLAYER_INFO/RULE_INFO.
- `transport`: `Transport` trait, `UdpTransport` (non-blocking std UdpSocket), `LoopbackTransport::pair()`.
- `qw`: QuakeWorld protocol 28 (from id's GPL QW source). Constants (svc/clc/PF_/CM_/U_/TE_), QW coord/angle encodings, `UserCmd` with `write_delta_usercmd`/`read_delta_usercmd`, `Netchan` (client side of net_chan.c: sequence + reliable bit, one reliable message in flight resent until acked, qport), `ServerChan` (server side, for test servers), `sequence_crc_byte` (COM_BlockSequenceCRCByte: CRC-16/CCITT over the move bytes plus chktbl; only the first 512 of chktbl's 1028 bytes are initialized in the C source, the rest are zero), `block_checksum` (MD4 folded to 32 bits) and `map_checksum2` (XOR over all lumps but entities, visibility, leafs and nodes; mvdsv kicks on a mismatch at prespawn), out-of-band packets and info strings.

### qclient
- `ClientState`: protocol/flags, signon, precache name lists, `model_flags` (MF_*, which the host fills in after loading models), `entities` (with baselines, `msg_origins`/`msg_angles` [0]=new [1]=old, interpolated `origin`/`angles`), statics, stats/items, scores, lightstyles, viewangles/punch/velocity, intermission/centerprint, fog/skybox. Effects live in qecs pools: `beams`, `dlights` (`Pool`) and `particles` (`ParticlePool`, PT_* kinds).
- `parse_server_message(&[u8]) -> Result<(), ParseError>` handles every svc_* that ironwail's CL_ParseServerMessage handles (FitzQuake/RMQ bits, Nehahra U_TRANS, temp entities). Side effects come out as `ClientEvent`s (sounds, prints, stufftext lines, signon stages) through `take_events()`. Signon replies and string commands are queued as clc bytes, drained with `take_reliable_out()`.
- `frame(dt)`: time advance, CL_RelinkEntities (CL_LerpPoint; `nolerp` for a local server), beam temp entities, dlight decay, CL_RunParticles. The particle spawners (run_particle_effect, rocket_trail, explosions, splashes, entity_particles) are public. `QRand` stands in for C rand().
- Input: `base_move(&InputState, &MoveSpeeds, frametime) -> UserCmd`, `encode_move`/`build_move` (clc_move; the first two moves of a level are dropped).
- `qw::QwState`: the QW client. `parse(payload, ack, inseq, realtime)` reads one netchan payload and returns NQ messages plus `QwAction`s for the host (stringcmds, precache/download steps, `packet`, `reconnect`, disconnect). Signon: serverdata → soundlist/modellist (paged) → `Precache` (host checks files, downloads, then `finish_precache(checksum2)` emits the NQ serverinfo + signon 1 and returns the prespawn command) → `cmd spawn` stufftext (signon 2) → `skins` (signon 3, sends `begin`) → the first entity frame makes it active. Frames (64, `UPDATE_BACKUP`) are keyed by the acknowledged outgoing sequence, which is what the server keys its copies by; `svc_deltapacketentities` deltas from the frame named by its `from` byte (checked against the stored sequence) and an unusable delta is read and dropped, as FlushEntityPacket does. Each packet with entities becomes one NQ frame: `svc_time` (receive time), the translated messages, `svc_clientdata` built from the QW stats (`updatestat` for stats 0–10 and items is folded into it; the rest pass as NQ `updatestat`), and an all-fields `U_SIGNAL` update for every present player (entity slot+1, colormap slot+1 for player.mdl, angles from the command with pitch/3) and packet entity, and nails as entities 512+. Temp entities map 1:1 except gunshot/blood/lightning blood, which become `svc_particle`; EF_BLUE/EF_RED become the QEX quad/pentagram lights; chat prints get the NQ `\x01` prefix; userinfo becomes updatename/updatecolors. `build_cmd` stores the command in the outgoing frame and writes clc_move (checksum byte, loss, three delta usercmds) plus clc_delta. `predict` is CL_PredictMove: replays unacknowledged commands from the last server state with `qworld::pmove` against the world, inline brush models in the frame (hull 1) and other players (boxes), then interpolates to realtime − latency. Tests in `qw/tests.rs` run a scripted handshake into a real `ClientState`.
- The test `tests/loopback.rs` connects to qserver on start.bsp for protocols 15/666/999 and checks signon, entities, the player origin and gunshot particles.

### qrender
- Vulkan 1.3 (dynamic rendering, descriptor indexing, multiDrawIndirect) via `ash` loaded at runtime; no SDL. `Renderer::new(&dyn SurfaceProvider, &palette)` or `Renderer::headless(w, h, &palette)` + `read_pixels()` (RGBA8). Windowed: `request_capture()` before `render` copies the presented swapchain image (swapchain gets TRANSFER_SRC usage when supported) into a host buffer; `read_pixels()` then returns it as RGBA8 (BGRA swizzled). `resize(w, h)` must be called by the host on window resize (vsync toggles recreate the swapchain).
- Loading: `load_world(&Bsp, lit) -> Vec<ModelId>` (submodels `*1..`; frees the previous level); `load_level(&Bsp, lit, &[(&Bsp, lit)]) -> (subs, brush ids)` also loads external brush models (`maps/b_*.bsp`): their faces, textures (appended to the material table) and lightmaps (same atlas) are appended to the world buffers and drawn like submodels, `load_alias(&Mdl)`, `load_sprite(&Spr)`, `set_skybox(Option<&[Rgba;6]>)` + `load_skybox(&Fs, name)`, `register_pic(&Pic)`/`register_pic_rgba`, `set_conchars(128×128)`. Pics persist across maps. `light_point(p, styles)` = R_LightPoint.
- Per frame: `render(&RenderFrame)` with `View` (fov_x is for 4:3, adapted to aspect), `RenderEntity` (frame/prev_frame/lerp, skin, colormap, alpha, viewmodel, fullbright, player), `Particle` (palette colour), `DLight`, d_lightstylevalue ints (`lightstyle_value`), `Fog` (`parse_fog`), polyblend, `Draw2D` list (pixels), `Settings` (gamma, contrast, wateralpha + per-type, skyfog, skyalpha, dynamic, vsync, `msaa`, `render_scale`, `texture_linear`, `anisotropy`; changes are applied at the start of `render`: MSAA rebuilds the scene pipelines via `Pipelines::build` and the targets, scale rebuilds targets, filtering recreates the `Sampling::World` sampler and rewrites those descriptors). `View::reserve_bottom` keeps the bottom rows free of 3D (classic status bar). These mirror qclient fields; the binary converts.
- Internals: own block allocator (64 MB blocks per memory type/linearity, first fit + merge). All textures are one bindless `sampler2D[4096]`; world materials SSBO is indexed by `firstInstance`. World: static vertex buffer; per frame CPU PVS + frustum + backface marking, indices copied per texture into a per-frame host buffer, one `vkCmdDrawIndexedIndirect` per pass (opaque/sky/liquid/translucent liquid). Brush entities are drawn with a dynamic depth bias (vkQuake `gl_zfix` values for D32F: constant -4, slope -0.125) so they win over coplanar world faces (e.g. e1m1's lowered floor door). Lightmaps: raw samples (mono or .lit) in an SSBO; a compute shader rebuilds visible surfaces' texels in an RGBA16F atlas (2048², layers) from styles + dlights every frame. Alias: all poses in one SSBO, lerp in the vertex shader, anorm shadedots as vkQuake, colormap via ramp masks + palette SSBO: base skins keep their original colours (blacking out shirt/pants texels broke linear filtering on non-player models such as the nailgun), and only translated entities add (translated − default) ramp colour where the nearest-sampled mask is set. Scene renders to RGBA8 at output size × render scale (multisampled + resolved when MSAA is on), then the post pass applies polyblend, contrast, gamma at output resolution and the 2D list is drawn on top in the same output pass (so UI is never scaled or gamma-adjusted). Texture sampling classes: `World` (user filter/anisotropy), `Nearest` (UI pics, colormap index textures), `Clamp` (sprites, skybox).
- Filtering and 8-bit emulation (ironwail/vkQuake parity, 2026-11-11):
  - Alias pipelines cull back faces (clockwise front, ironwail's `glFrontFace(GL_CW)`); other pipelines don't cull.
  - Texture filtering: `gl_texturemode` (ironwail's six `GL_*` names or 1–6; empty = `r_texfilter` picks nearest/linear with linear mips), `r_anisotropy` (default 16 like vkQuake's `vid_anisotropic 1`, clamped to the device), `gl_lodbias` (`auto` = -log2(samples)/2 when supersampling). They all go into the one `Sampling::World` sampler. Non-mipmapped modes use `max_lod 0`.
  - `vid_fsaamode 1` turns on per-sample shading (`sampleRateShading`) in the scene pipelines.
  - `r_dither` (default 1) with `r_softemu 0`: Bayer banding suppression of ±0.5/255 in the world and alias shaders and the post pass.
  - `r_softemu` 1 fine / 2 coarse / 3 banded palettizes in the post pass. A 128³ palette-index LUT is built on the CPU (`convert::palette_lut`, multithreaded) and stored in the palette SSBO after the 256 colours, packed 4 per uint. It is rebuilt when the metric changes: `r_softemu_metric` <0 auto = OKLab, or naive RGB in banded mode on maps without `.lit` (`World::lit`).
  - Polyblend, contrast and gamma are applied to the looked-up palette colour, like ironwail's postprocessed palette.
  - Per-mode values go in the Frame UBO (`soft`, `softf`), worked out in `frame::softemu_params`. World dither level 1 (coarse) snaps lightmap UVs to 1/16 texel, biases texture LOD by -0.5, and adds near (texture-space) / far (screen-space, fog only) noise. Level 2 (`r_softemu_lightmap_banding`) quantizes light to 64 levels with a -1 bias. Alias mode 1 dithers only in fog; mode 2 (`r_softemu_mdl_warp`) samples a `noperspective` texcoord at LOD 0 (software affine warp).
  - Coarse mode forces nearest + linear mips with at least 8× anisotropy. Fine mode dithers in post with noise per scene pixel.
  - Not ported: dithering for water, sky, sprites and particles.
- Example: `cargo run -p qrender --example offscreen [map] [w h] [game]` writes `target/qrender-<map>.ppm`. `QRENDER_DEVICE=<index>` picks a GPU; `QRENDER_VALIDATION=1` enables the Khronos layer.

## Milestone 4 crate boundaries (set before parallel work)
- `qplatform` owns SDL3, via raw `sdl3-sys` and linking the system libSDL3. Window creation has a Vulkan flag. It provides `vulkan_instance_extensions() -> Vec<CString>` and `create_vulkan_surface(instance: u64 /*VkInstance*/) -> u64 /*VkSurfaceKHR*/`. Events are a plain Rust enum (key, mouse motion/button/wheel, text, gamepad axis/button, added/removed, resize, quit). Also gamepad rumble, relative mouse, an audio stream fed by a callback `FnMut(&mut [i16])` in stereo at 44100/48000 Hz, and a high-resolution timer.
- `qrender` does not depend on SDL. It takes `trait SurfaceProvider { fn instance_extensions(&self) -> Vec<CString>; fn create_surface(&self, instance: u64) -> u64; fn drawable_size(&self) -> (u32, u32); }`. Inputs are `qformats` data plus a per-frame `RenderFrame` view built from `qclient::ClientState` (refdef, entities, particles, dlights, lightstyles, 2D draw list).
- `qsound` has no device code. `Mixer::paint(&mut [i16])` is called from the platform audio callback, sounds are fed from qclient `ClientEvent`s, and music is streamed (OGG/MP3/FLAC decoders allowed as solved-problem crates).
- `qinput` has no SDL dependency. It consumes `qplatform`-style events through its own small event enum mirrored in the binary, and produces `qclient::InputState`/view angle deltas. It owns binds, gamepad curves and aim assist.
- The root binary (`src/main.rs`) is the host glue: frame loop, cvars/commands, loopback server/client, and the console.

### qsound
- `SoundSystem::new(rate, loader)` returns `(SoundSystem, Mixer)`. `loader: FnMut(&str) -> Option<Vec<u8>>` fetches bytes by game path. `SoundSystem` stays on the game thread: `precache` (under `sound/`, resampled to mono i16 at the output rate, stereo downmixed), `event(SoundEvent)`, `update(Listener)`, `set_volume`/`set_bgm_volume`/`set_water_fx`, `play_music`/`play_cd_track` (`music/trackNN.ogg|mp3|flac|wav`, opened on the game thread)/`stop_music`/`pause_music`.
- `Mixer` is `Send` and lives on the audio thread. `paint(&mut [i16])` (interleaved stereo) first swaps out the `Mutex<Vec<Cmd>>` queue (a short lock), then mixes. Channel layout follows snd_dma.c: 4 ambients, then 128 dynamic, then statics up to 1024. Spatialization, pick-channel and ambient fade follow the C code. Music is decoded by symphonia inside the callback and linearly resampled. The underwater effect is a 1 kHz one-pole lowpass that fades in and out.
- `SoundEvent` mirrors the qclient events; the binary does the conversion (attenuation as a float, volume 0..1).

### qplatform
- `sdl3-sys` 0.7.3 links the system libSDL3 through pkg-config.
- `Platform` (`!Send`): `init` / `init_with_hints`, `create_window(title, w, h, vulkan)`, `poll_event(s)` (gamepads hotplug automatically), `rumble`, gyro (`has_gyro` / `set_gyro_enabled`), `open_audio(freq, FnMut(&mut [i16]) + Send)` (stereo S16; starts paused, so call `resume()`), `ticks_ns`.
- `Window`: `drawable_size`, `window_size`, `display_modes`, `desktop_size`, `set_display(DisplayMode::{Windowed, Fullscreen, Borderless}, size)`, `set_relative_mouse`, `set_text_input`, `set_fullscreen`, `vulkan_instance_extensions`, `create_vulkan_surface(instance) -> Result<u64>`. The binary implements `qrender::SurfaceProvider` on top of `Window`.
- The `Event` enum carries raw SDL scancodes and keycodes; `axis::*` and `button::*` hold the SDL gamepad enum values.

### qinput
- Keys use ironwail numbering (gamepad keys 207–248, plus `_ALT` variants). `KButton` behaves like `kbutton_t`. `InputEvent` is the crate's own enum; the binary converts from qplatform events.
- `InputHost: CmdContext`. `register_commands` adds bind/unbind/unbindall/bindlist/impulse and the +/- buttons. `handle_event(ctx, ev) -> Option<Routed>` returns what the console or menu still has to handle. `set_key_dest`.
- `Input::new(&mut Cvars)`. `Input::frame(&cvars, viewangles, dt, Option<&AimContext>) -> qclient::InputState`, where `look_delta` holds [yaw, pitch] degrees.
- Aim assist works only with the gamepad, never with mouse input in the same frame. Its parts: a cone of `aim_cone` plus the target's angular radius, linear falloff, look slowdown, and rotational assist while a stick is deflected. Snap is off. Targets need a visibility check through `trait Visibility`. `aim_assist_allowed(deathmatch, sv_aimassist)` gates it; the binary registers `sv_aimassist`.
- Cvars are listed in `qinput::CVAR_LIST` (mouse, joy_*, flick stick, gyro, aim_*).
- Differs from ironwail: flick stick works without gyro, and `gyro_mode` uses its own numbering (0 = always on, 1 = `+gyroaction` disables, 2 = `+gyroaction` enables).

### Host binary (`src/`)
- User data (config.cfg, saves, default screenshots) lives in `$XDG_DATA_HOME/quake-source-port/<game>/` (default `~/.local/share`), which is added as a top-priority search path. The game data dir is never written (user decision 2026-11-11).
- Modules: `main` (args, SDL/renderer/audio setup, frame pacing), `host` (cbuf/commands/cvars, loopback server+client, frame), `assets` (precache → qrender/qsound incl. `b_*.bsp` brush models via `load_level`, worldspawn fog/sky), `view` (V_CalcRefdef, colour shifts, viewmodel, entity/particle/dlight lists, alias frame lerp (`r_lerpmodels`) and MOVESTEP move lerp (`r_lerpmove`, R_SetupEntityTransform) tracked per entity; the view consumes `LERP_RESETANIM`/`LERP_RESETMOVE`), `sbar` (`scr_hudstyle` 1 = modern corner HUD, default; 0 = classic bar drawn in a full-width backtile strip below the 3D view via `View::reserve_bottom`), `console`, `menu` (basic menus only; the mod menu goes elsewhere; Options is a hub of Gameplay/Input/Graphics/Audio pages built from typed `Item`s (slider, toggle, choice, display mode, resolution, apply); display mode/resolution are pending until Apply runs `vid_apply`; `menu_options <page>` opens a page; every option cvar is archived; menus are laid out in a 16:9 640×360 virtual area (`Canvas::menu_layout`, integer scale `floor(min(h/360, w/640))`, 3x at 1080p) with the classic 320×200 screens centred in it and the options pages drawn as a wide panel with a highlight bar; option values with more than two choices (choice cvars, display mode, resolution) open a scrolling dropdown on Enter/click, while Left/Right still cycle; the quit prompt has clickable (Y)es / (N)o buttons (Left/Right + Enter, Y/N keys, Escape); mouse hover/click/wheel via `HostEvent::MousePos` mapped into that 640×360 space, click-to-set on option sliders), `draw` (2D canvas in 320-wide virtual units, `scale = floor(h/240)`), `platform` (SurfaceProvider, SDL→`InputEvent`), `png`, `default.cfg` (Quakespasm's, used when `default.cfg` is missing as in the 2021 re-release).
- `qw` (QuakeWorld connection): `QwClient` owns its UDP socket, resends `getchallenge`/`connect` (4 tries, 2.5 s apart; the userinfo carries name, topcolor, bottomcolor, rate 25000, msg 1 and a random qport), then runs `Netchan` and `QwState`. `poll` returns NQ messages for `Host::deliver` and console lines; precache checks every model and `sound/` file with `Fs::exists` and downloads missing ones (`download`/`nextdl`, written via a `.tmp` rename into the user data dir of the server's gamedir, which is mounted on the search path), then computes the map's checksum2 and a `CollisionModel` for prediction. `send_cmd` is called once per host server tic (msec from wall time; zero movement before the game is active). The host keeps it in `qw_client` beside `net_client` (`remote()` covers both): string commands from the NQ client are forwarded except the NQ signon replies and name/color, which `send_userinfo` turns into `setinfo`; after `ClientState::frame` the predicted origin replaces the view entity's (`cl_nopred 1` uses the last server position) and scoreboard pings come from `svc_updateping`. `cmd <text>` forwards text to any server. A QW `svc_disconnect`, a 60 s timeout or a rejection ends the connection with a console message.
- One cvar registry: the host's `CmdContext::cvars` is `server.core.cvars`. Lines go to host commands/aliases/cvars, then to server commands (`Server::has_command`), else to the local client as a string command.
- Frame: input every frame (`base_move` updates view angles), server tic at 72 Hz when `host_maxfps` > 72 (else every frame); attack/jump/impulse are latched until a tic sends them. `connect_local` signs on directly, so client signon string commands (and name/color) aren't forwarded.
- Options: `-basedir`, `-game`, `-hipnotic/-rogue/-quoth`, `-width/-height`, `-fullscreen`, `-headless` (offscreen renderer, simulated `1/host_maxfps` steps, no audio), `-autoquit <s>`, `-nosound`, `+cmd` (an argument may contain spaces: `"+delay 2 +forward"`). Extra host command `delay <s> <cmd>` for scripting. `screenshot [path]` writes PNG (headless offscreen image, or windowed via `request_capture` + `read_pixels`). Prints are passed through `server.core.loc.translate` (server already formatted them).
- Example: `quake-source-port -headless -game ad -autoquit 6 +map ad_sepulcher "+delay 4 screenshot target/shots/ad"`.
- Savegames: `Server::save_game`/`load_game` (qserver `save.rs`, version 5 text format as ironwail); `Sv::loadgame` makes connect/spawn keep the saved edicts and parms.
- Autosaves (`src/autosave.rs`, host frame after server/client events): local single-player only, after signon with a living player, outside menus, pause, intermission and demos. Gameplay settings archive `sv_autosave_keep` (default 5; 0 disables, maximum 10), `sv_autosave_entry` (default 1), `sv_autosave_secret`, `sv_autosave_monsters`, `sv_autosave_secrets` (default 0), and `sv_autosave_interval` (minutes; default 0). Timer uses server simulation time; any autosave restarts it. Per-level baselines prevent repeats at completion and prevent level-entry saves on loading a save. Coincident triggers produce one save. `autosave0.sav` is newest; complete text is staged and synced before rotating older slots, and excess slots are pruned after the new save is installed. Manual/quicksaves are separate. Trigger descriptions are encoded as a single underscore-separated v5 comment token, retaining external-engine compatibility. Save failures are reported in the console.
- Save/load cards: a 2×2 paged grid in the 640×360 menu canvas, navigable by arrows and mouse. Load shows the newest autosave and Browse Autosaves first; its submenu (also `menu_autosaves`) lists retained slots newest first and Escape returns to Load. Save only edits the twelve manual slots. `src/saveinfo.rs` reads v5 headers, globals, worldspawn and player fields without loading a level; cards show the worldspawn level title, filesystem modification timestamp (UTC), health, armor, kills/total, secrets/total, inventory and autosave reason. Legacy v5 saves work without sidecars. Missing/truncated saves are treated as unused slots.
- `src/save_inventory.rs` reads inventory masks from the active mounted `progs.dat`, resolves art through the mod filesystem/WAD, and handles Hipnotic/Rogue, AD upgrades/custom-key skins, Keep/Mjolnir's separate inventory banks, QBJ3's wrench and themed counted-key strips, Dwell's extra weapons, and MG3's native weapon pictures. Missing icons retain textual names; no game art is bundled. Installed-mod inspection and limitations are recorded in `docs/SAVE_INVENTORY_AUDIT.md`.
- One shared command buffer, as in Quake: the server's Cbuf text (QC `localcmd`, changelevel) is moved into the host Cbuf before each server frame and at each `exec_cbuf`, so it reaches host commands and cvars too. `name`/`color` are host commands that set `_cl_name`/`_cl_color` and forward to the server, which has server-side `name`/`color` (svc_updatename/updatecolors).
- `.lit` and `.ent` files load through `Fs::open_companion`, which only accepts them from the same or a higher-priority game dir than the map (ironwail's `path_id` check), so id1's `start.lit` never lights another game's `start.bsp`.
- Fog has a single current state, `cl.fog`. Worldspawn sets it at map load (unless an svc_fog arrived first), and svc_fog or the `fog` console command (Fog_FogCommand_f) change it; MG1 sets fog through QC. Fade times apply instantly.
- Liquid alpha (GL_WaterAlphaForTextureType): worldspawn `[_]wateralpha/lavaalpha/slimealpha/telealpha` override `r_wateralpha` and `r_lavaalpha/r_slimealpha/r_telealpha`; a per-type value of 0 falls back to water alpha. Not ported: ironwail's check that the map was vised for transparent water (`contentstransparent`).
- `r_drawentities 0` hides all entities except the view model (for debugging).
- `COMPAT_CVARS` (host.rs) registers cvars from other engines without effect (gl_*, r_*_list, scr_usekfont, ...), so vkQuake.cfg and mod configs load quietly. `gamecfg`/`savedgamecfg` are real: QC reads them.
- `sbar::Pack` (Id/Hipnotic/Rogue, from the mounted game dirs as in ironwail: rogue, hipnotic or quoth) selects the mission-pack status bar rules in both HUD styles: hipnotic laser/Mjolnir/proximity weapons, keys on the main bar, wetsuit/empathy shield items; rogue RIT_* ammo and armor bits, r_invbar1/2, powered-up weapon pics and shield/antigrav items, and no sigils. Rogue's CTF team-colour face is not done.
- Menu pause: in single player the host calls `Server::frame_held(dt, true)` while the menu is open, which skips physics like ironwail's `key_dest == key_game` check, without setting `sv.paused`.
- Demo playback (`src/demo.rs`, host `read_demo`): `playdemo`, `startdemos` (gated by `cl_startdemos`), `demos`, `stopdemo`, ported from ironwail's CL_PlayDemo_f/CL_GetMessage/CL_NextDemo. Messages go through the normal client parser, which is fed until `cl.time` catches up with `mtime[0]`. View angles are interpolated from `cl.mviewangles`. With no server world, point contents and ambient sound levels come from the client's BSP (`bsp_leaf`). The startup menu stays open over the demo; a key pressed in game mode during a demo opens the menu, and starting a map ends the demo loop.
- Demo recording (`DemoWriter`): `record <name> [<map> [track]]` writes `<user dir>/<name>.dem` from the messages in `feed_client`; `stop` ends it with svc_disconnect, and leaving the game or starting a map stops it too. Recording mid-game follows ProQuake/ironwail. The messages that reached signon 2 (`demo_head`) are written first, then scores, lightstyles, stats, setview and signon 3. Signon 3 is skipped when loopback already batched it into the head. With a map argument, recording starts when that map connects. `playdemo` also looks in the user dir.
- `timedemo <name>` reads one message per frame without a frame cap and prints frames/seconds/fps from wall-clock time, so the result is real even headless.
- Gaps: multiplayer menu, `sizeup/down` are stubs.

### Save inventory audit helper

Qbot assist audit and prerequisite planning (2026-11-11): every actual `setpos`
assist now appends evidence to `report.json`'s `assists` array: simulation time,
goal entity and kind, classname, recovery reason, source/destination player
origins and (when identified) the first blocking door. Its length equals
`noclip_uses`; clean route replays have no events. Classification compares all known
touch/firing approaches under three graph searches: no restrictions, door gates,
and gates plus execution blocks. Categories are `off_graph`, `missing_approach`,
`disconnected`, `prerequisite`, `mover_blocked`, `execution_blocked` and
`reachable_unfinished`. These describe current graph evidence, not definitive
root causes: cached firing candidates may be stale, disconnected geometry can
hide an interaction, and a blocked Ride edge does not establish a mover timing
bug. Off-graph recovery retains the current goal's identity, so use `reason` to
distinguish returns from direct goal assists. Console summaries count each
category and its non-monster subset (including returns with no current goal).

`actions::Prerequisites` searches alternative door openers and their prerequisite
chains before ordinary ungated opener recovery. It uses routes under actual
known gates and execution blocks, checks current shot clearance for firing
approaches, retains touch priority, rejects cycles, and bounds search to eight
doors deep and 64 search states. It executes one reachable leaf goal and then
observes/replans through the existing goal loop; it never assumes that a button
has already opened a door. `prerequisite_actions` counts changes to such a leaf
goal. Existing ungated recovery remains when no valid leaf is found: removing
it regressed scripted-map coverage in trial sweeps. This is an incremental
prerequisite planner, not a model of arbitrary QC state or future mover motion.

Final validation: fresh route-disabled sweeps preserve each of the 77 maps'
kills, secrets, exits and assist totals exactly, without baseline changes.
The prerequisite planner selected 17 actions across these maps.
The audit therefore does not demonstrate an assist reduction from prerequisite
search on this corpus. It points next to approach generation (especially buttons
and secrets), followed by disconnected-region investigation. Synthetic tests
cover evidence classification, alternate openers, chains, cycles, touch/firing
priority, execution blocks and depth bounds; report serialization checks escaped
entity names. Game-data traversal tests skip when assets are absent.
