# DESIGN

Living design doc. `PROPOSAL.md` says *what*; this says *how*. Update when decisions change.

Directional Dodge / Dive: see [DODGE.md](DODGE.md) for input, physics and body animation.

Bullet time adds peripheral radial blur even while stationary (keeping the centre
sharp, sharing the speed-blur shader), respects Reduce Motion, and plays local
Quake protection pickup/expiration cues on entry/exit.
Transitions include meter exhaustion and suspension by menus or pause.

Directional damage uses per-player view state and fading red HUD edge bands.
HUD → Directional Damage (`hud_damageindicator`, archived, default 1)
scales opacity with blood plus armor damage and respects `v_flashscale`.
Front/right/back/left hits map to top/right/bottom/left edges at impact;
repeated hits accumulate up to a bounded opacity and fade over time.
The menu tooltip explains the edge directions and Screen Flashes scaling.

### Hit and kill feedback

HUD → Crosshair edits the crosshair and hitmarker with static side-by-side previews;
both share normal (grey), target (white), and kill (red) colors. Shapes and sizes
are independent. Audio → Hit Sounds edits the synthesized hit and kill cues.
See [HIT_FEEDBACK.md](HIT_FEEDBACK.md) for settings, target detection, event
capture, synthesis, and diagnostic commands.

### Audio enhancements (`qsound::{category, reverb, hrtf, footsteps}`, `src/audio/`)

All client-side, wired under **Options → Audio** (and **Options → Audio → Volume Mix**, `menu_options audiomix`):

- **Underwater muffling** (`snd_waterfx`, archived, default `1`): 2-pole Butterworth low-pass filter (~550 Hz, Q 0.85, gentle 0.86 submerged gain) in `qsound::reverb::UnderwaterFilter`, smoothly crossfaded over 0.25 s while `Listener::underwater` is true.
- **Environmental reverb** (`s_reverb` default `0`, `s_reverb_amount` default `1.0`, 0.25–2.0, archived; slider dimmed while off): stereo Freeverb network (8 parallel comb filters + 4 series allpass diffusers per channel, zero audio-thread allocations) in `qsound::reverb::Reverb`, applied to world/spatialized SFX while keeping UI, hit feedback and music dry. `src/audio/acoustic.rs` probes 14 BSP rays (`BspWorld::trace_line`, throttled to 80 ms / 24 u motion) to estimate mean room size, sky/outdoor openness, and wall material reflectivity (`hitfx::classify`).
- **3D binaural audio (HRTF)** (`s_hrtf`, archived, default `0`): analytical Woodworth-Schlosberg ITD (fractional-sample delay up to ~0.68 ms) + Brown-Duda head-shadow low-pass and front/back/elevation pinna cues in `qsound::hrtf`, driven by the full 3D listener basis (`Listener::{forward, right, up}`). Classic integer stereo panning stays unchanged when off; split-screen guest mono contributions blend alongside player 1's binaural mix.
- **Sound occlusion** (`s_occlusion`, archived, default `0`): 5-ray soft line-of-sight cluster (`src/audio/acoustic.rs`) between listener eye and active dynamic sounds (immediate probe on `Start`, refreshed every 50 ms following moving entities) plus nearby static sounds; occluded channels smoothly low-pass (down to ~650 Hz) and attenuate (to 44%) in `qsound::Mixer`.
- **Optional footsteps** (`s_footsteps` default `0`, `s_footsteps_volume` default `0.6`, 0.1–1.5, archived, slider dimmed while off). Each surface (Stone, Metal, Wood, Dirt, Water, Slime, Lava) has four step variations and a landing cue. `qsound::footsteps` decodes the embedded CC0 Ogg Vorbis recordings with `symphonia`. The stone cues use short boot strikes from Fission9's stone floor recording, with a pitched-down strike for the landing. Source credits are in `crates/qsound/assets/footsteps/LICENSE.txt`. `src/audio/footsteps.rs` tracks grounded distance and landing velocity per local player (including split-screen guests) and classifies floor textures via `impacts::surfaces::texture_at` and `hitfx::classify`.
- **Per-category volume mix** (`s_vol_ambient`, `s_vol_weapons`, `s_vol_monsters`, `s_vol_world`, archived, all default `1.0`, 0–1; Audio → Volume Mix): `qsound::category::classify_sound` maps sound paths into Ambient, Weapons, Monsters, World, or Ui (always dry and un-attenuated by category sliders); static sounds and BSP leaf ambients map to Ambient.
- **Soundtrack switcher & music crossfade** (`s_soundtrack` archived default `""`, `s_music_crossfade` archived default `0.5`, 0–3 s): `src/audio/soundtrack.rs` discovers music packs across installed game directories (loose files and PAK/PK3 `music/`) and custom folders under `<user data>/music/<pack>/` (supporting both `trackNN.*` and arbitrary sorted playlists). Switching `s_soundtrack` in Audio → Soundtrack (or `soundtrack [name]` / `music_track <n>`) swaps the active level or main-menu track live with smooth crossfading in `qsound::Mixer::mix_music`.

### Smart weapon auto-switch & priority (`qserver::weaponswitch`, `src/host/weaponswitch.rs`, `src/menu/weapon_priority.rs`)

Wired under **Options → Gameplay**:

- **Weapon Auto-Switch** (`cl_autoswitch`, archived, default `1`): `0` = **Never** (never switches weapon on pickup), `1` = **Better weapon** (switches only if the picked-up weapon ranks higher in `cl_weaponpriority`).
- **Weapon Priority** (`cl_weaponpriority`, archived, default `"8 7 5 6 3 4 2 1"`, `menu_options weaponpriority`, dimmed while `cl_autoswitch 0`): custom screen listing the 8 stock Quake weapons from highest to lowest priority with `gfx.wad` weapon icons, live mouse drag-and-drop reordering, keyboard/controller grab-and-move (press **A** / **Enter** to pick up an item, move it up/down with D-Pad / stick / arrows, **A** / **Enter** to place, **B** / **Esc** to cancel), and **Reset to Defaults** (**Y** on controller).
- **Pickup interception**: on local servers (`qserver::server::physics`), `WeaponSnapshot` captures local clients' weapon state before `physics_client_move` (and after `PlayerPostThink` for dropped backpacks) and reverts unwanted pickup switches *before* `PlayerPostThink` calls `W_Attack`, preventing accidental mid-fire rocket/lightning self-damage without losing collected weapons/ammo or interrupting manual switches, out-of-ammo fallbacks, or firing animations. Mod-only weapons (`weaponismoditems` / unknown bits) are preserved on re-pickup and kept when walking over stock weapons. Remote multiplayer servers fall back to a client-side impulse restore (`src/host/weaponswitch.rs`).

### Automap / 3D wireframe map (`src/automap.rs`, `src/automap/`, `qrender::Draw2D::Line`)

Wired under **Options → Gameplay** (and **Options → Controls** `Automap` → `automap`, default `M` merged once via `cl_automapbind`; single player and co-op only, disabled in deathmatch):

- **Master toggle & sub-page**: `cl_automap` (archived, default `0` off) enables the automap on the statistics screen while holding **Tab** / **Select** (`+showscores`); **Automap Settings** (`menu_options automap`, dimmed while `cl_automap 0`) configures `cl_automap_view` (`0` 3D wireframe, `1` Top-down), `cl_automap_display` (`0` Framed panel, `1` Center overlay), `cl_automap_rotate` (default `1`, heading-up vs North-up), `cl_automap_reveal` (`0` Explored only, `1` Full map), `cl_automap_zoom` (`0.5`–`3.0`, default `1.0`), `cl_automap_alpha` (`0.2`–`1.0`, default `0.85`), and `cl_automap_markers` (default `1`).
- **Always-on HUD element** (`Kind::Automap`, `src/automap/widget.rs`): players who want the automap visible at all times during gameplay can add **Automap** (`automap@anchor`) in **Options → HUD → Edit HUD**, with per-element position, scale, opacity, framed/overlay background toggle (`g`), and shared automap options (`cl_automap_view`, `cl_automap_rotate`, `cl_automap_reveal`, `cl_automap_zoom`, `cl_automap_markers`). When no map is loaded in the HUD editor, a synthetic wireframe preview is rendered.
- **Architectural wireframe & exploration** (`src/automap/mesh.rs`): extracts deduplicated world edges from `bsp.models[0]` once per map load, omitting `TextureKind::Sky`, coplanar interior BSP split seams (`n0·n1 > 0.96`), and tiny slivers (< 8 u), while color-coding liquids (water/slime/lava/teleporter) and keyed door submodels (`func_door` silver/gold spawnflags). Exploration tracks visited BSP leafs and nearby PVS leafs (720 u radius, or 512 u AABB fallback on unvised maps) plus a player breadcrumb trail.
- **Rendering & interactive fullscreen** (`src/automap/draw.rs`, `src/automap/widget.rs`, `src/automap/input.rs`): projects 3D wireframe or orthographic top-down edges with Z-elevation color coding (current floor cyan, above indigo, below teal), 3D near-plane clipping and 2D Liang-Barsky rect clipping into `qrender::Draw2D::Line` quads (supported by both Vulkan and wgpu backends). On the statistics screen (`+showscores`), the automap centers cleanly below the top `scorebar` (or above the classic bottom status bar). Pressing `M` (`automap [0|1]`) opens the interactive fullscreen 3D map (pausing single player) with mouse/stick orbit, WASD/stick pan, Q/E/D-Pad elevation slicing, wheel/trigger zoom, `Tab`/`Y` 3D↔2D toggle, `F`/`X` explored↔full reveal toggle, and `R`/`LB` recenter.

### HUD layout and editor

The HUD is a free layout of elements (`src/hud.rs`, `src/hud/`), kept in the archived
`hud_layout` cvar and edited in Options → HUD → Edit HUD (`menu_hudedit` opens it). The
text form is one token per element, separated by spaces: `kind@anchor` plus `,<key><value>`
fields that differ from the kind's defaults (`x`/`y` offset, `s` scale, `o` opacity, `f`
font b/q/m, `z` size, `i` immersive, `g` background, `t`/`k` text and label colour as a
crosshair palette index (255, the default, keeps the element's own colours), `a`/`b` kind
options, `l` bar length),
e.g. `health@bl,a0 clock@tr,a3,fm`. Unknown kinds and fields are skipped (`layout.rs`).

- **Kinds** (`kind.rs`, the editor's Add tree): Status (health, armor, face, health and
  armor bars), Ammo (current ammo, ammo bar, ammo counts, shells/nails/rockets/cells),
  Inventory (weapon grid with `a` columns, keys & powerups, keys, powerups, sigils),
  Classic (the Quake status bar: `a` 0 status only / 1 with the inventory strip, `b` fill
  width with backtile), Time & Stats (clock, level timer, personal best, kills, secrets)
  and Performance Metrics (FPS, frame time, CPU, RAM, GPU, VRAM). Numbers take the big
  status bar digits, Quake 8×8 text or the modern TTF; text takes Quake or modern.
  Immersive elements (`Fade`) show for 3 s after their value changes, then fade over
  0.5 s; low health always shows.
- **Messages are permanent**: the center message, notify lines and sound captions are
  always in the layout (`Layout::ensure_permanent`) and can be moved and sized but not
  deleted. The console and captions draw at their rectangles (`MsgPlace`,
  `Console::center_place` / `notify_place`, `Captions::draw` centre, bottom and colour); their
  durations and `cl_captions` stay cvars and are edited from the elements.
- **Placement** (`place.rs`): an element's anchor is one of nine screen points
  (8 units in from the edges); its matching corner, edge midpoint or centre sits there,
  plus its offset. Each element reserves a fixed box, the widest its settings can show
  (`draw::size`: "888", the longest clock and timer text, every weapon slot of the pack
  plus enabled add-ons), so a layout that fits stays fitting in play. Elements never
  overlap: `place_all` places them in list order and moves one that would overlap an
  earlier one to the nearest free spot on screen (candidates line up with the wish, the
  screen edges or another element's edges). The result is cached per layout, sizes and
  screen. A full-width status bar touching the bottom makes the 3D view end above it
  (`reserve_bottom` → `View::reserve_bottom`).
- **Editor** (`editor.rs`, `editor_mouse.rs`, `editor_pad.rs`, `editor_rows.rs`, `editor_popup.rs`, `editor_draw.rs`): a
  dialog that can be dragged by its title bar and collapsed to a single title bar via the
  hamburger button in the top-right corner (or RB on a controller). The element list and
  selected element's config options panels use distinct background tints. It lists every
  element with scale and offset, buttons (Add, Delete, Reset to Defaults with a confirm,
  Done), and the selected element's settings: font, size, scale, opacity, visibility,
  background, text colour (values and numbers, tinting the big digit pictures; alerts stay
  red, owned ammo types gold; the personal best keeps `hud_pb_color`), label colour
  ("FPS", "K", ...), the position button (a 3×3 grid that snaps to an anchor with no
  offset), X and Y (typed or stepped) and the kind's options, with help under the dialog.
  Elements on screen can be clicked and dragged. While editing, the HUD is a preview with
  a sample player (`sample_client`), the selected element gives way when elements would
  overlap, and the settled offsets are written back (`Hud::settled`), so the dialog shows
  where things really are. Keyboard: arrows move and step, Enter acts, Esc leaves, Del
  deletes, Ins adds. Controller: left stick / D-pad navigates the element list (or config
  options); A selects an element to move it on screen with the left stick or D-pad (A
  confirms, B cancels); X toggles into/out of the element's config options; right stick
  moves the editor panel; Y adds, LB deletes, RB collapses/expands, LT/RT scales,
  View/Back resets (with confirm), Menu/Start finishes, and B backs out/exits; when using a
  controller, button glyphs draw directly on the dialog buttons, title-bar collapse toggle,
  and options header, with a single-row gamepad hint bar along the bottom.
- **Presets**: HUD → HUD Preset (`hud_preset`, archived: 0 modern, default; 1 classic;
  2 custom), above Edit HUD. Picking modern or classic sets `hud_layout` to `default` or
  `classic`, which the host turns into that layout (`Layout::default_layout`, the old
  modern defaults; `classic_layout`, a full-width status bar and the messages). Any change
  the editor saves sets custom; its Reset to Defaults sets modern. The host acts on a
  changed `hud_preset` only once the configs have run (`Host::hud_preset`), and once at
  startup checks the saved layout against its preset: a different one makes it custom
  (layouts saved before presets existed). ironwail's `hudstyle 0` picks classic, and
  `hudstyle 1`/`2` picks modern only from classic, so a custom HUD stays.
- **First run**: an empty `hud_layout` becomes the layout the old settings describe
  (`Layout::from_legacy`: `scr_hudstyle`, `hud_<elem>` modes and `_pos` anchors,
  `hud_face`, Time & Stats, `scr_show*` metrics, `scr_centerpos`, `con_notifypos`,
  `scr_textscale`, `scr_textbg`; elements sharing an anchor are stacked by
  `place::stack`), once the configs have run, and `hud_preset` is set to the preset
  it matches (else custom). Those cvars are still registered, so old
  configs load, but no longer saved. Reset to Defaults sets `hud_layout default`, which
  becomes the fresh-install layout the same way. Tools that need no HUD set
  `hud_layout center@mc` (only the messages).
- Player elements hide with the scoreboard and at death (the scoreboard then shows at
  the top unless a status bar shows it); Time & Stats hide with the scoreboard. In split
  screen each cell places the layout for its own size and draws the player elements; the
  metrics then go over everything, as outside the in-game HUD.

### Time & Stats and personal bests

The HUD's Time & Stats elements (`src/sbar/time.rs` formats, `src/host/level_time.rs`
`level_info`): the clock (local time from `qplatform::local_time`; 24- or 12-hour, with or
without seconds), the level timer (whole seconds, tenths or hundredths), the personal best
(its own precision; `hud_pb_100` 0 any% / 1 100% and `hud_pb_color`, a crosshair palette
index, default 2 green, are cvars shared with the save cards), and kills and secrets (count
or percent). Deathmatch shows only the clock and timer. The timer is the client clock, as
on the intermission screen
(server time starts at 1 s, stops while paused or in the single-player menu, and freezes at
`completed_time`); a loaded save goes on from its saved time, and such runs still count.
Personal bests live in `qsp_stats.json` per map as `pb_any` / `pb_100` arrays indexed by
skill (`qui::stats::MapStats::pb`), recorded at the level exit by `record_level_stats` only
in a local, uncustomized, non-deathmatch game (the skill is taken at the level's
serverinfo). 100% means every kill and every secret at the exit. A new PB prints
"New personal best (any%): 1:23.45". Save cards show the PB for the save's map and skill in
the PB colour, `hud_pb_100`'s category first, falling back to the other one.

### Performance metrics

The HUD's Performance Metrics elements (`src/host/metrics.rs`): FPS, frame time (average
and slowest frame, ms), CPU (process CPU time over wall time, as a share of all logical
cores), RAM (resident memory), GPU (ms per frame: the sum of the renderer's
pass timestamps via `take_gpu_times`, which turns `gpu_times_wanted` on; skipped while
`prof_start` owns the timestamps) and VRAM (device-local heap usage / budget from
VK_EXT_memory_budget, enabled when the device has it; `Renderer::vram`, None on the wgpu
backend). Values are sampled every 0.5 s while the layout has any of them. CPU and RAM come
from `qcore::procstat` (`/proc/self/stat` and `status` on Linux and Android,
`GetProcessTimes` and `K32GetProcessMemoryInfo` on Windows, unavailable elsewhere, shown as
"n/a"). Outside the in-game HUD (menus without a game, intermission, split screen) they are
drawn on top of everything.

## Compatibility targets

Everything ironwail/vkQuake load: id1, hipnotic/rogue (`-hipnotic`/`-rogue` builtins quirks), MG1/MG3 (Machine Games re-release `progs`, `mg1`/`mg3` dirs, KEX extensions where the references handle them), Arcane Dimensions (fog, skyfog, `alpha`, BSP2, `colormod`-free, large entity counts, particle-heavy, func_illusionary etc.). Formats:

- Archives: PAK, PK3/zip (store + deflate).
- BSP29, BSP2, 2PSB, lit/colored (`.lit`, else BSPX `RGBLIGHTING` via `qformats::bspx::find_lump`, else Quake64 RGB), external `.ent` overrides, `.vis` not required.
- MDL (incl. `QuakeForge` flags, MD3 native and `.md3` replacement models via `r_enhancedmodels`; `.md5mesh`/`.md5anim` re-release replacements baked into MD3 poses; mesh joints may name a later joint as parent, and pose parents come from the `.md5anim` hierarchy, each mesh joint mapped to its nearest animated ancestor, as in vkQuake's MD5Anim_Load, so MG3's `ogre_rocket` loads), SPR/SPR32, WAD2, LMP, TGA/PCX external textures, external world texture replacements (`textures/[<map>/]<name>`, see Renderer), `.skybox` (`sky` worldspawn key).
- QuakeC progs.dat v6, FTE/QSS extensions used by AD/MG (checkextension, string builtins, `sv_protocol 999` limits).
- Audio: WAV, OGG/FLAC/MP3 music in `music/` (decoders: `lewton` ok as a "solved" crate; mp3 via `minimp3`-class crate).

## Architecture

Cargo workspace. Binary crate at root (`src/main.rs`) wires crates together.

```
crates/
  qcore      math (Vec3, plane, bbox), byte reader, hashing, cvar + cmd + console text, filesystem (pak/pk3 search paths, gamedir stack)
  qformats   BSP29/BSP2/2PSB, MDL, MD3 (`.skin`), SPR, WAD2, LMP, palette, PCX/TGA, WAV parsing → plain Rust structs, no GPU
  qpool      edict slot allocator (ED_Alloc reuse), capped effect pools, SoA particle pool (see below)
  qvm        QuakeC VM: progs loader, interpreter, builtin dispatch trait, edict field storage
  qworld     collision (hull traces, BSP2 large hulls), SV_Move, physics (SV_Physics_*), area grid
  qnet       message buffers, protocols 15/666/999, loopback + UDP datagram transport
  qserver    server frame, builtins impl, entity delta encoding
  qclient    client state, parse, prediction-free NetQuake model, interpolation, effects/particles (CPU sim)
  qrender    Vulkan renderer (ash)
  qsound     mixer + spatialization, music streaming
  qplatform  SDL3 wrapper: window, events, gamepad, audio callback, timers
  qinput     binds, mouse, gamepad curves, aim assist
  qui        immediate-mode UI toolkit custom-built for console/menus/HUD; mod menu
tools/
  qbot       automated level-breaking test (headless server, god + noclip bot)
  qinspect   CLI: QuakeC disassembler (`progs`) and renderer-matched portal sheets (`portals`); bsp/mdl/pak dumps planned
  qbench     timedemo runner comparing against ironwail/vkQuake numbers; qprof  CPU+GPU profiling suite (vanilla, every enhancement, every add-on, ultimate)
```

Dependency direction: qcore ← qformats ← {qworld, qvm} ← qserver; qnet ← {qserver, qclient}; qrender/qsound/qinput/qui depend on qcore/qformats and client state, never on qserver. The server must run headless (no SDL/Vulkan) — required by `qbot` and dedicated servers.

### Entity and effect storage

The engine is not an ECS. It keeps Quake's own model, where QuakeC defines what an entity is and the engine supplies subsystems, because the progs field layout is fixed and mods depend on it.

- **Server**: edicts are one dense `u32` slot array in `qvm`, laid out exactly as progs expects (QC reads fields by offset, so access stays O(1) and branch-free). `qpool::EntityAllocator` hands out slots with the ED_Alloc reuse rules and generation-checked `Entity` handles for engine code that must not follow a reused slot (e.g. damage feedback); QC uses raw edict numbers. Engine-side per-edict data that QC cannot see (baseline, PVS leafs, alpha, send interval) is one `EdictExt` struct per edict in a `Vec` indexed by edict number (`qserver::Sv::ext`), as `edict_t` held it in C. Area-tree links live in `qworld::World`.
- **Behaviour**: entity logic runs in QuakeC (`think`, `touch`, `blocked`); the engine runs subsystems as plain functions in a fixed order each host frame (`src/host/frame.rs`): events and input, server (physics and QC), client (parse, interpolation, effects), view and sound, render — the same phases `prof_start` measures. No scheduler, no component queries.
- **Client**: network entities, statics and temp entities are `Vec`s of whole structs (`ClientEntity`, as `cl_entities[]`). Beams and dlights are `qpool::Pool`s (capped dense lists, swap-remove), and classic particles are a `qpool::ParticlePool` (SoA pos/vel/color/die/kind/ramp, auto-vectorised integrate).
- Host-side presentation (debris, ragdolls, blood, add-on effects in `src/`) owns its state in ordinary per-feature structs with `Vec`s.

### Renderer (`qrender`)
Teleporter windows are opt-in (`r_teleportwindows`, archived, default 0; Enhancements menu). Disabled frames skip destination views and retain classic teleport surfaces. Teleporter windows (`qrender::portals`, `frame::portals`) match world `*tele*` sheets against unnamed, nonsilent `trigger_teleport` brushes with one explicit `info_teleport_destination`. Changelevel slipgates, ambiguous links, silent/named triggers and unrelated textures stay classic. Up to four front-facing windows per frame use rigid camera transforms, destination PVS and exit-plane fragment clipping, with no recursion. Destination views include available brush/alias entities; remote network entities outside the server PVS may be absent. Portal and teleporter targets (`t.portals`, `t.portal_depth`) render single-sampled (`portal` pipelines) before the main scene at output-capped `r_portal_quality` scale (0 low `0.5×`, 1 medium `0.75×` default, 2 high `1.0×`, `sampler_linear` when scaled, `FrameUbo::portal_uv` UV clamping in `water.frag`/`fte.frag`) with per-tier view/recursion budgets, per-portal alias culling, and skipped ripples/caustics/non-oval particles (all destinations on low, nested `depth >= 1` on medium); dynamic UBO offsets isolate each view. Destination drawing uses a conservative source-aperture scissor (`frame::portal_scissor`) while clearing the active target region and retaining view-matched projection for recursive screen-space sampling. Bounds include the sheet's 0.25-unit acceptance margin, teleporter UV warp measured in target pixels (also in split views), and two pixels for sampling/rounding; near-plane crossings or invalid projections use the full view. This changes rasterization only: shared world ranges, camera transforms, draw order and lightmap requests are retained. Within a frame, portal/teleporter views sharing the same cached PVS surface-list allocation also share immutable world index/indirect ranges (`frame::world_draw::PortalWorldCache`); camera UBOs, clipping, entities and particles remain per view. The cache is recreated each frame so texture animation, alpha and hidden-surface changes rebuild the ranges, and lightmap requests enter the frame union only on a miss. CPU draw construction reads a compact 16-byte `DrawSurface` table (first index, index count, texture and lightmap) alongside the full CPU surfaces. It is built once after world and external brush loading and freed with the level; these fields are immutable afterward. Animation, visibility filtering, draw order and lightmap requests remain live, using the same paths as before. The extra CPU storage is 16 bytes per surface. The water shader composites an opaque, black-tinted shimmer and gold sparks independently of telealpha. Client weapon impacts test the shot segment near the reported hit against the BSP polygons of `*tele` textures, including sheets in front of a solid backing wall. The host defers the visual payload of weapon impact temp entities until it classifies the hit. A sheet contact suppresses the scripted and classic particles, enhanced impact smoke and sparks, decals, physical nails, and the explosion flash and matching sprite in either display mode. The same classification handles bullets, projectile spikes and explosions from rockets or grenades. With windows enabled, the impact settings also feed up to 12 short-lived contact points into the water shader. It distorts the destination image along an expanding ring and fades it over 0.65 seconds. Destination scissoring allows for the extra UV displacement while ripples are active. Gameplay teleport rules remain QuakeC-owned.

Debug visibility (`r_visibility`, session-only): `list [texture substring]` prints BSP face IDs, texture names, bounds and hidden state. `hide/show face <id>` and `hide/show texture <substring>` filter both world and inline brush geometry in the main view and teleporter destination views. Texture matching is case insensitive. `hide/show entity <render key>` filters nonzero render keys (ordinary client entities use their edict number); shared key 0 is rejected. `isolate <portal index> [camera distance]` optionally fixes the render camera in front of the sheet (4–4096 units, independent of mod player relocation) and keeps only that source sheet in the main view, bypasses source PVS, suppresses source entities/particles and retains destination scenery and available entities; indices match qinspect. `reset` restores everything; level teardown also clears filters. Hidden faces force the main world through the CPU PVS draw builder; normal frames retain GPU culling. Collision, lighting queries, server visibility and particle simulation are unchanged, so hiding a wall does not expand the PVS or expose unreceived network entities. Example: `r_visibility list tele`, `r_visibility hide face 123`, `r_visibility show face 123`, `r_visibility reset`.

- Vulkan 1.2 baseline + dynamic rendering when available; ash, hand-written allocator (big-block suballocation; few resource types).
- World: BSP surfaces batched into one big vertex buffer at load; per-frame visible face set from PVS + frustum culled on CPU (multithreaded mark-leaves), drawn via indirect indexed draws grouped by texture+lightmap atlas. GPU lightmap update for lightstyles (compute shader, like ironwail's approach) to avoid CPU uploads. Lightmap bounds match ironwail/vkQuake's `CalcSurfaceExtents`: evaluate texture projections in double precision, then round each to float before taking bounds and snapping to the 16-unit grid. Retaining doubles adds rows/columns on near-boundary faces and corrupts baked sample strides (notably qbj3 start). As in vkQuake `R_BuildLightMap` and ironwail, a face without samples in a lit BSP starts black and can receive dynamic light; only an entirely unlit BSP uses a fullbright fallback (`LmSurf::tmins.w`). This avoids glowing strips/triangles on qbj3 start.
- Alias models: GPU vertex lerp from packed frame buffers; instanced by model.
- Water warp, sky (scrolling + skybox), fog (AD `fog` / worldspawn), alpha surfaces sorted, r_wateralpha / per-entity alpha, fullbrights, colored lighting, palette-accurate shading option (`r_softemu`-style). Graphics menu toggles: `r_coloredlight` (default 1, archived; 0 loads only the mono lightmap, applied on the next map load) and `r_fog` (default 1, archived; 0 renders with fog density 0 but keeps the map/mod fog in `cl.fog`, so it returns immediately), plus a Sky Fog slider for `r_skyfog` (0–1, now archived). Sky wind (`src/skywind.rs`, ironwail/vkQuake gl_sky.c): a skybox's `gfx/env/<sky>wind.cfg` (`skywind distance yaw period pitch`; sky names end in `_`, so mods ship `<name>_wind.cfg`) makes its clouds drift: the sky shader samples the box at the view direction and at two offsets along the wind, cross-faded over the loop and laid over the still box by their alpha (ironwail's sky_cubemap ANIM). The host computes Sky_SetupFrame's vector (world space; ironwail's cubemap axes are Quake's (-y, z, x)) and phase into `Settings::sky_wind`, the frame uniform's `wind` in both backends. `r_skywind` (archived, default 1) scales the speed, 0 stops it; `skywind [distance yaw period pitch]`, `skywind_lookdir [period [distance]]`, `skywind_rotate yaw [pitch]`, `skywind_load` and `skywind_save` (into the user dir, which overrides the game data) tune it live. `r_fullbright` (single player only, as ironwail's cheat-safe check) draws the world lightmaps as neutral light (bit 4 of the frame uniform's `softf.x`) and gives alias models ironwail's 0.5 light colour.
- Shaders: GLSL compiled with `glslc` in `build.rs` to SPIR-V, embedded.
- Target: ≥ ironwail fps on AD large maps (ad_sepulcher, ad_tears) measured by `qbench`.

### Server / QuakeC

Interpreter ported faithfully from the references (opcode semantics, runaway loop limit, string table handling incl. dynamic strings for QSS extensions). Builtins table indexed by number, with extension builtins looked up by name like QSS. Physics ported from sv_phys/sv_move/world.c behaviors including known quirks maps depend on.

Parity rules found by the spawn/run parity sweeps against ironwail (2026-11-17, full audit in [COMPAT_AUDIT.md](COMPAT_AUDIT.md); `crates/qserver/tests/compat.rs` pins them). With them, spawn state is identical to ironwail on 830+ of 858 maps (the rest are ironwail failing on Linux file-name case or a map it can't spawn), and 3 s of simulation on every id1 map:
- `ED_Alloc` reuses only the head of a FIFO free list (ironwail since 27f3b9d5, vkQuake's circular buffer), not the lowest free index; world and client edicts are never listed (`qpool::EntityAllocator`).
- `SV_Physics` fixes its loop bound at the start of the frame (`entity_cap`): entities spawned during the frame (projectiles fired in PlayerPostThink, sparks) get physics from the next frame.
- `SV_Physics` does not write the `frametime` global (only Host_ServerFrame does), so SV_SpawnServer's settle frames run with the progs' value (0). `SV_Impact` sets the `time` global even when neither entity has a touch function.
- `PF_setmodel` gives alias models their real bounds over every pose (vkQuake `sv_gameplayfix_setmodelrealbox` 1; an MDL with a `.md3`/`.md5mesh` replacement keeps the MDL's bounds, as in vkQuake, where ironwail takes the replacement's bind pose) and sprites ±width/2, ±height/2.
- `PR_MergeEngineFieldDefs`: `alpha`, `scale`, `emiteffectnum`, `traileffectnum`, `tag_entity`, `tag_index`, `modelflags`, `colormod` (+ `_x/_y/_z`) are appended to every progs that lacks them, so map keys like `scale` work with any mod and saves carry them.
- `AngleVectors`, `vectoangles`, `vectoyaw`, `walkmove` reproduce C's float/double rounding (double `sin`/`cos`/`atan2` of float inputs, results stored as float); f32 math flipped an `(int)` truncation in AD.
- `PR_SetEngineString("")` is non-null; entity keys and values keep at most 1023 bytes (COM_Parse); savegames write strings raw (`"%s"`, newlines included), replacing only `"`.
- A `-dedicated` server runs `autoexec.cfg` and the command line, never the game's `quake.rc` (AD's sets `temp1 1024`).
- Console commands mods stuff from QC or set in their configs, as in ironwail/vkQuake: `v_cshift r g b percent` (`cshift_empty`, the contents shift outside liquids; sky no longer gets the water tint), `sky <name>` (runtime skybox), `hudstyle` (ironwail's cvar name: 0 picks the classic HUD preset, 1/2 modern unless the HUD is custom), `play`/`playvol`/`stopsound`, `chase_active` with `chase_back`/`chase_up`/`chase_right` (a `Camera::Chase` mode), `freecam [0|1]` / `freecam x y z [pitch yaw]` (our own; `host/freecam.rs`: a `Camera::Free` that flies noclip-style through walls with the movement keys and mouse while player 1 stands still and the game runs; demos or a local game with no remote players, not splitscreen; ends on map change; the local server adds the camera's fat PVS to player 1's entity filter via `Client::extra_view`), `pause` as Host_Pause_f (server side, `pausable`, broadcast, `svc_setpause`; pauses a playing demo), `host_framerate`/`host_timescale`, quiet `sys_ticrate`, sky wind (see Renderer), `v_idlescale` with `v_iyaw/iroll/ipitch_cycle/_level` (V_AddIdle sway; the gun takes it back out as CalcGunAngle does, twice for pitch, and intermissions always sway at scale 1), `gl_polyblend` and `gl_cshiftpercent` plus QuakeSpasm's `gl_cshiftpercent_contents/damage/bonus/powerup` (V_CalcBlend; during intermission only the contents shift shows), `cl_nolerp` (CL_LerpPoint returns 1 after clamping time), `scr_conalpha` (classic console background; default 1 keeps our opaque look, ironwail's is 0.5) and `fly` (Host_Fly_f). Mapper/debug commands: `mapname`, `maps [filter]`, `path`, `find`/`apropos`, `entities` (CL_PrintEntities_f), `edict n`/`edicts`/`edictcount` (host commands printing `Server::edict_text` etc., since a listen server's log only echoes diagnostics) and `pointfile [leak]` (`maps/<map>.pts` with collinear points merged, drawn as depth-tested arrows through the `r_showbboxes` line geometry; cleared on map load).
- Savegames: version 5, and KEX version 6 (a game-dir line after the version; refused for another game). `load` falls back to the re-release's save folder (`qcore::fs::kex_save_dirs`: Windows `Saved Games\Nightdive Studios\Quake`, or the Steam Proton prefix of app 2310) for a KEX save of the running game, and to saves vkQuake/QuakeSpasm (`<basedir>/<game>`) and ironwail (`~/.ironwail/<game>`) left. The Load menu lists those after our own saves (`Host::external_saves`, same folder order as `load`, our names win), labelled with their source (`SaveSource`), without thumbnails and without Delete; `saveinfo` previews KEX v6 files too. The dead-player check uses active clients' edicts (a dedicated server or a client still in signon can save).

### Input and aim assist

Gamepad via SDL3 gamepad API + SDL DB. Look: radial deadzone, response curve (exponent), acceleration ramp on sustained full deflection. Aim assist (gamepad only, never mouse):
- **Slowdown (friction)**: reduce look sensitivity when crosshair within an angular cone of a valid target's bbox.
- **Rotational/magnetism**: when player is moving and target is in cone, add a portion of the target's relative angular velocity to view.
- **Snap**: none (not industry standard for this genre); optional `aim_snap` cvar off by default.
Target selection: live monsters (`FL_MONSTER`, health > 0) and DM opponents if allowed, visible via trace, within range; weighted by angle and distance. Client-side, using interpolated entity positions; server cvar gating via serverinfo/stufftext.

### Controller support

- **Default binds** (`src/pad_defaults.cfg`): RT attack, LT/A jump, B swim down, X/Y weapon wheel, LB/RB previous/next weapon (`impulse 12`/`impulse 10`), Back scoreboard, LS run, RS centre view. Start/Guide act as Escape. They are queued after every `default.cfg` (id1's has no pad binds). After `config.cfg`, `_paddefaults_merge` runs once per config (`cl_paddefaults` 0 → 1) and fills in any default whose pad key is still unbound, so configs that predate the defaults pick them up. Back is its own key (`BACK`), not Tab.
- **Active device**: `Input::last_device` switches to the gamepad on a button or on a stick/trigger past 0.5. It switches to keyboard/mouse on a key, click, wheel, or mouse motion over 4 px (resting-mouse jitter doesn't count). Prompts show pad glyphs only while a pad is connected and was used last (`Host::pad_ui`). Rumble is gated the same way.
- **Glyphs** (`src/glyphs.rs`): the label/colour table comes from padwight's `button_glyph`. Xbox: coloured A/B/X/Y. PlayStation: coloured ✕○□△. Nintendo: neutral discs labelled by position (south shows B). LB/L1/L, LT/L2/ZL, View/Share/−, and so on. Family comes from SDL's gamepad type, then vendor id, then name (`qplatform::pad_family`, sent as `HostEvent::PadFamily`). `joy_glyphs` overrides it (0 auto, 1 Xbox, 2 PS, 3 Nintendo). Discs and PS symbols come from a 5-cell RGBA atlas rasterised at startup with bilinear sampling (`Renderer::register_pic_rgba_linear`). Keyboard keys are drawn as square tags. `Glyphs::button_label` / `button_label_raw` centres a button's label inside its rect with an optional inline controller glyph to its left (clipped to fit). General UI rule: whenever a clickable button has a specific controller input mapped to operate it, that glyph is drawn directly inside or next to the button while `pad_ui` is active (shared Back button, Map Packs / Level Select / Quaddicted filter + sort controls with Y opening the OSK and RT cycling sort, Demos tabs/sort/actions, Save/Load Delete, Directory Browser actions and modal Cancel, Confirm/Quit/Auto-aim Cancel/No, OSK Shift/Del/Done, Add-on New Game Play, HUD Editor controls, Demo playback bar + peek tab, Export Cancel), and footer hint bars only list remaining non-button actions.
- **Touch** (`qinput::touch`, `src/host/touch.rs`): SDL finger events become `Event::Finger`, and `SDL_TOUCH_MOUSE_EVENTS` is off, so touches never also arrive as mouse clicks. In menus a tap hovers and then clicks on release, and a vertical drag sends wheel steps. In the console or chat a tap re-opens the OS keyboard. In game the twin-zone overlay applies: a floating stick on the left half (base follows the finger past the rim, 10% deadzone) and drag-to-look on the right half (180° per screen-height drag × `touch_sensitivity`, `touch_invert`). Round buttons run commands. Held `+` buttons pass key `1000+i` so the release matches. FIRE also turns the view while dragged. `touch_enable`: 0 off, 1 auto (shown from the first touch until a key, click, mouse move or pad input), 2 always. `touch_size` 0.5–2, `touch_opacity`. Menu: Options → Input → Touchscreen (`menu_options touch`). Fingers are released when the key destination leaves game.
- **Menus**: D-pad or left stick moves, A selects, B goes back. The host auto-repeats held directions for the pad only, since keyboards repeat themselves. Footer button prompts appear only for an active controller. Back buttons sit beneath their menu content, sharing draw/click bounds (`menu/navigation.rs`). **Options › Controls** lists rebindable actions with keyboard and controller columns. Select starts capture, and the next key or button binds; a third key of the same kind replaces both. Backspace/Del clears the keyboard keys and X clears the pad keys. Esc/Start cancels. While capturing, `Input::capture` stops the sticks from emulating arrows. "Reset to Defaults" runs `_resetbinds`, which replays default.cfg's `bind`/`alias` lines plus the pad defaults and leaves cvars alone. `menu_options controls` opens the page. Pressing A on a text field (player name, join address) opens an on-screen keyboard: a 10×4 character grid plus Shift/Space/Del/Done. A types, X deletes, Y toggles shift, and B/Start closes it. Physical typing still works while it is open.
- **Weapon wheel** (`src/wheel.rs`, `+weaponwheel`): tap (released within `HOLD_TIME`, 0.2 s) quick-switches to the previously used weapon (`Wheel::last`, tracked from the active entry however it changed), so repeated taps toggle two weapons; holding past that opens the wheel, and while it is open, either stick (whichever is pushed further) or a mouse-driven virtual cursor picks a stock or enabled add-on weapon clockwise in assigned-slot order (stock first), instead of moving or turning. Releasing selects that exact owned weapon with ammo; addon selections stay local. `wheel/inventory.rs` supplies shared weapon identities, labels and slot order. In single player (local server, maxclients 1) the server tic and client time run at `cl_wheel_timescale` (default 0.25; Input page "Wheel Slow Motion").
- **Rumble** (`joy_rumble` 0..1): on firing, detected from STAT_AMMO dropping on the same weapon or an axe swing starting, with strength by weapon; on damage, scaled by armor + blood; and on view punches (`punchangle`). Requests are merged per frame and the main loop sends them to every pad (`Platform::rumble_all`).
- **Intermission**: any key, click or pad button except Escape/Start sets the attack button, which QC treats as "continue". After QC's exit delay (2 s, or 5 s in deathmatch), "Press any key/button to continue..." follows the active device.

Sub-options `r_debris_quality` (`0` low, `1` medium — default, `2` high), `r_debris_ragdolls`, `_ragdollstart` (0 after animation, 1 at death, 2 mixed — default), `_maxragdolls`, `_gibs`, `_shrapnel`, `_movers`, `_force` and `_killlift` make up `debris::Settings` (Debris Settings page, disabled while `r_debris` is 0). When it is off, `Debris::update` returns at once and owns nothing.
- **Quality tiers** (`settings.rs`): `r_debris_quality` scales simulation fidelity, trace cost, and active lifetimes across three tiers (`tier_for`): **Low** (`0`) uses up to `6` bones, `3` Verlet constraint/shape-match iterations at `30 Hz` (max `3` steps/frame), skips downward clearance traces and mover coupling, and caps pools at `min(maxragdolls, 16)` ragdolls (`12 s` post-sleep lifetime), `32` gibs (`8 s` server / `6–10 s` client), and `24` shards (`6` per barrel, `4–6 s`); **Medium** (`1`, default) uses `8` bones, `4` iterations at `45 Hz` (max `5` steps/frame), `min(maxragdolls, 32)` ragdolls (`24 s` lifetime), `64` gibs (`16 s` server / `8–14 s` client), and `48` shards (`10` per barrel, `6–9 s`); **High** (`2`) keeps `12` bones, `6` iterations at `60 Hz` (max `6` steps/frame), full `maxragdolls` (`48` default), `128` gibs (`10–20 s` client), `96` shards (`14` per barrel, `8–12 s`), and infinite settled corpse / server-gib lifetimes. Corpses fade out over `1.5 s` before retiring (or are evicted oldest-first when hitting the active cap), keeping their death-frame slot marked in `gibbed` so retired bodies never pop back into `AtDeath` animations.
- **Ownership**: a replaced server entity is flagged in `ClientState::debris_owned`. `view::entities` skips it, and relink gives it no model trail. The flag is released as soon as the server changes the entity (model, death frame, or removal), so QC state always wins.
- **Ragdolls**: a corpse is taken over once it holds a death frame. Death frames are found by name ("death", "deth", "dth", "die", "dead"), which makes it work for mod monsters. The trigger is the last frame of the sequence for 0.12 s, or any death frame for 1 s; with `r_debris_ragdollstart 1` it is the first death frame, so the killing shot or blast throws the body. With 2 (mixed) the choice is rolled once on the first death frame: the killing hit's strength is the pellets of the latest volley passing the body plus nearby explosions (12 at point blank), and below 6 the chance of playing the animation is `1 - strength/6`. The inferred shooter ignores muzzle flashes within 56 units of the impact, so a monster hit while firing is not taken as its own shooter (which flung bodies toward the player). Players (`<= maxclients`) are skipped. `rig.rs` builds a skeleton keyed by `(model, frame, max_bones)` from the pose: k-means clusters (up to `max_bones`, seeded by farthest-point sampling) plus `max_offset` bounding margin, with links between clusters that share a triangle and soft two-ring links against folding. Each vertex is skinned to two bones. `ragdoll.rs` runs Verlet particles with distance constraints, step-scaled damping, zero-move trace skipping, and velocity rescaling when switching sim rate (`set_step`). Bone rotations come from shape matching (Müller's rotation extraction, warm-started). Visible ragdolls are packed into the MDL vertex format (reusing cached vertex/scratch buffers without per-frame heap allocations) and sent as `RenderEntity::dyn_pose` / `RenderFrame::dyn_verts`, while offscreen ragdolls are skipped by `qrender::ViewFrustum` in single-view frames (checked against `Ragdoll::bounds()`). The renderer copies these into the dynbuf (set 0 binding 9), and `alias.vert` reads them when flag 16 is set. A ragdoll goes to sleep after 1 s still, and its packed pose is cached while it sleeps.
- **Gibs**: entities whose model has `EF_GIB` become tumbling `Body`s, keeping the throw velocity from the last two messages and scaling/expiring per tier.
- **Barrels**: an external brush model named `*expl*`/`*exbox*`/`*barrel*` that changes model (or vanishes next to an explosion) throws 6–14 shards (`fragment.rs` procedural MDL) per tier.
- **Movers** (`scene.rs`): `Scene` adds visible unrotated inline brush entities (`*N`) to the world's hull-0 traces when enabled for the active tier. Between frames, debris resting on or overlapped by a mover is moved with it, and debris nearby is woken. Rotated movers are skipped.
- **Pushes**: `shot_impacts` drive them. A bullet or nail pushes what lies on its line of fire (`fire.rs`). That line comes from a fast alias entity that vanished next to the impact, or else from the nearest muzzle flash in the last 0.15 s with a clear line to the impact, or else from the view. An explosion pushes everything within 200 units. One within 28 units of a ragdoll's bones gibs it (`gibs.rs`: the game's precached `EF_GIB` models, preferring ones named after the monster, plus its `h_*` head; id1 `gib1-3` as fallback; blood and `udeath`, spawning `3`–`6` gibs per tier) after 0.1 s, so a server-side gib wins. Explosions in the last 0.6 s also fling corpses as they are taken over. Bullet and nail hits from the last 0.3 s are remembered too, including hits on living monsters: QC's SpawnBlood sends a blood-colour `svc_particle` instead of `TE_GUNSHOT`, which the client collects as `blood_hits`. When a ragdoll is taken over, the latest volley whose line passes within 12 units of the body is replayed on it. Each pellet also adds a whole-body knock-back (25 u/s along the flattened shot), plus a 30 u/s lift with `r_debris_killlift 1` (Kill Lift), scaled by `r_debris_force`, so a good shot throws the body back. `impacts` runs before `take_over`, because the killing hit arrives in the same packet as the death frame.
- Fixed tier-rate steps (30/45/60 Hz, driven by `cl.time` so pause and slow motion apply).

### Customize: vanilla and customized games
A game is *vanilla* or *customized* from its start, and never changes mid-game.
Vanilla games aim for exact save (`.sav` v5) and demo compatibility with
ironwail and vkQuake; anything that changes the simulation lives behind
Customize. Starting a game (Single Player → New Game, or a map from Level
Select / Map Packs) opens the launch pop-up (`src/menu/launch.rs`,
`Prompt::Launch`, the pending game in `Menu::launch`): a big Play button,
tagged CUSTOM while any modifier differs from its default or any add-on is
on (`launch::customized`); Customize Experience, which opens
`Page::NewGameCustomize` (Gameplay Modifiers, Add-ons, Play; Back returns to
the pop-up); and, while something is modified, Disable All Modifications
(modifiers to defaults, add-ons off, per-add-on settings kept), reachable by
arrows/d-pad, click, Del/Backspace or gamepad X. Play sets `custom_enable`
(archived) from `launch::customized`, then asks for the skill (levels) or
confirms ending a running game; `map` then fixes `Core::custom` (read-only
mirror `custom_active`). There is no Customize row on the Single Player menu,
so nothing suggests changes apply to loaded saves. `menu_newgame` opens the
pop-up (screenshots, binds). Loading a `.qsa` makes the
game customized, a `.sav` vanilla. In a customized game the main menu gains
a Customize box (`Page::Customize`: Modifiers, Add-ons) and every modifier
and add-on stays editable, applying at once. In a vanilla game those rows are
fixed (`Menu::game_locked`: dimmed, "(fixed for this game)") except while
setting up the next new game (`Menu::new_game_setup`). Customized games save
as `.qsa` (add-on header plus `modifier <cvar> <value>` lines), show a
"Customized" save-card tag and skip level-select stats (`qsp_stats.json`).
Multiplayer games (split-screen, co-op: more than one slot) also save as
`.qsa` (`Server::qsa_saves`), since other ports refuse to save them and load
them as single player: the header has `vanilla` (not customized) and
`players <slots> <local> <coop> <deathmatch> <teamplay>`; `load_game` restores
maxplayers, the rules and `cl_splitscreen` before spawning, and rejoining
guests take their saved edicts (`sv.loadgame`). A plain `.sav` loads as one
slot, coop 0, deathmatch 0. Cards show "Split-screen, N players" or "Co-op".
`menu_options customize|newgamecustomize|modifiers` open the pages.
- Gameplay modifiers (`qserver::modifiers`, `Page::Modifiers`, Reset to
  Defaults): applied only when `modifiers::active` (customized, not
  deathmatch); `modifiers::value` returns the default otherwise.
- Player aids that never touch the simulation stay global options: auto-aim
  (Accessibility) and the grenade arc (HUD → Crosshair). Auto-aim only turns
  the local view, so demos and saves are unaffected.
- Auto-aim (`qinput::lockon`) is opt-in (`assist_autoaim`) and independent of
  gamepad slowdown. The settings submenu selects hold lock-on (default) or
  continuous toggle, acquisition cone and range. Controls adds the matching
  `+lockon` binding only while enabled. Hold picks the nearest visible enemy;
  toggle acquires near the crosshair and stays enabled to reacquire after loss.
  A stable entity ID retains the target while tracking. Clicking the look stick
  cycles visible enemies (left stick when move/look are swapped), suppressing
  its usual binding while locked. Corner ticks indicate a lock even with the
  crosshair disabled (`assist_autoaim_indicator`, default on). Toggle mode shows a
  small gold AUTO AIM label below the crosshair while armed, even between targets
  and with the crosshair or lock ticks disabled; each split-screen view uses its
  own active state. Hold mode requires
  a fresh press after target loss unless `assist_autoaim_reacquire` is enabled.
  Enabling assigns free RMB/LT defaults; conflicts prompt on Back and Yes opens
  Controls with Lock-on highlighted, preserving existing bindings.
- The host rejects auto-aim for remote clients and whenever any nonlocal player
  joins its server, including coop. Local split-screen is allowed, including
  deathmatch (players are targets there; coop targets monsters). Each player
  has independent lock state. Death, intermission, menus, demos and disabling
  the assist clear the lock. Targets must stay alive and in range. Acquisition
  additionally requires on-screen visibility through the map and inline brush doors/lifts (`host::aim_vis`). FOV follows the renderer's 4:3 adaptation and local
  viewport. Acquired locks persist through occlusion and leaving the viewport. Tests cover acquisition, tracking, cycling, toggling, occlusion,
  gating and conditional menu bindings.
- Grenade arc (`host::grenade_arc`, `host::arc_learn`, `assist_grenadearc`,
  default off): for the held weapon's throw profile (launch offset and
  velocity in the view basis, world-z lift, gravity scale, overbounce,
  stick-on-contact, fuse) the host simulates MOVETYPE_BOUNCE/TOSS flight
  from the player origin and draws the path as camera-facing FTE quads (walls
  occlude it) with a target ring at the end, lying on the last surface touched
  and growing with distance. The ring is stretched into an ellipse (along and
  across the throw) covering the first impacts of the extreme random throws:
  `spread_offsets` re-simulates every sign corner of `Profile::spread` (id1
  `crandom()*10` right/up; gel ±3.5% aim, ±8% speed; learned profiles keep a
  decaying max deviation, capped at 10% of speed). Bounces after the first
  impact are not covered. Profiles are keyed by view model: `known()`
  hardcodes id1/hipnotic/rogue `v_rock.mdl` (forward*600 + up*200, 2.5 s) and
  qbj3's grenade launcher, rebar cannon (sticks) and flak shotgun (spread
  centre). Held add-ons use `arc_learn::toy()`: the Stickybomb launcher
  (current charge speed from `Stickies::arc_speed`, up*200, sticks to
  anything) and the Gel sprayer (950 u/s from the eye, half the player's
  velocity, splats on first hit), both traced as MOVE_MISSILE; the other
  add-ons fly straight. Other mods are learned: `Server::thrown_by` lists the player's
  TOSS/BOUNCE projectiles each server tick; the first fast one (> 250 u/s) a
  weapon spawns gives its launch (one physics step undone, spread averaged),
  and following it gives stick-on-contact and fuse. Learned profiles live for
  the session per game dir. Each simulation step is a full SV_Move
  (`Server::grenade_trace`, passing the player), so doors, lifts and other
  brush entities bounce it and a DAMAGE_AIM entity (monster, player) ends the
  arc where it would explode. The "Grenade Arc Settings" sub-page (gated by
  the toggle; `menu_options grenadearc`) has `assist_grenadearc_style`
  (0 solid, 1 dashed, default 1), `assist_grenadearc_color` (crosshair palette
  index, default 1 yellow) and `assist_grenadearc_alpha` (0.1–1, default 0.6).
  Local games only, not in deathmatch; QC's aim randomness is not modelled.
- Modifier damage: qvm resolves QC `T_Damage` at load; each QC→QC call to
  it first runs `Host::before_damage`, which may change the damage parm or
  skip the call. `modifier_damagetaken` (25–300%) scales damage to clients,
  `modifier_enemyhealth` (25–300%) divides damage to `FL_MONSTER`s.
  `modifier_nofalldamage` / `modifier_nodrown` skip world damage (and
  `modifier_noselfdamage` any damage whose attacker is the target, applying
  the id1 knockback itself so rocket jumps still work) whose caller is
  `PlayerPostThink` / `WaterMove` (in water, not slime/lava), so no pain
  flinch either.
- After each physics frame, per-client state on `Level`: ammo increases
  scaled by `modifier_ammo` (50–400%, capped at the id1 limits or the QC
  value), decreases undone by `modifier_infiniteammo` (`currentammo` kept in
  step); health increases scaled by `modifier_health` (50–200%, capped at 100
  or the pickup's own result); `modifier_regen` heals 5 hp/s to 100 after
  5 s without losing health; `modifier_jumps` 2/3 gives air jumps on a fresh
  press, using QC's `FL_JUMPRELEASED` to tell presses apart.
- `modifier_horde` (0–3) adds that many copies of every monster at map
  spawn (the `sv_horde` code; the larger of the two applies).
  `modifier_pistolstart` calls QC `SetNewParms` instead of `SetChangeParms`
  on changelevel. `modifier_nosaves` makes the host refuse `save` (the Single
  Player Save entry explains why); autosaves still run.
- Tests: `crates/qserver/tests/modifiers.rs` (needs game data; vanilla games
  ignore modifiers, `.qsa` round trip), menu flow in `src/menu/tests.rs`.

### Test bot (`tools/qbot`)

A level-breaking test, not a player simulation (simplified 2026-11-12: the earlier nav-graph traversal bot tried to play levels built to challenge people and was dropped). The bot has god mode, noclip and full knowledge of the edicts, and sets off everything a level scripts; the question is whether the level or the engine breaks along the way. In-process headless `qserver::Server` at 20 Hz (`sys_ticrate 0.05`), `skill 3`, one local client driven by `set_move`, client entity updates skipped. `sv_altnoclip 0` (classic noclip: the up move is the vertical velocity, so flight steers independently of aim) and `sv_maxspeed 1000`. Code: `main.rs` (CLI, jobs, report, baseline), `bot.rs` (setup, main loop, teleport/pin handling), `bot/goals.rs` (goal scan, done tests, choice), `bot/fly.rs` (flight, aiming, firing spots, buttons).
1. Goals, rescanned every 2 s since triggers spawn monsters and items: FL_MONSTER edicts, `trigger_secret`, every other `trigger_*` that is SOLID_TRIGGER with a touch, `func_button`, touch-opened doors that fire a `target` (no targetname; key doors), pressed like buttons, shootable SOLID_BSP/SOLID_BBOX edicts (secret doors, altar triggers with health), every `item_*`/`weapon_*` the map places at load (later ones, such as backpacks and horde-wave drops, only keys, sigils, the Horn of Conjuring and items with a `target`; ammo, health and armor are taken by lowering the matching stat first, ammo in rogue's fields too; a plain item that still refuses the bot for 3 s fails at once; items not yet touchable, and keys the bot already holds, are dormant; taking a key reopens failed buttons and key doors), monsters whose classname starts with `monster_` even without FL_MONSTER (mgend's Chthon), and finally the exit (`trigger_changelevel`, touch cleared until everything else is done or failed). Pickups with a `target` go last, and nothing but another non-target goal is chosen for 5 s after one (mgend: the thunderbolt and each key raise Chthon for its next stage, which only works once the stage before has sunk). An edict seen free after its goal is done is forgotten, so a monster a spawner later puts in the reused slot becomes a new goal. Monsters that are not damageable yet are dormant (spawn-on-trigger, not solid; rogue statues, solid stone until their targetname fires) and skipped until they wake; dormant ones with `spawnfunction` set are hipnotic `func_spawn` templates, which only ever spawn copies, and are not goals. Touch spots keep clear of other triggers by the engine's 1-unit link padding on both boxes (else a teleporter next to a secret sends the bot away); a firing spot flight can't reach is warped to like a touch spot. Trigger volumes count once the player's box overlapped them; a key once it was placed and is not solid again; a button once its `state` changed.
2. Loop: nearest open goal by straight-line distance. Touch goals: fly to a point inside the box clear of every other trigger (a secret wrapped around a teleporter). Shootable goals: fly to the nearest open spot (rings of 48–320 units around the target, bodies ignored) with a clear shot at the centre or a face of the target, then fire. A shot is clear when the engine's own `traceline` (`Server::traceline`, monsters and brushes in the way) hits the target both from `origin + '0 0 16'` (where weapons fire) and from the origin (where the lightning gun's damage traces start); a non-solid target (a downed zombie, hurt only by splash) needs only nothing solid in between. Lightning gun within 560 units unless submerged (it discharges), super nailgun beyond, rockets for zombies. On the way it shoots any live monster in sight within 1200 units. Buttons fire on contact, which noclip never makes: fly to a spot just off a face (or on top, for floor buttons; or level with its top, for a lock bar set in a sill) with nothing of the world in between, switch noclip off and walk/swim into it for 1.5 s, up to 3 faces. `impulse 9` every 5 s (the keys it adds are stripped, so key doors stay locked until the key is taken); fire is held while impulses are queued because QC ignores them until `attack_finished`.
3. Recovery: a goal not reached after 5 s of flight is `setpos`'d to every 5 s (teleporters on the way keep bouncing the bot off). A move further than flight goes in one frame is a teleport: trigger goals at the departure point count as touched. A bot that doesn't move for 1 s although it tried (a teleporter whose destination lies inside it) counts the triggers there and `setpos`es to the goal. A goal times out after 20 s; failed goals get one more try once everything else is done. A knocked-down monster that is not solid and lies inside the world (e1m7's closet zombies, placed in the floor: they never get up and can't be hit, vanilla too) fails at once. When everything is done but `killed_monsters < total_monsters` (a monster that isn't a goal: e1m7's Chthon, killed only by `event_lightning` while two raised doors are up), buttons that popped back out are pressed again, up to 12 rounds: ones that move doors/plats/trains first, the others only once those have stopped; re-presses count as done in the report.
4. The level is finished when its changelevel fires or its intermission runs for 8 s. Sim time is capped at max(600 s, 10 s per goal) (`-time`). `<out>/report.json` per map: kills, secrets, triggers, buttons (incl. shootables), pickups (each done/total), has_exit/exited, `failed` ("kind classname #ent at (x y z): why"; at the end, kills short of `total_monsters` that no failed goal explains are listed as live monsters that were never goals, or a count of ones neither killed nor alive), sim/wall time, errors, `unusual`. A timeout says why (`bot/attempt.rs` tracks each attempt: closest approach, clear-shot and firing frames, health at start, pushes, warps), e.g. "timed out: shots do no damage", "never reached it (closest 36u)", "no free spot touching it"; the phrase before any numbers groups failures across a sweep. `<out>/trace/<map>.log` (`bot/trace.rs`) is the whole run with sim-time stamps: every console line unfiltered (`con`) interleaved with bot events (`bot`: goal picked, warps, pushes, done, FAILED with its diagnosis); `-v` prints the bot events to stderr too. The server runs with `developer 1`; `bot/devlog.rs` joins the console log into lines, drops ones every level prints (join, godmode, "N entities inhibited") and keeps the rest deduplicated (`t=first (xN): text`) as `unusual`. `tools/qbot/baseline-<game>.json` holds kills, secrets, events (triggers + buttons + pickups), exited and `log` (the map's known unusual lines: bad entity keys, monsters in walls, items falling out) per map: fewer of any, losing the exit, an engine error, or a developer-log line not in `log` (printed as NEW-LOG) is a REGRESSION (exit 1). Runs are deterministic; any bot change can reorder goals and shift numbers by one or two, so re-save (`-save-baseline`) only after checking that differences are explained.

First results (2026-11-12, all cores, about 1 s wall per game): id1 42/42 exits, 8 failed goals (e1m7 closet zombies knocked down where no open spot sees them, an e1m1 shootable trigger, e4m2/e3m4 buttons, one e4m7 secret); hipnotic 18/18 exits, 36 failed, mostly 31 spawn-on-trigger monsters that never woke (hip2m5, hip2m6); rogue 17/17 exits, 9 failed (buttons, a dragon, knights). Versus the old traversal bot's baselines some mission-pack maps have 1–4 fewer kills (hip2m6, r1m6, r2m2, r2m8): monsters whose spawners never fire, the main open item.

Guest-only temp entities (beam segments, which carry no key) are matched against player 1's by model and rounded origin and the missing ones added with the guest's view bit. `splitcmd <2..6> <command>` runs a client command as a guest (setpos, give, god). Phase 3 (2026-11-13): gamepad events carry their SDL id (`HostEvent::Pad`, `PadRemoved`). `host/split_input.rs`: the first pad used is player 1's (`p1_pad`); a guest's pad drives that guest; Start on a free pad takes over a padless guest or, while a local multiplayer game has room (`join_open`), raises `cl_splitscreen` and joins; other input from free pads is ignored then (outside local multiplayer free pads still drive player 1). A guest has its own `qinput::Input` (player 1's binds copied on join); its events run with `input_target` set, so `ctx.input()`/`ctx.cbuf()` point at the guest and its binds execute at once (`guest_cbuf`). While a menu or the console is open, guest presses navigate the shared menu (releases still reach the guest). `guest_moves` builds each guest's move from its input every frame with aim assist against its own targets (`aim_targets(cl)`), and runs its own weapon wheel (`Guest::wheel`, drawn in its cell). HUD: each cell draws its player's status bar (classic or modern, own `HudFade`), crosshair and scoreboard into a cell-sized canvas, moved into place with `draw::translate`; each cell also draws its player's center print (guests' `CenterPrint` events go to `Guest::center`, a console used only for its centerprint state); intermission, console, notify, captions and menus stay full-screen (player 1's). Sound: `qsound::Listener::others` adds up to 5 more listeners; a channel plays at the loudest any player hears it (mono for guests), a player's own sounds at full volume; guests' attenuated sounds more than 1000 units from player 1 (which player 1's client didn't get) are started too. Rumble goes to player 1's pad only once guests have pads. Host Game has Local Players (1–6, `_mp_localplayers`): Start Game sets `cl_splitscreen` and raises `maxplayers` to fit. Single player after a split game drops guests quietly. Tests: `host::split_tests` (headless host: pads claim, join, move their own player, binds hit only their player, Start opens the menu, a removed pad's player is taken over), `qsound` `split_screen_listeners`, menu `host_game_start`.

Subagent split: crates with frozen interfaces (qformats, qvm interpreter, qsound mixer, qui toolkit, qbot nav) are independent tasks given to separate agents once qcore's API is set.

## Implemented APIs

### qpool
- `Entity` (index = QC edict number + generation); `EntityAllocator` with `alloc_with(|idx, freed_at| bool)` for ED_Alloc-style reuse policies, `alloc_at(idx)`, `free(e, now)`, `get`, `free_time`.
- `Pool<T>`: `with_max` cap, `insert` returns false when full, swap-remove `retain`.
- `ParticlePool`: SoA, `spawn`, `kill`, `kill_expired`, `integrate(dt)`; per-kind ramps/gravity are in `qclient` `run_particles`.

### qformats
All parsers take `&[u8]` and return `qformats::Result<T>`; bad input gives an `Error { format, msg }` with the byte offset, never a panic. Vectors are `[f32;3]`.
- `Bsp::parse`: BSP29/BSP2/2PSB/Quake64 normalised into one set of structs (i32 children: a node child < 0 is leaf `-(i+1)`, a clipnode child < 0 is a contents value). Also `decompress_vis`, `leaf_pvs`, `parse_lit`.
- Miptex texel data that runs past the end of the lump (seen in qbj, retrojam2) is tolerated: mip 0 is clamped and zero-filled, as in ironwail, and smaller mips that are out of bounds are point-sampled from the previous level.
- Quake64 (`q64`): `miptex64_t` adds `MipTex::shift` (the renderer divides st by `2*shift`), only mip 0 is stored, and the 16-bit RGB lightmap is expanded into `Bsp::rgb_lighting` (used like a `.lit` when no `.lit` file is present) plus mono `lighting`. `lightofs` is halved to index the expanded data. Skies are 32×64 with the front layer on top at alpha 128 (`convert::sky_layers(.., q64)`).
- `parse_entities` keeps key order and duplicate keys.
- `Mdl`, `Spr` (v1 and SPR32), `Wad` (WAD2/WAD3), `parse_pic`/`parse_palette`/`parse_colormap`/`parse_pcx`/`parse_tga`, `Wav` (with loop points as in GetWavinfo).
- Known gaps: maps inside .pk3 are not covered by tests yet (qcore's zip reader will fix that). For stereo WAV, the frame count is length / (width × channels), whereas Quake divides by width only; the mixer must take this into account.

### qcore
- `math`: `Vec3`, `angle_vectors`, `vec_to_angles`, `Plane` (with `box_on_side`), `Bounds`. `vertex::ParticleVertex` is the shared packed particle layout, re-exported as qpart `Vertex` and qrender `FteVertex`, so geometry can transfer directly without a conversion copy.
- `reader`: `Reader<'a>`, a little-endian cursor that returns `ReadError{pos,need,len}`.
- `fs`: `Fs::new(basedir)` / `Fs::default_basedir()`, `add_game_dir`, `truncate_game_dirs`, `open -> Option<Vec<u8>>`, `exists`, `origin`, `list(prefix, ext)`. Search order within a gamedir: loose files < pak0..N < *.pk3 (sorted, QSS order); later gamedirs override earlier ones. Names in archives are case-insensitive. Loose files and `pakN.pak` fall back to a case-insensitive match when the exact name is missing (beyond the references, by user decision 2026-11-11). `..` is rejected. Each `open` reopens the archive; mmap is a future optimisation.
- `cvar`: `Cvars` registry (`register` keeps a value already set by `set`; the usual flags).
- `cmd`: `com_parse`, `Args::tokenize`, `Cbuf` (`wait`), `Commands<C: CmdContext>` with built-in alias/set/seta/toggle/echo. `exec` and `cvarlist` must be registered by the engine.
- `text`: Quake font text is 8-bit conchars indices. `decode` carries each byte as the same-valued Unicode scalar through string-based entity/save parsers and client print events; `encode`/`glyphs` restore the indices at VM, disk and drawing boundaries. BSP entities and external `.ent` files use this explicitly, rather than lossy UTF-8. Centerprints wrap, center and count typewriter glyphs by these indices (qbj3 colored door titles/icons); manual saves, autosaves and save previews preserve them too. Modern UI fonts keep UTF-8; translated text in a non-English language travels as UTF-8 bytes inside Quake text and is decoded only for drawing (`glyphs_utf8`, see Localization). See `QBJ3-LABELS.md` for the regression evidence.
- `time`, `vfs`: portable clocks and file access; see Web build below.
- Dependency: `miniz_oxide` (pk3 deflate).

### qworld
- `ents::Edicts`: the trait the server implements. Fields are read and written by enum (`V`/`F`/`E`). The `touch`/`blocked`/`think` callbacks receive `&mut World` so QC can run re-entrantly.
- `hull::CollisionModel::from_bsp`: hulls 0–2 and per-submodel heads. `Hull::trace` matches `SV_RecursiveHullCheck` exactly, including the epsilon, the 0.1 backup loop and doubles on non-axial planes.
- `world::World`: depth-4 area tree with C-identical link order. `trace` is SV_Move; also `link_edict`/`unlink`/`touch_links`/`point_contents`. Traces don't allocate.
- `phys`: per-movetype physics and push movers (`PhysParams` holds the cvars and f64 time). `physics_client_move` sits between PlayerPreThink and PlayerPostThink, which the server calls.
- `monster`: movestep / check_bottom / move_to_goal. `user`: SV_User movement.
- `pmove`: QuakeWorld player movement (pmove.c/pmovetst.c) for the QW client's prediction: `predict(physents, movevars, from, cmd, dead, spectator)` splits commands over 50 ms like CL_PredictUsercmd. Physents are brush submodels (traced with hull 1 through `Hull::recursive_check`) or boxes expanded by the player size; physents[0] is the world, whose hull 0 gives point contents.
- Where C would Host_Error, this crate carries on instead (bad movetype, SOLID_BSP without a model, and similar). Rotating pushers (`SV_PushRotate`) are deliberately absent, matching ironwail and vkQuake: hipnotic rotation is done entirely in QC.

### qvm
- `Progs::parse`: v6 progs. Every operand, jump and range is validated at load, so running code can't panic.
- `Vm::new/load(progs, max_edicts, maxclients)`: `execute(&mut dyn Host, fnum)` is re-entrant, with the reference limits (runaway, stack depth). Errors come back as `VmError { msg, trace }` and the VM stays usable afterwards.
- Edicts: one dense u32 slot array. `ed_alloc` follows the ED_Alloc reuse rules via `qpool::EntityAllocator::alloc_with`. The host must unlink an edict before `ed_free`.
- Strings: a handle ≥ 0 is an offset into the progs string table; a negative handle is an engine slot (1024 rotating temp strings, zone strings, interned constants).
- `trait Host { builtin, ext_builtin, has_extension, dprint, print }`. `Builtin` is an enum of the id1 numbers 1–80. Re-release ex_* names and numbers 90–92 are remapped. #0 builtins are resolved by name at load. Math and string builtins run inside the VM.
- `spawn::load_from_file(host, ents, SpawnFilter)`: ED_LoadFromFile, including the key hacks.
- Approximations: sprintf %g, strconv modes 0–2 only, `random()` uses its own generator rather than C rand(), and tokenize uses com_parse.

### qserver
- `Server::new(fs, cvars, maxclients)` holds `core` (fs, cvars, cbuf, clients, level state) and `level` (VM + World). `spawn_server(map)` follows SV_SpawnServer (including `.ent` overrides). `frame(dt)` runs cbuf, then client input, then SV_Physics, then sends.
- Clients are in-memory slots. `connect_local()` drains every prespawn signon buffer before spawning, matching the remote handshake, and redoes it after changelevel. Large maps such as ad_sepulcher need multiple reliable messages; skipping the later baselines left the player model unset and froze the client camera while server movement continued. `set_move(i, ClientMove)`, `client_command`. Output via `take_reliable(i)` / `take_datagrams(i)`, which are protocol 15/666/999 byte streams. `sv_protocol` defaults to 999 (INT32COORD, like ironwail/vkQuake): 666 coords wrap past ±4096, which breaks large maps (e.g. Mjolnir start2).
- `stats() -> LevelStats { total/found secrets, total/killed monsters }`, used by qbot.
- qworld `CollisionModel::submodels` mins/maxs are spread by ±1 as in Mod_LoadSubmodels; precache dispatches on file magic (alias models named `.bsp` load as alias).
- Localization (`loc.rs`, `Core::loc`): `localization/loc_<language>*.txt` over English, loaded in `Server::new` and reloaded by the host when `language` changes (see Localization). bprint/sprint/centerprint use PF_VarString with LOC_GetString + LOC_Format (`{}`/`{N}` filled from the following args, each translated), WriteString translates `$key` as ironwail. `Localization::translate` is the client-side LOC_GetString for whole print strings.
- Differences from ironwail: alias and sprite models get ±16 bounds, no QSS custom stats, no `sv_netsort`, and the `alpha` key is kept only when progs define an `alpha` field.
- Smoke tests: `smoke_fast` runs by default. `cargo nextest run --release -p qserver --run-ignored only smoke_all` loads every installed map; the summary goes to `target/qserver-smoke-all.txt`.

### qnet
- `msg`: `SizeBuf` (a copy of `qserver::msg::SizeBuf`, so qserver can switch to it later) and `MsgReader` (MSG_Read*: reading past the end sets `badread` and never panics). Both have coord/angle/angle16 for the PRFL_* flags of protocols 15/666/999. `protocol`: svc/clc/TE/U_/SU_/B_/SND_/STAT_ constants.
- `dgram::Connection` is the net_dgrm.c state machine and has no I/O: reliable messages are split into fragments (`fragment`, 1024 by default), each ends with EOM and must be acked before the next goes out. A fragment is resent after 1 s. Unreliable messages carry a sequence number and stale ones are dropped. Queued reliable messages are merged up to 64000 bytes. Use it through `send_reliable`/`send_unreliable`/`handle_packet`/`poll`/`take_outgoing`. `NetSocket<T: Transport>` ties a connection to a peer.
- `control`: `Ccreq`/`Ccrep` encode/decode for CCREQ_CONNECT/SERVER_INFO/PLAYER_INFO/RULE_INFO and CCREP_ACCEPT/REJECT/SERVER_INFO/PLAYER_INFO/RULE_INFO.
- `transport`: `Transport` trait, `UdpTransport` (non-blocking std UdpSocket), `LoopbackTransport::pair()`.
- `delta`: FTE replacement deltas (PEXT2_REPLACEMENTDELTAS), shared by both sides: `EntState`, `calc_bits`, `write_update`, `read_delta` (skips fields we don't use: prediction info, bones, lights, glow…), record and entity numbers (23 bits).
- `qw`: QuakeWorld protocol 28 (from id's GPL QW source). Constants (svc/clc/PF_/CM_/U_/TE_), QW coord/angle encodings, `UserCmd` with `write_delta_usercmd`/`read_delta_usercmd`, `Netchan` (client side of net_chan.c: sequence + reliable bit, one reliable message in flight resent until acked, qport), `ServerChan` (server side, for test servers), `sequence_crc_byte` (COM_BlockSequenceCRCByte: CRC-16/CCITT over the move bytes plus chktbl; only the first 512 of chktbl's 1028 bytes are initialized in the C source, the rest are zero), `block_checksum` (MD4 folded to 32 bits) and `map_checksum2` (XOR over all lumps but entities, visibility, leafs and nodes; mvdsv kicks on a mismatch at prespawn), out-of-band packets and info strings.

### FTE replacement deltas (PEXT2_REPLACEMENTDELTAS)
Port of vkQuake/QSS's entity delta protocol, layered on 15/666/999. It is needed for per-entity fields (`traileffectnum`/`emiteffectnum`) and interoperates with FTE-protocol clients and servers. PEXT2_PREDINFO is not implemented, so stats stay in svc_clientdata.
- Handshake (SV_SendServerinfo / SV_Pext_f): with `sv_protocol_pext2` (default 8; 0 = plain protocol) a remote client first gets `cmd pext`. Our client answers `pext 0x58455446 0 0x32455446 <mask>` (0 with `cl_nopext 1`); a vanilla client forwards a bare `pext`. Both get the serverinfo then. The local client skips the query. svc_serverinfo starts with `'FTE2' <pext2>` before the protocol number.
- Server (`qserver::delta::DeltaState`, per client): each frame builds a snapshot (the same PVS/alpha filter as U_* updates) and diffs it against the last one into per-entity pending bits (UF_RESET for new entities, sent twice; UF_REMOVE). `svcfte_updateentities` (`float time`, records, 0) replaces svc_time and the U_* updates. svc_clientdata still comes first. Frames are logged by datagram sequence in a 64-entry ring: `clcdp_ackframe` retires one, gaps mark frames dropped and their bits pending again, and -1 asks for a full resend. A snapshot that doesn't fit continues in more datagrams (`net.rs` sends all queued datagrams to delta clients and syncs `set_datagram_sequence` with the connection before each frame). The local client is lossless, so its frames are acked when written. Baselines and statics stay in the shared vanilla signon buffer: a reset is computed against the same vanilla baseline the client holds.
- Client: `ClientEntity::{netstate, delta_live}`. Each update applies the records and then every live entity (CL_EntitiesDeltaed), so they keep `msgtime == mtime[0]`. svcfte_spawnbaseline2/spawnstatic2, svcdp_updatestatbyte and svcfte_updatestatstring/float, and the FTE sound flags are parsed for foreign servers. Acks ride on clc_move (`ack_frames`); network datagrams carry their sequence (`ClientPoll::Messages`, `net_sequence`). `record` mid-game asks for a full resend so the demo starts complete. Demos recorded this way need a pext-aware engine (vkQuake/QSS/FTE/ours).
- Tests: `qnet::delta` (round trips, record numbers), `qserver::delta` (lost frames resent, snapshot split over datagrams), `tests/loopback.rs` (every protocol with and without deltas), `net.rs` UDP play (one delta client, one vanilla).

### qclient
- `ClientState`: protocol/flags, signon, precache name lists, `model_flags` (MF_*, which the host fills in after loading models), `entities` (with baselines, `msg_origins`/`msg_angles` [0]=new [1]=old, interpolated `origin`/`angles`), statics, stats/items, scores, lightstyles, viewangles/punch/velocity, intermission/centerprint, fog/skybox. Effects live in qpool containers: `beams`, `dlights` (`Pool`) and `particles` (`ParticlePool`, PT_* kinds).
- `parse_server_message(&[u8]) -> Result<(), ParseError>` handles every svc_* that ironwail's CL_ParseServerMessage handles (FitzQuake/RMQ bits, Nehahra U_TRANS, temp entities). Side effects come out as `ClientEvent`s (sounds, prints, stufftext lines, signon stages) through `take_events()`. Signon replies and string commands are queued as clc bytes, drained with `take_reliable_out()`.
- `frame(dt)`: time advance, CL_RelinkEntities (CL_LerpPoint; `nolerp` for a local server), beam temp entities, dlight decay, CL_RunParticles. The particle spawners (run_particle_effect, rocket_trail, explosions, splashes, entity_particles) are public. `QRand` stands in for C rand().
- Input: `base_move(&InputState, &MoveSpeeds, frametime) -> UserCmd`, `encode_move`/`build_move` (clc_move; the first two moves of a level are dropped).
- `qw::QwState`: the QW client. `parse(payload, ack, inseq, realtime)` reads one netchan payload and returns NQ messages plus `QwAction`s for the host (stringcmds, precache/download steps, `packet`, `reconnect`, disconnect). Signon: serverdata → soundlist/modellist (paged) → `Precache` (host checks files, downloads, then `finish_precache(checksum2)` emits the NQ serverinfo + signon 1 and returns the prespawn command) → `cmd spawn` stufftext (signon 2) → `skins` (signon 3, sends `begin`) → the first entity frame makes it active. Frames (64, `UPDATE_BACKUP`) are keyed by the acknowledged outgoing sequence, which is what the server keys its copies by; `svc_deltapacketentities` deltas from the frame named by its `from` byte (checked against the stored sequence) and an unusable delta is read and dropped, as FlushEntityPacket does. Each packet with entities becomes one NQ frame: `svc_time` (receive time), the translated messages, `svc_clientdata` built from the QW stats (`updatestat` for stats 0–10 and items is folded into it; the rest pass as NQ `updatestat`), and an all-fields `U_SIGNAL` update for every present player (entity slot+1, colormap slot+1 for player.mdl, angles from the command with pitch/3) and packet entity, and nails as entities 512+. Temp entities map 1:1 except gunshot/blood/lightning blood, which become `svc_particle`; EF_BLUE/EF_RED become the QEX quad/pentagram lights; chat prints get the NQ `\x01` prefix; userinfo becomes updatename/updatecolors. `build_cmd` stores the command in the outgoing frame and writes clc_move (checksum byte, loss, three delta usercmds) plus clc_delta. `predict` is CL_PredictMove: replays unacknowledged commands from the last server state with `qworld::pmove` against the world, inline brush models in the frame (hull 1) and other players (boxes), then interpolates to realtime − latency. Tests in `qw/tests.rs` run a scripted handshake into a real `ClientState`.
- The test `tests/loopback.rs` connects to qserver on start.bsp for protocols 15/666/999, each with and without replacement deltas, and checks signon, entities, the player origin and gunshot particles.

### qrender
- Vulkan 1.3 (dynamic rendering, descriptor indexing, multiDrawIndirect) via `ash` loaded at runtime; no SDL. `Renderer::new(&dyn SurfaceProvider, &palette)` or `Renderer::headless(w, h, &palette)` + `read_pixels()` (RGBA8). Windowed: `request_capture()` before `render` copies the presented swapchain image (swapchain gets TRANSFER_SRC usage when supported) into a host buffer; `read_pixels()` then returns it as RGBA8 (BGRA swizzled). `resize(w, h)` must be called by the host on window resize (vsync toggles recreate the swapchain).
- Loading: `load_world(&Bsp, lit) -> Vec<ModelId>` (submodels `*1..`; frees the previous level); `load_level(LevelBsp, &[LevelBsp]) -> (subs, brush ids)` also loads external brush models (`maps/b_*.bsp`): their faces, textures (appended to the material table) and lightmaps (same atlas) are appended to the world buffers and drawn like submodels. Each `LevelBsp` carries the BSP, its `.lit` and its external replacement textures (`ExternalTexture`: RGBA at any size plus an optional fullbright layer, indexed like `bsp.textures`). The host finds them as ironwail/vkQuake's Mod_LoadTextures do (`src/assets/external_textures.rs`): `textures/<map>/<name>` then `textures/<name>` (liquids `*x` as `#x`, skies never), the image from the highest-priority game dir winning, then png, tga, jpg, pcx, lmp (vkQuake's Image_LoadImage); `<path>_glow`, else `_luma`, as the fullbright layer of lit textures; the world takes any game dir, an external brush model only its own or a higher one (`Fs::priority`). A replacement is uploaded at its own size with a full mip chain (alpha forced opaque except on fences) and replaces the miptex's fullbright mask. Texel coordinates stay in miptex units: the material's 4th word (Vulkan) / `DrawU.extra.xy` (wgpu) holds the packed miptex size, which `world.frag`/`fs_world` divide by instead of the texture's own size; liquids already use the fixed `st / 64`. Arcane Dimensions ships 83 replacements (its waterfalls among them; found by Part 1's ad_tears still, V5), mjolnir 208. `tests/external_textures.rs` checks a 4× replacement covers a face like its miptex. Also `load_alias(&Mdl)`, `load_sprite(&Spr)`, `set_skybox(Option<&[Rgba;6]>)` + `load_skybox(&Fs, name)`, `register_pic(&Pic)`/`register_pic_rgba`, `set_conchars(128×128)`. Pics persist across maps. `light_point(p, styles)` = R_LightPoint. CPU-requested lightmaps (brushes and portal views, union over split views) use a reusable bitset indexed by the dense `World::lm_surfs` ids (`frame::lightmaps`). Setting a bit deduplicates immediately; scanning set bits in ascending order reproduces the former sort/dedup list exactly. The output vector and bits are reused, reset for every frame/map size, and the scan is restricted to the requested word span. The complete list is uploaded in the frame bump buffer, then dispatched in batches of at most 65535 surfaces. The GPU world culler has a separate reserved list. This avoids truncating large portal requests (ad_sepulcher with transparent water) and leaving brushes black until the camera turns.
- Per frame: `render(&RenderFrame)` with `View` (fov_x is for 4:3, adapted to aspect), `RenderEntity` (frame/prev_frame/lerp, skin, colormap, alpha, viewmodel, fullbright, player), `Particle` (palette colour), `DLight`, d_lightstylevalue ints (`lightstyle_value`), `Fog` (`parse_fog`), polyblend, `Draw2D` list (pixels), `Settings` (gamma, contrast, wateralpha + per-type, skyfog, skyalpha, dynamic, vsync, `msaa`, `render_scale`, `texture_linear`, `anisotropy`; changes are applied at the start of `render`: MSAA rebuilds the scene pipelines via `Pipelines::build` and the targets, scale rebuilds targets, filtering recreates the `Sampling::World` sampler and rewrites those descriptors). `View::reserve_bottom` keeps the bottom rows free of 3D (classic status bar). These mirror qclient fields; the binary converts.
- Internals: own block allocator (64 MB blocks per memory type/linearity, first fit + merge). All textures are one bindless `sampler2D[4096]`; world materials SSBO is indexed by `firstInstance`. World: static vertex buffer; per frame CPU PVS + frustum + backface marking, indices copied per texture into a per-frame host buffer, one `vkCmdDrawIndexedIndirect` per pass (opaque/sky/liquid/translucent liquid). Brush entities are drawn with a dynamic depth bias (vkQuake `gl_zfix` values for D32F: constant -4, slope -0.125) so they win over coplanar world faces (e.g. e1m1's lowered floor door). Lightmaps: raw samples (mono or .lit) in an SSBO; a compute shader rebuilds visible surfaces' texels in an RGBA16F atlas (2048², layers) from styles + dlights every frame. Alias: all poses in one SSBO, lerp in the vertex shader, anorm shadedots as vkQuake, colormap via ramp masks + palette SSBO: base skins keep their original colours (blacking out shirt/pants texels broke linear filtering on non-player models such as the nailgun), and only translated entities add (translated − default) ramp colour where the nearest-sampled mask is set. Scene renders to RGBA8 at output size × render scale (multisampled + resolved when MSAA is on), then the post pass applies polyblend, contrast, gamma at output resolution and the 2D list is drawn on top in the same output pass (so UI is never scaled or gamma-adjusted). Texture sampling classes: `World` (user filter/anisotropy), `Nearest` (UI pics, colormap index textures), `Clamp` (sprites, skybox).
- Filtering and 8-bit emulation (ironwail/vkQuake parity, 2026-11-11):
  - Alias pipelines cull back faces (clockwise front, ironwail's `glFrontFace(GL_CW)`); other pipelines don't cull.
  - Texture filtering: `gl_texturemode` (ironwail's six `GL_*` names or 1–6; empty = `r_texfilter` picks nearest/linear with linear mips), `r_anisotropy` (default 16 like vkQuake's `vid_anisotropic 1`, clamped to the device), `gl_lodbias` (`auto` = -log2(samples)/2 when supersampling). They all go into the one `Sampling::World` sampler. Non-mipmapped modes use `max_lod 0`.
  - `vid_fsaamode 1` turns on per-sample shading (`sampleRateShading`) in the scene pipelines.
  - `r_dither` (default 1) with `r_softemu 0`: Bayer banding suppression of ±0.5/255 in the world and alias shaders and the post pass.
  - `r_softemu` 1 fine / 2 coarse / 3 banded palettizes in the post pass. A 128³ palette-index LUT is built on the CPU (`convert::palette_lut`, multithreaded) and stored in the palette SSBO after the 256 colours, packed 4 per uint. It is rebuilt when the metric changes: `r_softemu_metric` <0 auto = OKLab, or naive RGB in banded mode on maps without `.lit` (`World::lit`).
  - Polyblend, contrast and gamma are applied to the looked-up palette colour, like ironwail's postprocessed palette.
  - Per-mode values go in the Frame UBO (`soft`, `softf`), worked out in `softemu::scene_params` (shared with the wgpu backend, with `post_dither`, `post_mode`, `forces_nearest` and `lut_metric`). World dither level 1 (coarse) snaps lightmap UVs to 1/16 texel, biases texture LOD by -0.5, and adds near (texture-space) / far (screen-space, fog only) noise. Level 2 (`r_softemu_lightmap_banding`) quantizes light to 64 levels with a -1 bias. Alias mode 1 dithers only in fog; mode 2 (`r_softemu_mdl_warp`) samples a `noperspective` texcoord at LOD 0 (software affine warp).
  - Coarse mode forces nearest + linear mips with at least 8× anisotropy. Fine mode dithers in post with noise per scene pixel.
  - Not ported: dithering for water, sky, sprites and particles.
- Post effects (Enhancements menu; SSAO and per-object motion blur default off; add-on night-vision/thermal goggles are in docs/ADDONS.md):
  - SSAO (`r_ssao`: `0` = off, `1` = low, `2` = medium, `3` = high; `r_ssao_strength` default 2; `r_ssao_radius` world units, default 32) runs inside the scene, between the opaque draws (world, opaque alias models) and everything translucent: the scene pass ends, the colour (MSAA: the multisampled image, which is therefore SAMPLED, not transient, and bound at set binding 8) and depth move to read-only, and `ao.frag` (AO viewport) reconstructs view positions from depth (MSAA: sample 0), takes normals from the smaller-difference neighbours, and sums a quality-scaled golden-angle spiral (`N = 6` with 2×2 Bayer on `low`, `8` on `medium`, `12` on `high` with 4×4 Bayer + noise; SAO-style normalized cosine with distance falloff) into an RG16F target (visibility, view depth). `t.ao` is capped at output resolution when `r_renderscale > 1`, and halved on `low` and `medium` (`(min(scene, output) / 2)`). Visibility is masked by scene alpha (sky writes 0) and faded with the fog factor so fogged distance isn't darkened. With MSAA, `aosource.frag` first extracts exact sample-0 depth/alpha at AO target resolution into an RG32F image (`t.ao_source`), so repeated generation reads use a single-sampled texture; the image is allocated on the first MSAA SSAO frame, reused between views/frames and freed with scene targets on resize/sample/scale/AO-quality changes. Single-sample SSAO reads the original depth/colour directly mapped into the active view. `aoapply.frag` then reads exact full-resolution scene depth (`scene_depth` or `scene_depth_ms` sample 0; early-outs on sky), clamps to the active view's AO bounds so split-screen cells never bleed, does a depth-aware bilateral blur/upsample (`2×2` on `low`, `4×4` on `medium`/`high`), and multiplies it into the scene colour (blend ZERO/SRC_COLOR, all samples), and the scene pass resumes. Water, sprites, particles, translucent entities and the viewmodel are drawn afterwards and are not darkened. Cost when on: one extra store/reload of the scene attachments. Profiling splits this work out of `translucent` into `ao-prepare`, `ao-generate`, `ao-to-apply`, `ao-apply` and `ao-resume`: transitions and rendering boundaries are separate from the generation/application draws; `ao-prepare` includes the MSAA snapshot extraction and its barriers, and timings include GPU stalls rather than isolated barrier costs. Queries are written on SSAO-off and menu frames too. As with the existing stage timings, these intervals cover the first split view; later views are included in `post`.
  - Per-object motion blur (`r_motionblur` on/off, `r_motionblur_quality` `0` low / `1` high [archived, default `1`; Enhancements menu `Motion Blur Quality`], `r_motionblur_amount` default 0.5: blur = amount × motion over 1/60 s; forced off by `a11y_reducemotion`): `RenderEntity::key` (client entity number; 0 for statics, temp entities, the view entity and the viewmodel) lets the renderer reuse a double-buffered map of last frame's origin/angles (`Renderer::prev_xforms` / `Renderer::cur_xforms`). Opaque alias models (when visible in the main view) and brush entities that moved (not teleported >256 units, frame gap <0.25 s) are checked against conservative screen-space motion/radius bounds (`vel_entity_visible`, `<0.45 px` blur or `<0.5 px` radius on high, `<1.0 px` blur or `<2.0 px` radius on low) before redrawing into an RG16F velocity target (`t.vel`: output-capped `min(scene, output)` on high, half that on low) by `velalias.vert`/`velworld.vert` + `vel.frag` (mapping `gl_FragCoord.xy` via `FrameUbo::vel_uv` to `scene_depth`/`scene_depth_ms`): both positions use the *current* view-projection, so camera motion never blurs, and fragments behind the stored scene depth are discarded. Alias vertex animation is not part of the motion. Post measures velocities against output resolution (`PostPush::mb_w`/`mb_h`) for consistent behaviour across render scales and `t.vel` sizes: on high it takes the centre velocity or, if still, the strongest of 8 constant-offset taps 24 output px away and averages 12 jittered colour samples; on low it skips the 8-tap neighborhood dilation on static pixels and averages 6 jittered colour samples, both clamped to 6% of the screen.
  - High-speed peripheral blur (`r_speedblur`, archived, default 1; Enhancements → Speed Blur) uses each player’s full interpolated 3D velocity in `view::speed`, with a smooth ramp from 800 to 2000 units/s. `View::speed_blur` follows each split view into `PostPush`; `post.frag` averages eight inward radial taps near the edges, leaving the centre and overlaid UI sharp. Disabled for dead players, intermission and `a11y_reducemotion`; independent of per-object motion blur. View settings and accessibility overrides live in `view::settings`.
  - Bloom (`r_bloom`, archived, default 0, the DarkPlaces cvar name; Enhancements → Bloom, plus a Bloom Settings sub-page `Page::Bloom` / `menu_options bloom`, dimmed while off: `r_bloom_quality` `0` low / `1` high [default 1], `r_bloom_intensity` 0.25–3 [default 1], `r_bloom_size` 0.5–2 [default 1], `r_bloom_bright` 0–1 [default 0]; DarkPlaces' `r_bloom_colorscale/brighten/blur/resolution/colorexponent/colorsubtract/scenebrightness` are accepted and ignored). Unlike DarkPlaces, which blooms everything bright on screen, light sources glow: while bloom is on, the scene pipelines are rebuilt (`Pipelines::glow`, `Desc::glow`) with a second colour attachment (`GLOW_FORMAT` RGBA8, `t.bloom.glow`, multisampled + resolved like the colour) written by `*_glow.frag` variants of world/water/sky/alias/particle/poly/fte (each `X.frag`/`X_glow.frag` is `#include "X.glsl"` without/with `#define GLOW`; `GLOW_OUT` in common.glsl, so the plain pipelines have no unconsumed output). Glow is fog-attenuated (`fog_factor`) and blended with the colour's factors, so translucent surfaces occlude it: fullbright texels of world and alias skins; lava (0.55 × colour, more where `lava_rings` heat breaks the crust) and teleporters (0.5); the teleporter-window sparks and gun-portal rim; additive FTE modes (AddA/AddC) at full colour, Blend/Premul FTE batches, classic particles and sprites by `effect_glow` (brightness 0.55–0.95, weighted toward saturated colours, so fire and sparks glow and smoke, bubbles and blood hardly do); modulating/subtractive modes, gel, sky and thermal-goggle output none. Portal and teleporter destination views use the single-sampled `portal` pipelines without glow. After the scene (and the velocity pass) `frame/bloom.rs` records per view: `bloom.frag` mode 0 reads the view's region of the glow (plus, with `r_bloom_bright`, the linearly sampled scene colour × `smoothstep(0.35, 0.9, max channel)`) into level 0 with Jimenez's 13-tap filter (taps half a destination pixel apart, so a 4× ratio still covers the footprint), mode 1 halves each level, then mode 2 adds `r_bloom_size` × a 3×3 tent of each smaller level onto the next (`bloom_up`, blend ONE/ONE). Levels are RGBA16F from half (quality 1) or a quarter (0) of `min(scene, output)` down to ~8 px, at most 7; split views use proportional viewports, and every tap clamps to the view's region. `post.frag` adds level 0 × intensity × `BLOOM_GAIN` 3 / Σ sizeⁱ after motion/speed blur and before palettizing, goggles, polyblend and gamma (so `r_softemu` palettizes the glow too). Cost on an RTX 3060 Ti at 1080p (ad_sepulcher timedemo, `QSP_GPUTIMES`): about 0.1 ms, mostly the chain in `post`; nothing while off.
  - Real-time dynamic lights (`r_shadow_realtime_dlight`, archived, default 0, DarkPlaces' name; Enhancements → Real-time Dynamic Lights, plus Real-time Light Settings `Page::RtLights` / `menu_options rtlights`, dimmed while off: `r_shadow_realtime_dlight_shadows` [default 1] and `r_shadow_quality` `0` low / `1` medium / `2` high [default 1]; needs `r_dynamic`, off with `r_fullbright`). The frame's dynamic lights stop being added to the lightmaps (lightmap.comp gets none) and to alias models' light colour (R_SetupAliasLighting); instead `crate::rtlight::select` takes up to 32 whose sphere touches a view, most important first (radius / (eye distance + radius)), and `dyn_lights` in common.glsl lights world/brush and alias fragments per pixel: Quake's `(radius − distance) / 128` above `minlight` (alias × 1.28 for its /200 × 2 scale), times a mild facing term `(0.7 + 0.3·N·L)` that fades out behind (Quake's lightmap distance, radius minus plane and in-plane distance, is longer than the Euclidean one, which this evens out on floors), clamped to 2 like the lightmaps. Normals: world faces from `dFdx/dFdy` turned toward the eye; alias models from `alias.vert`'s lerped anorm through the model's inverse transpose (`o_nrm`). The first 2/4/8 lights (low/medium/high) are shadowed: `light_visibility` (the hook a ray-traced test can replace) picks the cube face by the major axis of light → point, projects with `Lights::shadow_vp[layer]`, the very matrices the faces were rendered with (`rtlight::face_vps`: 90° frusta, near 4, far = radius, `setup_view`'s conventions), so no cube-map convention can disagree, and filters with a `sampler2DArrayShadow` (1 / 4 / 9 bilinear compare taps), after a normal offset of ~1.5 texels. Shadow maps (`lib/shadows.rs` `ShadowMaps`): one D16 2D array, six layers per light, 256² faces on low, 512² otherwise (placeholder 16², one light, while off); set 0 binding 10 is the light list (dynbuf at `OFS_LIGHTS`, `rtlight::LightsGpu`), binding 11 the maps. `frame/dlights.rs` records them at the start of the first view: per light and face a depth-only pass (`shadow_world`/`shadow_alias` pipelines with `shadow_world.frag`/`shadow_alias.frag`: fences and holey skins alpha-tested; two-sided; dynamic depth bias 2 / slope 2) of the world surfaces in the PVS of the light's leaf within its radius (`World::portal_surfaces` + plane and box tests; liquids don't cast), the first view's opaque brush entities (`WorldDraw::bounds`) and alias models (`AliasDraw::key`) within reach, except the entity that emits the light (`DLight::key`, the client dlight key: rocket, player's muzzle flash) and the view model; each face draws with the first view's frame uniform and its own `viewproj`. Off-screen entities cast no shadow. Cost on an RTX 3060 Ti at 1080p: demo1 unchanged within noise; eight shadowed 300-unit lights on high ≈ 0.15 ms of shadow faces + 0.35 ms more world shading. Debug: `r_testlight x y z radius [r g b]` adds fixed dynamic lights, `r_testlight clear` removes them (`src/host/render_commands.rs`).
- Optional liquid effects (all default off; Enhancements menu: Enhanced Water master toggle `r_enhancedwater` (default off; gates every effect below in `host.rs`) plus a Water Settings sub-page (`Page::Water`, also accessible via `menu_options water`: quality tier `r_water_quality` `0`/`1` [low/high, archived, default `1`], translucency, opacity, ripples + intensity, splashes, caustics + intensity) that is dimmed and refuses to open while the master is off):
  - `r_watertranslucency` (archived, default off) enables water alpha blending under the master; `r_wateralpha` (default 1, as in ironwail/vkQuake; the Enhanced preset sets 0.5) is editable in the menu only while both toggles are on, and then overrides map water opacity. Otherwise water follows the references (2026-11-17, found by the parity stills on ad_tears): the map's worldspawn `[_]wateralpha`, else `r_wateralpha` only where VIS sees through water or there is no VIS (`World::liquid_seethrough`, ironwail's `contentstransparent`; `Settings::wateralpha_vised_only`), else opaque. AD's progs stuffs `r_wateralpha` from its maps' `water_alpha`; before this, ours drew that water opaque. Translucent liquids bypass leaf PVS (retaining frustum/depth culling) so opaque-water VIS maps include submerged geometry; changing mode invalidates the visibility cache. This can increase rendering cost on large maps.
  - `r_waterripples` (menu toggle; strength from `r_waterripples_amount`, default 1): `water::WaterFx` (renderer, CPU) tracks alias entities by `RenderEntity::key` plus `RenderFrame::player` (view entity origin − 23, 1 unit above the feet) and samples world leaf contents (`World::liquid_surface`: contents at the point, then a march + bisection up to the surface; kind 1 water / 2 lava / 3 slime, +4 when solid caps the column). A liquid-contents change between frames (not a >256-unit teleport) emits a ripple at the surface scaled by speed; wading near the surface (`z - o[2] < 48`) leaves a wake ring every 0.3 s; landing droplets add tiny rings. `water::quality_budgets` caps active ripples at `8`/`16` (low/high, trimming excess when lowered), uploaded in the Frame UBO (1024 bytes: `water` with `water_quality`, `ripples[32]`, `ripple_amp[8]`). `water_grad` in `common.glsl` does per-ripple bounding-box and squared-annulus early rejects before `sqrt`, summing a 3-wave swell and Gaussian-enveloped rings (85 u/s, 2.5 s life) gated and scaled by `water_dist_fade` (`640..1024` low, `1024..1536` high); `water.frag` offsets the classic sine-warp lookup and shades horizontal water/slime slopes. Lava uses `lava_rings` instead: each event is one broad, non-oscillating swell that spreads slowly (`60·(1−e^{−0.9t})` units) under a slowed, weaker heave, and it adds heat (a cooling molten core at the impact plus a glowing ridge) that lerps the texel toward yellow-white, so lava reads as thick and molten, not watery.
  - `r_water_reflections` (archived, default `0`; Water Settings → Reflections `off`/`planar`/`ray traced`, with Reflection Strength `r_water_reflections_amount` 0.25–1.5 [default 1], dimmed while off): planar reflections of horizontal water and slime (not lava or teleporters) as portal views (`portals::reflection`: `rot` mirrors across the plane, `pvs` is the eye, `reflect` set). `frame::portals::reflection_portals` takes the liquid surfaces of the eye's PVS whose face points at the eye (|n.z| ≥ 0.99, eye more than a unit above) and touches the frustum, merges them per plane (bounds unioned) and keeps the nearest two; they join gun portals and teleporter windows in the same four slots (`FrameUbo::portal_max.w` 2 marks a reflection; teleporter sheets are 1) and targets (`r_portal_quality` scale; `gun_targets` keeps them once reflections were on). A reflection view draws no liquids (the reflecting sheet would cover everything) and keeps 8 units below the plane (`Portal::clip` lift −8), so the wobbled lookup never reaches past the drawn image at the shore; alias models use `portal_alias_mirror` (counter-clockwise front faces, since the mirror flips winding); the sky and fog come out right because the view's eye is the mirrored one. `water.glsl` (main views only) finds its sheet's slot by plane and box like teleporters, samples the target at its screen position wobbled by the classic warp (±0.0025) and the ripple slope (`r_waterripples`), and mixes it over the fogged water by `min((0.2 + 0.8 (1 − cos θ)^5) × strength, 0.9)`, raising the alpha of translucent water to match. The image is fogged along the reflected path already. One reflection costs about 0.07 ms on an RTX 3060 Ti at 1080p (`destinations`). Not in the wgpu backend (it has no portal views).
  - `r_water_reflections 2`, ray traced (Vulkan devices with `VK_KHR_ray_query` + `VK_KHR_acceleration_structure`; `Renderer::reflection_mode` falls back to planar elsewhere, and `QRENDER_NO_RT=1` forces that): every water/slime pixel of the main views (not lava, teleporters or portal views) traces one ray query. `gpu/rt.rs` detects support and enables `bufferDeviceAddress`; buffers then carry `SHADER_DEVICE_ADDRESS` and buffer memory blocks `DEVICE_ADDRESS`. Resources are made on first use (`rt.rs` `ensure_rt`): per submodel (world, brush entities, `b_*.bsp`) one static BLAS with opaque and fence (alpha-tested) triangles as separate geometries, over the world vertex buffer and an index copy (`rt/world.rs`; tables `idx`, `tex` = BSP texture | `RT_SKY`, `geom` = first triangle per submodel geometry); per frame slot a TLAS (world, every brush entity with its transform and alternate-texture bit, one instance for all alias models; custom index = submodel, `RT_ALIAS`/`RT_ALT` in `rt_types.glsl`), an alias BLAS, and a host buffer with the texture animation table (`resolve_texture` per BSP texture, primary then alternates) and the alias draws (`RtDraw`, 144 bytes). `frame/rt.rs`: the first view's alias list (`prepare_rt`) includes off-screen models while RT is on (viewmodel excluded, at most 131072 triangles), as do brush entities; `rt_pose.comp` (one thread per triangle, binary search over draws, vertex/index buffers read by device address, decoding as `alias.vert` incl. MD3 and ragdoll poses) writes world-space positions and per-triangle attributes (st, shadedot, draw); the alias BLAS is refitted while the model list is unchanged (up to 32 frames, then rebuilt), and the TLAS is rebuilt every frame before the views. Graphics set 1 (`pipelines/rt.rs`, part of `Pipelines::layout` only on RT devices) holds the TLAS and tables; `water_rt*.frag` (`water.glsl` with `RT`) are used for main-view water in place of `water`/`water_alpha`. `rt.glsl` reflects the view about the face normal bent by the ripple slope (×0.35) and the classic warp, traces from 0.5 units off the surface (fences and holey skins as candidates), and shades the hit like the raster path at a LOD from the ray footprint: world/brush texture × lightmap (+ per-pixel dynamic lights) + fullbrights, liquids warped and unlit, sky by `sky_common.glsl`'s `sky_color` (skyfog applied), alias skins with colormap, Quake shading and fullbrights; the result is fogged over eye → surface → hit and mixed with planar's Fresnel weight. The player's own body is reflected in first person too: while reflections are on (planar or ray traced, `Host::reflections_on`) the host emits it as a `portal_only` entity like it does for live gun portals (`View::with_self`; guests in split-screen alike), which the main view skips and reflection views and ray queries include; in third person it is a normal entity anyway. Water ripples and splashes ignore that entity (and the third-person `follows_camera` body), since `fr.player` already tracks the player; before, live gun portals or third person gave the player doubled wakes. The eye's PVS surfaces request lightmap updates every frame (planar reflections get the same by drawing that view), so reflected surfaces never seen directly are lit. Cost on an RTX 3060 Ti at 1080p over the e1m2 pool: about +95 µs builds and +150 µs water shading, close to planar overall. `tests/rt_reflections.rs` (start.bsp pool, skips without ray queries) checks that the water changes, that a model above it changes more pixels with reflections than without, that a `portal_only` body under the eye is invisible in the view but reflected in both modes, and that frames are stable across mode switches, MSAA and a level reload.
  - `r_watersplash`: vertical crossings (`vz > 80`, e.g. jumping or falling, not flat horizontal walking) spray droplets (6–32, by speed; half on exit) simulated with sv_gravity 800, capped with spray puffs by `water::quality_budgets` (`512`/`1024` drops, `128`/`256` puffs for low/high).
  - Shot impacts: the client queues the positions of bullet, nail, spike and explosion temp entities (`Client::shot_impacts`, passed on as `RenderFrame::shot_impacts`; lightning and beams are left out). Since the shooter is unknown, the renderer bisects the line from the view to each impact (stepping 1 unit back toward the view when `hit` sits on or slightly inside a solid floor/wall). Where that line crosses a horizontal, uncapped liquid surface, or the impact sits right at the surface, it adds a ripple and a small splash. Explosions (flagged in the queue) inside an uncapped liquid instead throw up a big splash above them: a tall column and a wide crown whose drop count, height and spread scale with `1 - depth/200`, so there is no splash at 200 units deep or more (`BLAST_MAX_DEPTH`). ## Milestone 4 crate boundaries (set before parallel work)
- `qplatform` owns SDL3, via raw `sdl3-sys` and linking the system libSDL3. Window creation has a Vulkan flag. It provides `vulkan_instance_extensions() -> Vec<CString>` and `create_vulkan_surface(instance: u64 /*VkInstance*/) -> u64 /*VkSurfaceKHR*/`. Events are a plain Rust enum (key, mouse motion/button/wheel, text, gamepad axis/button, added/removed, resize, quit). Also gamepad rumble, relative mouse, an audio stream fed by a callback `FnMut(&mut [i16])` in stereo at 44100/48000 Hz, and a high-resolution timer.
- `qrender` does not depend on SDL. It takes `trait SurfaceProvider { fn instance_extensions(&self) -> Vec<CString>; fn create_surface(&self, instance: u64) -> u64; fn drawable_size(&self) -> (u32, u32); }`. Inputs are `qformats` data plus a per-frame `RenderFrame` view built from `qclient::ClientState` (refdef, entities, particles, dlights, lightstyles, 2D draw list).
- `qsound` has no device code. `Mixer::paint(&mut [i16])` is called from the platform audio callback, sounds are fed from qclient `ClientEvent`s, and music is streamed (OGG/MP3/FLAC decoders allowed as solved-problem crates).
- `qinput` has no SDL dependency. It consumes `qplatform`-style events through its own small event enum mirrored in the binary, and produces `qclient::InputState`/view angle deltas. It owns binds, gamepad curves and aim assist.
- The root binary (`src/main.rs`) is the host glue: frame loop, cvars/commands, loopback server/client, and the console.

### qsound
- `SoundSystem::new(rate, loader)` returns `(SoundSystem, Mixer)`. `loader: FnMut(&str) -> Option<Vec<u8>>` fetches bytes by game path. `SoundSystem` stays on the game thread: `precache` (under `sound/`, resampled to mono i16 at the output rate, stereo downmixed), `event(SoundEvent)`, `update(Listener)`, `set_volume`/`set_bgm_volume`/`set_water_fx`, `play_music`/`play_cd_track` (`music/trackNN.ogg|mp3|flac|wav`, opened on the game thread)/`stop_music`/`pause_music`.
- `Mixer` is `Send` and lives on the audio thread. `paint(&mut [i16])` (interleaved stereo) first swaps out the `Mutex<Vec<Cmd>>` queue (a short lock), then mixes. Channel layout follows snd_dma.c: 4 ambients, then 128 dynamic, then statics up to 1024. Spatialization, pick-channel and ambient fade follow the C code. Music is decoded by symphonia inside the callback and linearly resampled. The underwater effect is a 1 kHz one-pole lowpass that fades in and out.
- `SharedMixer` (`lib/shared.rs`) wraps the `Mixer` for the binary: the device callback calls `paint_device`; video capture switches painting to the game thread (`capture_begin(monitor)`, `capture_paint(frames)`, `capture_end`) and the device then plays the captured samples from a bounded queue or silence. `SoundEvent::StopDynamic` stops entity and local sounds but keeps ambients and statics (demo seeking).
- `SoundEvent` mirrors the qclient events; the binary does the conversion (attenuation as a float, volume 0..1).

### qplatform
- `sdl3-sys` 0.7.3 links the system libSDL3 through pkg-config.
- `Platform` (`!Send`): `init` / `init_with_hints`, `create_window(title, w, h, vulkan)`, `poll_event(s)` (gamepads hotplug automatically), `rumble`, gyro (`has_gyro` / `set_gyro_enabled`), `open_audio(freq, FnMut(&mut [i16]) + Send)` (stereo S16; starts paused, so call `resume()`), `ticks_ns`.
- `Window`: `drawable_size`, `window_size`, `display_modes`, `desktop_size`, `set_display(DisplayMode::{Windowed, Fullscreen, Borderless}, size)`, `set_relative_mouse`, `set_text_input`, `set_fullscreen`, `vulkan_instance_extensions`, `create_vulkan_surface(instance) -> Result<u64>`. The binary implements `qrender::SurfaceProvider` on top of `Window`.
- The `Event` enum carries raw SDL scancodes and keycodes; `axis::*` and `button::*` hold the SDL gamepad enum values.

### qinput
- Keys use ironwail numbering (gamepad keys 207–248, plus `_ALT` variants). `KButton` behaves like `kbutton_t`. `InputEvent` is the crate's own enum; the binary converts from qplatform events.
- `InputHost: CmdContext`. `register_commands` adds bind/unbind/unbindall/bindlist/impulse and the +/- buttons. `handle_event(ctx, ev) -> Option<Routed>` returns what the console or menu still has to handle. `set_key_dest`.
- `Input::new(&mut Cvars)`. `Input::frame(&cvars, viewangles, dt, Option<&AimContext>) -> qclient::InputState`, where `look_delta` holds [yaw, pitch] degrees.
- Aim assist works only with the gamepad, never with mouse input in the same frame. Its parts: a cone of `aim_cone` plus the target's angular radius, linear falloff, look slowdown, and rotational assist while a stick is deflected. Snap is off. Targets need a visibility check through `trait Visibility`. `aim_assist_allowed(deathmatch, sv_aimassist)` gates it; the binary registers `sv_aimassist`.
- Gyro: `InputEvent::Gyro { pitch, yaw, roll }` (rad/s). Per-axis cvars `gyro_yawsensitivity`, `gyro_pitchsensitivity`, `gyro_rollsensitivity` (default 0; roll adds to yaw, may be negative), `gyro_noise_thresh`, `gyro_mode`. The Options → Input → Controller → Gyro page (`Page::Gyro`) also exposes `gyro_enable`, the aim style (`joy_flick` 0 = 2D aiming, 1 = flick stick) and `joy_flick_time`.
- Cvars are listed in `qinput::CVAR_LIST` (mouse, joy_*, flick stick, gyro, aim_*).
- Differs from ironwail: flick stick works without gyro, and `gyro_mode` uses its own numbering (0 = always on, 1 = `+gyroaction` disables, 2 = `+gyroaction` enables).

### Host binary (`src/`)
- Source layout: modules over ~500 lines are split along logical seams into submodules declared from the parent (`src/host.rs` + `src/host/*.rs`, `src/menu.rs` + `src/menu/*.rs`, `crates/qrender/src/lib.rs` + `lib/*.rs` via `#[path]`). Moved code keeps its behaviour; moved items are `pub(super)` so siblings can reach them.
- User data (config.cfg, saves, default screenshots) lives in `$XDG_DATA_HOME/quake-source-port/<game>/` (default `~/.local/share`), which is added as a top-priority search path. The game data dir is never written (user decision 2026-11-11).
- Graphics presets (`src/host/presets.rs`): `graphics_preset classic|enhanced|lowend` sets every visual option at once from one shared base list (enhancement masters and their sub-options, MSAA, anisotropy, render scale, dynamic lights, quality tiers), so switching never leaves a stray effect behind. **Classic** = the re-release look (enhanced models, MSAA 4x, every enhancement off); **Enhanced** = every enhancement on at its top tier (SSAO high, motion + speed blur, bloom high, real-time dynamic lights with high shadows, Enhanced FX/particles at high, impacts at spectacle with decals/nails/scorches, blood high, all water effects with planar reflections, see-through teleporters with high portal quality, debris high, MSAA 8x clamped to the device; render scale and supersampling untouched); **Low-End** = Classic with original models, no MSAA, 4x anisotropy and every quality tier at low. - `qw` (QuakeWorld connection): `QwClient` owns its UDP socket, resends `getchallenge`/`connect` (4 tries, 2.5 s apart; the userinfo carries name, topcolor, bottomcolor, rate 25000, msg 1 and a random qport), then runs `Netchan` and `QwState`. `poll` returns NQ messages for `Host::deliver` and console lines; precache checks every model and `sound/` file with `Fs::exists` and downloads missing ones (`download`/`nextdl`, written via a `.tmp` rename into the user data dir of the server's gamedir, which is mounted on the search path), then computes the map's checksum2 and a `CollisionModel` for prediction. `send_cmd` is called once per host server tic (msec from wall time; zero movement before the game is active). The host keeps it in `qw_client` beside `net_client` (`remote()` covers both): string commands from the NQ client are forwarded except the NQ signon replies and name/color, which `send_userinfo` turns into `setinfo`; after `ClientState::frame` the predicted origin replaces the view entity's (`cl_nopred 1` uses the last server position) and scoreboard pings come from `svc_updateping`. `cmd <text>` forwards text to any server. A QW `svc_disconnect`, a 60 s timeout or a rejection ends the connection with a console message.
- One cvar registry: the host's `CmdContext::cvars` is `server.core.cvars`. Lines go to host commands/aliases/cvars, then to server commands (`Server::has_command`), else to the local client as a string command.
- Frame: input every frame (`base_move` updates view angles), server tic at 72 Hz when `host_maxfps` > 72 (else every frame); attack/jump/impulse are latched until a tic sends them. `connect_local` signs on directly, so client signon string commands (and name/color) aren't forwarded.
- Options: `-basedir`, `-game`, `-hipnotic/-rogue/-quoth`, `-width/-height`, `-fullscreen`, `-headless` (offscreen renderer, simulated `1/host_maxfps` steps, no audio), `-autoquit <s>`, `-nosound`, `+cmd` (an argument may contain spaces: `"+delay 2 +forward"`). Extra host commands for scripting: `delay <s> <cmd>`; `menu_keys <key>...` presses keys in the open menu (names as `bind` takes them, e.g. `menu_keys DOWNARROW TAB e 1 m YBUTTON`) and `menu_text <text>` types into a menu text field, so menu states can be screenshotted headless. `screenshot [path]` writes PNG (headless offscreen image, or windowed via `request_capture` + `read_pixels`). Prints are passed through `server.core.loc.translate` (server already formatted them).

- Autosaves (`src/autosave.rs`, host frame after server/client events): local single-player only, after signon with a living player, outside menus, pause, intermission and demos. Gameplay has an `sv_autosave` toggle (default 1; 0 disables) and an Autosave Settings sub-page archiving `sv_autosave_keep` (default 5; 0 also disables, menu range 1–10), `sv_autosave_entry` (default 1), `sv_autosave_secret`, `sv_autosave_key` (triggers when player 1 gains a standard silver/gold key, AD custom key, Keep skeleton key, or QBJ3 counted key, via `Server::player_keys`), `sv_autosave_monsters`, `sv_autosave_secrets` (default 0), and `sv_autosave_interval` (minutes; default 0). Timer uses server simulation time; any autosave restarts it. Per-level baselines prevent repeats at completion and prevent level-entry or held-key saves on loading a save. Coincident triggers produce one save. `autosave0.sav` is newest; complete text is staged and synced before rotating older slots, and excess slots are pruned after the new save is installed. Manual/quicksaves are separate. Trigger descriptions are encoded as a single underscore-separated v5 comment token, retaining external-engine compatibility. Save failures are reported in the console.
- Save/load cards: one centred column of cards (480×62 in the 640×360 canvas, pitch 66). On Load the newest save (row 0) is pinned at the top above a divider; the other cards scroll in pixels beneath it, clipped above the hint row, with a draggable scrollbar right of the column (`menu/scroll.rs`: `card_y`, `card_at`, `fix_card_scroll`). The wheel scrolls the list itself (24 px per notch, no wrap) and the card under the pointer becomes the cursor; before, the wheel was mapped to Up/Down, so it moved the highlight and the list only followed once the cursor left the window. Up/Down move (scrolling just enough to show the cursor card), Left/Right jump 3, mouse hover/click picks the card under the pointer. Save shows a New save card (first free `sN`) and then every non-autosave; picking an existing save asks before overwriting. Del/Backspace, pad X or the card's Delete button ask, then `_deletesave` removes the save and its thumbnail. Prompts (`menu/prompt.rs`) are modal yes/no boxes or the skill picker: New Game while a game is running asks first, and starting a map from Level Select/Map Packs picks the skill (switching mods mid-game asks too). `src/saveinfo.rs` reads v5 headers, globals, worldspawn and player fields without loading a level; cards (`menu/cards.rs`) show the level title and map file, local or relative time (SDL `SDL_TimeToDateTime`), skill, time in level, health, armor, kills, secrets, keys, weapons (not the axe) and autosave reason. Missing icons retain textual names; no game art is bundled. Installed-mod inspection and limitations are recorded in `docs/SAVE_INVENTORY_AUDIT.md`.
- `exec_cbuf` is Cbuf_Execute: it runs once per frame, so the startup pass after `stuffcmds` stops when the first pass stopped at a `wait`. A frame whose commands spawned a server (`ServerCore::spawns`) also runs a server frame, as Host_Frame does, so `map` + N `wait`s run exactly N server frames in both engines.

At world build, `World::check_water_vis` (ironwail's `Mod_CheckWaterVis`) checks whether each liquid type's PVS crosses content boundaries (`water_vised`), and `World::needs_transparent_novis` forces `novis` (`transparent_liquids`) only when an active translucent liquid type lacks water-vis on the map.
- `r_drawentities 0` hides all entities except the view model (for debugging).
- `COMPAT_CVARS` (host.rs) registers cvars from other engines without effect (gl_*, r_*_list, scr_usekfont, ...), so vkQuake.cfg and mod configs load quietly. `gamecfg`/`savedgamecfg` are real: QC reads them.
- `sbar::Pack` (Id/Hipnotic/Rogue, from the mounted game dirs as in ironwail: rogue, hipnotic or quoth) selects the mission-pack status bar rules in both HUD styles: hipnotic laser/Mjolnir/proximity weapons, keys on the main bar, wetsuit/empathy shield items; rogue RIT_* ammo and armor bits, r_invbar1/2, powered-up weapon pics and shield/antigrav items, and no sigils. Rogue's CTF team face (Sbar_DrawFace: in multiplayer with `teamplay` 4..6, `r_teambord` with shirt/pants fills and the frag count, gold digits on a white shirt) is drawn by the classic bar (`Sbar::rogue_team_face`); like ironwail it reads the local `teamplay` cvar, so it shows on listen servers.
- Menu pause: in single player the host calls `Server::frame_held(dt, true)` while the menu is open, which skips physics like ironwail's `key_dest == key_game` check, without setting `sv.paused`.
- Demo playback (`src/demo.rs`, host `read_demo`): `playdemo`, `startdemos` (gated by `cl_startdemos`), `demos`, `stopdemo`, ported from ironwail's CL_PlayDemo_f/CL_GetMessage/CL_NextDemo. Messages go through the normal client parser, which is fed until `cl.time` catches up with `mtime[0]`. View angles are interpolated from `cl.mviewangles`. The startup menu stays open over the demo; in the attract loop (`_playdemo_loop`, queued by `CL_NextDemo`) a key pressed in game mode opens the menu, and starting a map ends the loop. `playdemo` typed or picked by the player ends the loop (`demonum = -1`).
- Demo playback controls (`src/demo/playback.rs`, `src/host/demo_play.rs`, user demos only): ironwail's keys, Space pause, Up/Down double/halve the speed (0.25..8, below 0.25 pauses), holding Left/Right scrubs at 5× the speed backwards/forwards, Shift/Ctrl ×0.25; ours add PgUp/PgDn ±10 s, Home start, End next map, I/O clip marks, Backspace/Del clear marks, E export, K keep (auto-demos), H hides/shows the bar (the wheel is swallowed: any other key opens the menu). Triggers are axes, so `Host::handle_input` turns their dead-zone crossings (`joy_deadzone_trigger`, `demo_ui.triggers`) into K_LTRIGGER/K_RTRIGGER for `demo_key`; the event still reaches the binds, which a demo ignores. Console: `demo_seek <time|+s|-s>` (`90`, `1:30`; parsed from the raw line because the tokenizer splits at `:`), `demo_speed`, `demo_pause`, `demo_mark_in/out/clear`. With `cl_demo_endpause` (default 1, Options → Demos) a user demo stays paused on its last frame (svc_disconnect or end of file) instead of disconnecting, so it can be rewound; the attract loop, timedemo and exports end as before.
- Demo timeline (`src/demo/index.rs`): on `playdemo` a background thread replays the file through a bare `ClientState` (`index::scan`; synchronous on wasm) and records per serverinfo the map, its block offset and first/last `mtime` in game (signon 4). Running demo time = the map's `base` + time since its `t0`; `Playback::ord` counts the NewMaps seen (`demo_new_map`). The bar shows "Indexing..." and seeks wait (`pending_seek`) until it arrives.
- Demo seeking (`src/demo/keyframes.rs`): our demos carry FTE replacement deltas (each frame lists only changes), so ironwail's rewind (re-reading an older block over the current state, `demo_rewind`) would be wrong; we restore snapshots instead. After each block in game a `ClientState::demo_snapshot` (qclient `snapshot.rs`: a clone without particles, beams, dlights, temp entities and queued events; `ClientState` is `Clone`) is kept when none lies within 0.5 s (`DENSE`) on that map; snapshots further than 12 s (`NEAR`) from the play head thin to 5 s (`SPARSE`), the first of each map always stays, and a 384 MB estimate (`snapshot_bytes`) doubles the sparse spacing as needed. `demo_seek(t)` locates (map, server time), reads on from the current frame when the target is just ahead on the same map, else restores the latest snapshot at or before it (or the map's first; another map's snapshot reloads the level, static sounds and sky, `reload_seek_level`), or restarts the file when the map has none yet, then replays blocks with sounds and one-shot events skipped (`Host::demo_seeking`, `seek_skips`) and clears transient effects (`clear_seek_fx`: ragdolls and gibs (`Debris::clear`; they own entity numbers via `debris_owned`, which a restored older state may not have, so debris writes are also bounds-checked), add-on effects, client effects, FTE particles, blood, impacts, hit fx, tracers, `SoundEvent::StopDynamic`). Holding rewind is a seek per frame to `now − 5 × speed × dt`, at most half a second of replay. Test (game data, `host/tests/demo_seek.rs`): a recorded e1m1 walk seeks back through a snapshot to exactly the state a fresh forward seek reaches (entity origins, models, frames, stats), rewinds to 0 and stops, and pauses at the end.
- Playback bar (`src/host/demo_bar.rs`, `cl_demobar` 2 shown (default, the user's choice), 1 hidden (back for 3 s after a keyboard control and at the end of a demo; mouse movement does not bring it back), 0 never; H, View and the Hide button hide a showing bar and show a hidden one at once (`toggle_demo_bar` clears `shown_until`, and H skips `show_demo_bar`). When using a controller (`pad_ui`), each button on the bar grows taller to draw its pad button glyph (`Btn::pad_key`) directly underneath its icon or label inside the button; any text buttons dropped on narrow screens (e.g. 4:3) still appear in a compact hint strip above the bar. Mouse buttons, wheel and motion then never reach binds. - Automatic demos (`src/host/autodemo.rs`, `src/demo/library.rs`; `cl_autodemo` default 1 (the user's choice: demos are small, about 0.3 MB per minute), `cl_autodemo_slots` default 10, 0 = unlimited; Options → Demos): `deliver_seq` passes every server message to `autodemo_message` after parsing it; a serverinfo (a NewMap event) finishes the level's demo and starts `<user dir>/autodemos/<UTC stamp>_<map>.dem`, so each level visit (including a death restart) is one file. ## FTE scripted particles
Port of vkQuake `r_part_fte.c` as a new crate `qpart`:
Status: phase 1 done (`crates/qpart`: `types`, `parse` (FTE cfg), `effectinfo`, `Registry` in `lib.rs`, `num` for C atof/strtoul). Files come through the `FileSource` trait (any `FnMut(&str) -> Option<Vec<u8>>`); console output is collected in `Registry::messages`, and sound names in `sounds_to_precache`. Type links (`assoc`, `cliptype`, `inwater`, `emit`) are `Option<TypeId>` indices. Tests cover synthetic configs and parse every `particles/*.cfg` / `effectinfo.txt` in the game data (20 files).
Phase 2 done: `system.rs` (`System`) holds the live state. Non-beam particles live per-type in contiguous `Vec<Particle>` (`TypeRt.vec`, oldest-to-newest for sequential update/compaction and reverse newest-to-oldest draw) with hoisted type parameters on the common linear-ramp loop, while `RenderType::Beam` particles, beam segments and clipped decals sit in index arenas so handles (`BeamSeg::p`) remain stable. `System::frame` swaps `run_list` with reusable `run_scratch` instead of cloning per frame. Particles grow lazily up to `r_part_maxparticles`; when a pool is full, 256 entries are marked dead per frame, as in C. Dead beam particles are only freed at the end of a frame (beams read them). Trailstates are a ring of 1024; owners hold a `TrailHandle` (index + serial), which replaces C's `trailstate_t **` key check. `run_effect` (RunParticleEffectState), `trail` (ParticleTrail), `run_classic_effect` (pe_<color> / PE_* fallbacks), `run_weather`. `frame` does setup (recycle, flurry, rain, reap + per-particle update), then type processing (`types_pass.rs`: decal ramps, the zero-lifetime drain, beam bookkeeping, `Sink` emission, and in-place `run_list` rebuild), then runs the deferred effect/trail/decal spawns and advances the clock. Renderables go to a `Sink` (`particles_rev` for non-beam batches, plus `particle`/`beam`/`decal`); dlights and sounds are queued in `System::dlights` / `sounds` for the client. World access is the `World` trait (trace_line, point_contents, entity_origin, decal_polys). The world supplies candidate surface polygons in Quake winding (edge cross product points into the surface). qpart does the 6-plane fragment clipping. Rain: `sky_tris_for_polygon` + `set_sky_tris(model, ..)`; `FrameInput::rain` lists the emitting entities. Single-threaded; one RNG for spawns, another for the update pass. FTE's 128-entry sin/cos table is kept as precomputed `PSIN`/`PCOS` LUTs (`util::psin/pcos`), because it shapes circle/spiral spawns without runtime trig calls. Deviations from vkQuake: beams of types with a lifetime are actually handed to the sink (vkQuake computes the midpoint but never draws them, unlike FTE). DP `type blood` still gets no cliptype (as in vkQuake), so it never splats unless a cliptype is set. `anorms` moved from qclient to qcore for sharing.
Phase 3 done (rendering + first client hooks):
- `qpart::geom`: `Registry::resolve_textures` is P_LoadTexture. It runs after each load: `textures/<name>` then `<name>`, as `.png`/`.tga`/`.jpg`/`.pcx`/`.lmp` (vkQuake's order; png via the `png` crate, jpg via `zune-jpeg`). Missing images fall back to builtin white/beam/ptri/ball/fuzzy/classic textures and reset the type's texcoords, as in C. `Geometry` is a `Sink` that ports R_Emit*Particle, R_DrawParticleBeam and R_AddClippedDecal into `Vertex`/`u32` index/`Batch` lists. `Sink::particles_rev` emits a type's contiguous particle slice in one loop with hoisted view vectors, texture/blend lookup, and a single batch merge/push at the end. Consecutive batches with the same texture/blend/lines merge. The host returns vertex, index and renderer-batch storage to `Fte` after rendering, including appended add-on geometry; `Geometry::reuse_buffers` clears and reuses it next frame. Raw batches retain their own storage and are stably sorted in place, avoiding the `ordered_batches` clone. No-view frames keep the cached storage; empty-effect frames hand it through for add-ons. `ordered_batches` sorts by the C draw passes: subtract/invmod first, then alpha, then additive. The fan-spark premultiply bug (colour ×255 twice) is not copied. Normal billboards can conservatively skip geometry behind the eye or beyond all four side frustum planes using an oversized scale bound. - Hooks: `r_particledesc` default "classic" loads no FTE configs, so classic effects stay unless an effect resolves. Server: builtins particleeffectnum #335, trailparticles #336, pointparticles #337, te_particlerain #409 / te_particlesnow #410, advertise FTE_SV_POINTPARTICLES, DP_SV_POINTPARTICLES, DP_TE_PARTICLERAIN/SNOW, FTE_PART_NAMESPACE_EFFECTINFO; messages svcdp_precache (54, 0x4000|idx), svcdp_trailparticles 60, pointparticles 61, pointparticles1 62, TEDP 55/56. Entity emit/trail effect fields need replacement deltas; skip at first.

Monster movement interpolation: classic updates and FTE replacement deltas set `LERP_RESETMOVE` when an entity first appears or returns after a snapshot gap. This resets renderer transform history to the received position, preventing a brief slide from zero or a stale position. Ordinary `U_STEP`/`EFLAGS_STEP` updates retain movement smoothing.

Debug overlays (2026-11-16): `scr_showspeed` (`src/host/speed.rs`, ironwail SCR_DrawSpeed) draws the 50 ms peak horizontal `cl.velocity` under the crosshair, `scr_showspeed_ofs` moves it down; hidden at intermission and `viewsize >= 130`. `r_showbboxes` (`src/bboxes.rs`, ironwail R_ShowBoundingBoxes) reads `Server::edict_boxes` (`crates/qserver/src/server/bboxes.rs`: box, model kind, health, nextthink, target(name), entity-field links, fat-PVS membership; single player only) and emits line geometry with `FteBlend::Overlay`, an alpha-blended LINE_LIST FTE pipeline (index 16) without depth test, shaded as blend mode 0 because mode 8 is the gun portal. The box under the crosshair is white; its links are arrows.

Alias animation reset and MD3 models:
- `ViewState::alias_frame` (`src/view.rs`) clears `LERP_RESETANIM` on first evaluation (snapping `prev = frame` cleanly rather than skipping lerp after reset) and clears `LERP_RESETANIM2` across the *next* frame transition (preventing `EF_MUZZLEFLASH` two-step viewmodel snapbacks from morphing).
- `qformats::md3` parses `"IDP3"` v15 `.md3` models and validates `.skin` manifests; `qrender` stores per-surface `AliasSurface` ranges (`first_index`, `num_indices`, per-surface skins/holey) and decodes packed 16-bit MD3 positions and spherical `(lat, lng)` normals in `alias.vert`/`velalias.vert` (flag `32`, velocity bit `65536`). `src/assets/md3.rs` resolves companion `<stem>.md3` replacements (via `Fs::open_companion`, gated by `r_enhancedmodels` archived default `1`, preserving `.mdl` entity flags) and `.skin` / prefix fallback textures (`progs/`, `textures/`, embedded shaders) with `_glow`/`_luma` fullbright layers and indexed `.lmp` colormap translation. 2021 re-release MD5 models (`qformats::md5`, port of vkQuake's Mod_LoadMD5MeshModel): when no `.md3` replaces a `.mdl`, `load_md5_replacement` loads `<stem>.md5mesh` (same `open_companion` priority rule) and optional `<stem>.md5anim`. Instead of vkQuake's GPU skinning pipelines, every anim frame is skinned on the CPU at load (absolute joint matrices × bias-weighted joint-local positions, smooth per-frame normals from the triangles) and stored as an `Md3` with one pose per frame, so entity frame N shows md5anim frame N through the normal MD3 path (lerp, lighting, colormap). Skins are `<dir><shader>_SS_FF` (skin, skin-group frame) as tga/lmp/pcx. Mesh joints the animation does not drive keep their bind pose relative to their parent; an animation parent differing from the mesh parent fails the load and the `.mdl` is used. `r_enhancedmodels` (Options → Graphics → Enhanced Models, applies on the next map load) gates both MD3 and MD5. `debris` (`take_over`) and `qrender` skip MDL ragdoll takeover for `Model::md3` entities.

Single-player death recovery (`host/death.rs`) opens a paused menu once per death.
`cl_deathaction` is archived: 0 Ask (default), 1 newest readable living-player
save by filesystem modification time (including named saves and autosaves),
2 Load browser, 3 restart with level-entry spawn parameters. Missing saves
fall back to Ask. Keys 1–3 select recovery; 4 disconnects to Main. Mouse,

### Time and virtual file system (`qcore::time`, `qcore::vfs`)
All engine code takes `Instant`/`SystemTime`/`UNIX_EPOCH` from `qcore::time`,
which re-exports `std::time` natively and `web_time` on wasm32 (where the std
clocks panic). All file I/O for game data and user files goes through
`qcore::vfs` (`read`, `write` (creates parents), `append`,
`exists`/`is_dir`/`is_file`, `create_dir_all`, `remove_file`, `rename`,
`read_dir` -> `DirEntry { path, is_dir, len }`, `modified`, `open_read` ->
`Box<dyn ReadSeek>` for PAK/PK3, plus `mount_file`/`take_dirty`). Natively it
is a thin `std::fs` wrapper (`take_dirty` is always empty). On wasm32 it is an
in-memory tree (`vfs/mem.rs`, unit-tested natively). The web front-end mounts
game data under `/quake` (`Fs::default_basedir()`), user files live in
`/quake-user/<game>` (`user_dir()`), and written or removed paths are reported
by `take_dirty` for persistence to IndexedDB. `qcore::fs::Fs` and every
user-dir writer (config/global cfg, saves, save thumbnails and autosave
rotation, screenshots, demos, bug reports, console history, mod stats, QW
downloads) use vfs; autosave staging still fsyncs natively. On wasm32, UDP
sockets (`UdpTransport::bind`, `QwClient::connect`) return `Unsupported`,
shell jobs/PTY are unavailable and the Quaddicted browser reports downloads
as unavailable, so nothing on the web path spawns threads, sleeps or blocks.
Left on `std::fs` because they never run on the web: librashader presets
(`src/host/shader.rs`), the Steam/home install search
(`qcore/src/fs/discovery.rs`), the Quaddicted installer, and tests.

### wgpu backend (web / `--features wgpu`)
qrender has two backends behind one `Renderer` API. build.rs sets cfg `qvk`
(Vulkan, ash + glslc SPIR-V) unless the target is wasm32 or the `wgpu`
feature (root: `cargo run --features wgpu`) is on; then `src/wgpu_backend/`
is compiled instead and no GLSL is built. Shared modules: types, projection,
convert, world (CPU BSP/PVS/light), portals, water, shared (ShaderParam,
GpuViewTiming). The Vulkan Renderer lives in `src/lib/vk.rs`, include!d at
the crate root.
The wgpu backend (wgpu 30, WGSL in `wgpu_backend/shaders/`) builds draw lists
on the CPU each frame: world surfaces from `World::portal_surfaces`
(frustum/backface culled, bucketed per animated texture) into one index
buffer; alias/MD3/ragdoll poses lerped and lit on the CPU; sprites, classic
and FTE particles as poly geometry; translucent draws sorted far to near.
Lightmaps are built on the CPU (port of lightmap.comp) into an RGBA8
2D-array atlas storing light/2, rebuilt per surface when a lightstyle value
changes or a dynamic light touches it. Bind groups: 0 frame (dynamic UBO,
lightmap, palette), 1 material (3 textures + sampler; cached per slot triple)
or sky (6 textures), 2 per-draw dynamic UBO (256-byte records). The scene
renders to an RGBA8 target at output size × render scale (`r_renderscale`,
0.25–2, linearly filtered when scaled). MSAA draws into a 4× colour/depth
target resolved into it at the end of the scene pass; WebGPU guarantees only
1× and 4× for these formats, so any `r_msaa` above 1 means 4× and
`max_msaa` reports 4 (the scene pipelines are rebuilt per sample count,
`pipes::ScenePipes`). SSAO (`wgpu_backend/ssao.rs`, `shaders/ao.wgsl`, a
port of ao.frag/aoapply.frag) splits the scene pass after the opaque world,
sky and opaque models (`ViewDraw::split`; liquids and the viewmodel come
after): AO is generated per view from scene depth into an Rg16Float target
at half (quality 0/1) or full (2) resolution, masked by scene alpha (the sky
writes 0) and fog, then multiplied into the scene colour with the
depth-aware blur before the translucent draws resume. With MSAA both passes
`textureLoad` sample 0 of the multisampled targets, so Vulkan's aosource
copy isn't needed. Motion blur (`wgpu_backend/motion.rs`,
`shaders/vel.wgsl`, port of velworld/velalias/vel.frag and post.frag's
`motion_blur`): entity transforms are kept by entity key from the last frame;
moving opaque brush and alias entities (not the viewmodel, ragdolls or
teleports over 256 units) get a velocity-pass draw whose `DrawU.prev` is last
frame's transform (alias vertices are CPU-posed in world space, so theirs is
`M_prev · M_cur⁻¹`). After the scene (whose depth is then stored) they are
drawn into an Rg16Float target at half (quality 0) or full resolution,
discarded where hidden by scene depth, and the post pass smears along the
strongest nearby motion; speed blur (`View::speed_blur`, bullet-time
`edge_blur`) is in the same post pass. Like Vulkan, the post pass samples
the scene nearest-filtered, so at very high frame rates the per-frame blur
can be sub-pixel. Pipelines that read the scene targets (SSAO, velocity) are
in `fx_pipes.rs`, rebuilt per MSAA sample count; command recording is in
`encode.rs`. Real-time dynamic lights (`wgpu_backend/shadows.rs`,
r_shadow_realtime_dlight) port the Vulkan ones with the shared
`crate::rtlight`: the light list is a uniform (frame group binding 7), the
maps a Depth16 2D array (binding 8) with a comparison sampler (binding 9);
`dyn_lights`/`light_visibility` in common.wgsl use
`textureSampleCompareLevel` (no derivatives in the light loop) and flip v
for wgpu's clip space. `AliasV` carries the CPU-posed world normal
(location 3); `DrawU.extra.w` marks fullbright models. Casters: world
surfaces from `world_cmds` on the light's surfaces, plus `Lists::casters`
(the first view's opaque brush and alias draws with bounding sphere and
entity key). The shadow passes bind `shadow_frame_group`, whose binding 8 is
a 1×1 placeholder, since WebGPU forbids sampling a texture in the pass that
renders it. The CPU lightmaps and `alias_light` leave dynamic lights out
while it is on. Shadow passes write no GPU timestamps.
`encode.rs`. Bloom (`wgpu_backend/bloom.rs`, `shaders/bloom.wgsl`, r_bloom): the
scene fragment shaders return a `Frag` (colour, glow) and have `*_glow` entry
points; `Pipes::set_scene` rebuilds the scene pipelines (`scene_pipes.rs`,
including the soft-particle ones) with a second Rgba8 target while bloom is
on, and the scene passes add the glow attachment (resolved like the colour
with MSAA). The chain mirrors Vulkan's but runs once for all split views per
level (one render pass per level, a viewport and `DrawU` per view, taps
clamped to the view's rectangle); `fs_post` reads level 0 at post binding 6
with a linear sampler (binding 7). Bloom passes write no GPU timestamps.
`encode.rs`. Enhanced water (`wgpu_backend/water.rs`, r_enhancedwater)
drives the shared `crate::water::WaterFx` like the Vulkan backend; its ripple
events go into one `WaterU` uniform buffer (frame group binding 4, with the
caustic texture and a repeat sampler at 5/6), `fs_water` ports
water_grad/lava_rings (swell, rings, lava heat; liquid kind in
`DrawU.params.w`) and `fs_world` the caustics from `WorldVertex::liquid`.
Splash droplets and spray puffs are drawn as blended quads with the particles.
Soft particles (`shaders/soft.wgsl`, `Pipe::SoftPoly`): FTE batches flagged
`soft` (and the water spray) go to `ViewDraw::soft` and are drawn in a final
scene pass with the depth attachment read-only and the same depth texture
bound at group 3, fading by fte.frag's rules (high quality takes the nearest
MSAA sample). Poly draws fog like fte.frag: alpha blends toward the fog
colour, additive/modulating ones toward black (`DrawU.params.y`). `Overlay`
debug lines (r_showbboxes) have their own pipeline without depth testing.
A post pass applies the
`r_waterwarp 1` underwater screen warp (vkQuake's `water_warp`),
polyblend/contrast/gamma at output size, then the 2D layer. The
`r_waterwarp 2` FOV pulse works (it is in the shared projection); FTE
`Overlay` blends like `Blend`. `new_web(canvas, palette)` presents to a
WebGPU canvas configured with `COPY_SRC`. Read-back (`wgpu_backend/capture.rs`):
`headless` copies every frame into a buffer mapped blocking; a presented
frame is copied only after `request_capture` and mapped asynchronously, so
`Renderer::take_capture` returns `Ok(None)` until the map completes (in the
browser only after control returns to the page). The host
(`Host::write_captures`) keeps the screenshot/thumbnail pending and retries
each frame; the Vulkan backend's `take_capture` is never pending.
See-through portals and teleporter windows are deliberately left out of this
backend: every portal view would rebuild the CPU draw lists again, which is
too slow in a browser (portals and teleporters still work, the surface is
just opaque). Slang presets are not supported either.
r_softemu/r_dither share their parameter logic with Vulkan
(`crate::softemu`): `FrameU.soft`/`softf` carry the screen and texture
dither, world dither level (coarse texel/lightmap snapping, banded 64-level
light) and alias mode (dither or affine `@interpolate(linear)` texture
coordinates), ported from world.frag/alias.frag, and softemu 2/3 force
nearest world filtering. The post pass palettizes through the 128³ lookup
table, which `wgpu_backend/post.rs` builds with a compute shader
(`shaders/lut.wgsl`, a port of `convert::palette_lut`, rebuilt when the
metric changes) into a storage buffer bound with the palette in the post
group (`Pipes::post_bgl`); the browser has no threads for the CPU version.
`fs_post` also ports post.frag's goggles (night vision, thermal colouring
and glow taps) and the r_colorblind daltonize filter; its parameters are in
the post `DrawU` (`post::post_draw`). In thermal mode the scene shaders
write grey heat levels (world, liquids, sky, alias models by
`RenderEntity::heat` in `DrawU.params.w`, sprites and classic particles by
`DrawU.ix.y`; FTE particles keep their colours, like fte.frag), and warm
bodies get a second draw (`Pipe::AliasXray`: additive, depth test Greater,
front faces culled since triangles wind the other way than in Vulkan)
before the viewmodel. GPU timings (`wgpu_backend/timing.rs`; QSP_GPUTIMES,
`prof_start`) use the `TIMESTAMP_QUERY` feature when the adapter has it:
every render pass writes a timestamp pair (WebGPU allows nothing finer), so
the stages are per pass kind (scene, ao-generate, ao-apply, translucent,
soft-particles, velocity, post+ui) for all split views together, and
`gpu_view_times` is empty. They resolve into a ring of three read-back
buffers mapped asynchronously and are summed a frame or more later.
Natively at most two frames are in flight (`FRAMES_IN_FLIGHT`, waited on
with `poll(Wait)` and reported as `fence_wait_ns`): headless has no
presentation to throttle it, and an unbounded queue made headless timedemo
fps measure submission rather than rendering and kept the timing buffers
from ever mapping. r_visibility (`debug_visibility::command`, shared with
Vulkan) hides and shows faces, textures and entities; `isolate` needs
see-through portals and answers that it is unavailable. Natively
`Renderer::new` (windowed) returns an error with `--features wgpu`; use
`-headless`.

### Platform, entry point and page
On wasm32 qplatform uses the browser backend (`crates/qplatform/src/web*`:
DOM events, pointer lock, Gamepad API polling, WebAudio ScriptProcessor,
`js Date` for `local_time`, `window.alert` for `error_box`); natively it uses
SDL3 (`src/sdl*`). `src/lib.rs` shares `open_game`/`open_sound`/
`apply_rumble` between native `run()` and `src/web.rs`, which exports
`vfs_mount`, `vfs_take_dirty`, `vfs_read` and `async start(args)`;
`start` builds the host on `<canvas id="quake">` and drives `Host::frame`
from requestAnimationFrame (`host_maxfps` skips animation frames).
`tools/webbuild/build.sh` builds the root library as a `cdylib`
(`cargo rustc --offline --release --lib --crate-type cdylib --target
wasm32-unknown-unknown`), runs `wasm-bindgen --target web` (CLI 0.2.130, must
match the crate) into `target/web/`, and copies `web/` (index.html, main.js)
next to it. Serve with `python3 -m http.server -d target/web`. The page asks
for the user's Quake folder or .pak files, caches them in IndexedDB (store
`game`), mounts them under `/quake` via `vfs_mount`, restores user files
(store `user`) under `/quake-user`, calls `start(args)` (`?args=` in the URL,
space separated) and saves `vfs_take_dirty()` paths back to IndexedDB every
2 s and when the page is hidden. Checked in headless Firefox (WebDriver BiDi,
WebGPU enabled): e1m1, the demo loop with the main menu, and a save persisted
to IndexedDB.

A page may offer the shareware episode: when it has a `#shareware` button with
a `data-url`, main.js shows it, downloads that file (with an optional
`#progress` bar), stores it as `/quake/id1/pak0.pak` unless a pak0 is already
stored, and launches. `web/index.html` has no such button. The project website
(separate repo `quake-source-port-website`, checked out in the gitignored
`website/`) uses it: its `scripts/build-play.sh` runs `tools/webbuild/build.sh`
and copies the bundle plus main.js next to its own `play/index.html`.
